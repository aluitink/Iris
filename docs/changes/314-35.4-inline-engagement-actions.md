# 35.4 — Inline engagement actions on timeline cards

**Phase 35 — Timeline actions & content completeness**

## What was built

New `EngagementBar` component rendered under each content card in the timeline (home feed, profile posts, object detail replies). Three actions:

- **Like** (heart icon): calls `IActivityPubClient.LikeAsync` / `UnlikeAsync`. Tracks the server-minted IRI (`DeliveryResult.MintedId`) for the undo. Optimistic count: +1 on success, -1 on undo.
- **Boost** (repost icon): calls `IActivityPubClient.AnnounceAsync` / `UnannounceAsync`. Same pattern as like.
- **Reply** (arrow icon): links to `/compose?replyTo={objectIri}` (existing compose reply flow from 34.13).

## Integration points

`ObjectView.razor` renders `<EngagementBar>` in three places:
1. **Create branch** — when the embedded object is a Note or Article (via `IsContentCreate`)
2. **Announce branch** — when the announced object has an IRI (via `AnnounceTargetIri`)
3. **IObject branch** — when the item is a bare Note or Article (via `BareObjectIri`)

Social activities (Follow, Like, etc.) do NOT get engagement bars.

## Key types

- `EngagementBar.razor` — stateful component; injects `IActorSessionAccessor`; tracks `_liked`, `_boosted`, `_likeCount`, `_boostCount`, `_likeIri`, `_announceIri`, `_busy`
- `ObjectView.razor.cs` — new computed properties: `IsContentCreate`, `AnnounceTargetIri`, `BareObjectIri`

## Design decisions

- **Stateful per-card, no server-side "has liked" check on load.** The engagement bar starts in the un-liked/un-boosted state. Checking whether the current user already liked/boosted an object would require an extra collection fetch per card (expensive for a timeline with many items). The user can see their own likes on their profile page. This is the same approach Mastodon uses for the web UI (optimistic, client-side state).
- **No `CancellationToken` on the async handlers.** Blazor `@onclick` handlers don't receive a cancellation token; the session client handles its own timeouts.
- **Count starts at 0.** The real like/boost counts are shown on the object detail page (34.28). The timeline card shows a local interaction counter, not the global count. This avoids N extra fetches per timeline load.
