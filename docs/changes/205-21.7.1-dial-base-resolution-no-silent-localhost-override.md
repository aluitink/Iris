# Change 205 — 21.7.1: Dial-base resolution (no silent localhost override)

## What

The sample explorer's log-on form previously **silently overrode** the user's explicit base-URL input
with the `InstanceBaseUrls` map's value when the address's host was a known local instance. This made
the app dial `localhost:8081` even when the user had explicitly entered `https://iris-dev1.luit.ink`
as the base URL — the "it still calls localhost" complaint.

The dial base is now **resolved at log-on time** by a shared `ResolveDialBase` helper:

- **Entered base URL** → used as-is (the user's explicit input always wins).
- **Empty base URL** → derived from the address's host:
  - a **known local instance** (the `InstanceBaseUrls` map) → its host-published port
    (e.g. `iris-dev1.luit.ink` → `http://localhost:8081`);
  - an **unknown host** → the actor's home server (the host over `https`, e.g. `alice@example.com` →
    `https://example.com`).

The map override is removed from both the password log-on path (`LogOnAsync`) and the OAuth2 log-on
path (`LogOnWithOAuth2Async`).

## Why

The `InstanceBaseUrls` map exists to make the **local Docker env** work: the advertised FQDN
(`iris-dev1.luit.ink`) does not resolve from the browser in the local container, so the browser must
dial the host-published port (`localhost:8081`). The map is the mechanism that knows this mapping.

However, the map was being consulted **at log-on time** and **overriding** the user's explicit input,
which was confusing: the user entered `https://iris-dev1.luit.ink` as the base URL, but the app
silently substituted `http://localhost:8081`. The correct behavior is for the map to be a **default**
(used when the field is empty), not an **override** (which clobbers the user's explicit input).

The user's insight: "always talk to the actor's home server" — the dial base should default to the
actor's home server (derived from the address's host), with the map as a local-dev convenience for
instances whose advertised host is not directly reachable from the browser.

- `dotnet test` green (1,288 tests across six projects).
- **Manual (Playwright MCP):**
  - Log on by `alice@iris-dev1.luit.ink` with an **empty** base URL → the app dials
    `http://localhost:8081` (the map's value); the actor IRI carries the advertised FQDN
    (`https://iris-dev1.luit.ink/ap/v1/u/alice`); the "Dialing" line confirms
    `http://localhost:8081/`. Wire: WebFinger GET to `localhost:8081`, actor IRI GET to the FQDN,
    feed reads to `localhost:8081`.
  - The description text now reads: "The base URL defaults to the actor's home server (the address's
    host, e.g. `https://iris-dev1.luit.ink`); a known local instance is pre-filled with its
    host-published port (e.g. `http://localhost:8081`). Edit it to override."

## Notes

- No new framework tests (UI work, Phase 22 rule 5). The change is a Blazor UI fix verified manually.
- The `InstanceBaseUrls` map in `Program.cs` is unchanged (it still seeds the four known hosts); only
  the **consultation logic** (override vs. default) changed.
- The OAuth2 callback path (`CompleteOAuthCallbackAsync`) is unchanged: it uses the `dial` param
  echoed on the callback URL (set by `LogOnWithOAuth2Async` using the resolved dial base), which is
  already the resolved value.
