# 254 — Shared-host-per-collection test fixture (test-suite speed)

> 2026-09-05 · Slice 29.3 · Phase 29

## What was built

A shared-host-per-xunit-collection fixture to cut redundant in-process host construction in the integration test suite. xunit builds a **fresh test-class instance per test method**, so a test that builds its in-process `TestServer` (the full ActivityPub pipeline — DI, endpoints, signature validation) in the constructor rebuilds that pipeline once per method. The fixture builds the host **once per collection** and shares it across the collection's methods.

Investigation first (measured, not assumed):

- **Per-host construction cost** (measured against the real `ActivityPubHostFactory.Create`): ~**89ms** for a single-instance host, ~**221ms** for a two-instance pair (construct + dispose).
- **Total construction budget across Iris.Server.Tests** (89 classes, ~368 methods): ~**38s** — only **~11%** of the ~337s fast-run wall-clock. The remaining ~300s is per-method **test-body** work (multi-hop signed deliveries, backoff waits, assertions) that host-reuse does **not** reduce.
- **Conclusion:** host-reuse is a real but **bounded** win (consistent with the 29.0 honest finding). A full 89-class migration is a large, high-risk change for ~11%, so 29.3 is scoped to a bounded, high-confidence deliverable: add the fixture + convert the **cleanest** classes, with a measured before/after.

**Delivered:** the `SharedHostFixture` (in `Iris.Testing`) + conversion of the two cleanest single-instance, **read-only** classes (9 methods each):

- `CollectionEndpointIntegrationTests` (paged local collections)
- `GlobalSearchIntegrationTests` (global search / directory)

**Measured payoff:** Iris.Server.Tests fast run **5m37s → ~5m16s** (~21s, ~6%) from converting just 2 classes. The converted classes' methods now run in 1–20ms each (no rebuild) instead of ~90ms (the first method, which builds the host, still pays ~120ms).

## Key types & files

- `tests/Iris.Testing/SharedHostFixture.cs` (new) — `SharedHostFixture : IDisposable`: builds a `TestServer` once from `ActivityPubHostOptions` (its `Persistence` is seeded before the host binds it) and exposes `Server` + `Persistence`. Non-sealed so a test class derives a named fixture (with its own seed) and registers it via `[CollectionFixture]`.
- `tests/Iris.Server.Tests/CollectionEndpointIntegrationTests.cs` — now `[Collection("CollectionEndpointIntegrationTests")]` + a `CollectionEndpointSharedHost : SharedHostFixture` (seeds once) + a `CollectionEndpointCollection : ICollectionFixture<...>` definition. Constructor takes the fixture; the per-method host build is gone. `Seed` exposed as `internal static SeedForFixture` for the fixture.
- `tests/Iris.Server.Tests/GlobalSearchIntegrationTests.cs` — same pattern (`GlobalSearchSharedHost` / `GlobalSearchCollection`). Keeps a `_server` field (the client round-trip test builds an `ActivityPubClient` over the shared host's handler).

## Tests

No new test methods (this is a harness change). The two converted classes' existing 18 methods all pass unchanged (`dotnet test --filter "Category!=Slow"` green — 899 Iris.Server.Tests, all suites). The conversion is verified by (a) the methods passing identically on the shared host and (b) the measured wall-clock drop.

## Decisions

- **Scope to the cleanest classes, not all 89.** Measurement showed host construction is only ~11% of the run, so a full migration is high-risk for a modest win. A bounded, high-confidence slice (the two read-only classes with no absolute-count assertions) delivers a verified win and a reusable fixture; the rest is a follow-up.
- **Only read-only / idempotent classes are safe to share.** A shared host shares its seeded persistence across methods. A class whose methods **write** to persistence and assert on **absolute counts** (`totalItems == 0/1/2`, `Assert.Single`/`Empty`) — or that self-poisons (e.g. OAuth reusing a fixed code constant, an object test that tombstones the seeded note) — would break on a shared host. Analysis of the 15 largest single-instance classes found **4 SAFE** (CollectionEndpoint, GlobalSearch, IrisSettingsExtension, BearerTokenAuth) and **11 RISKY**. 29.3 converted the two that already used the shared factory (CollectionEndpoint, GlobalSearch). The other two SAFE classes use inline `WebHostBuilder` and would also need a factory refactor; deferred.
- **The 11 RISKY single-instance classes + the two-instance federation classes are the follow-up.** Converting them requires a **per-method persistence reset** (an `IAsyncLifetime`/`IDisposable` that reseeds or clears the store between methods) — a larger, higher-risk change than the fixture itself. Tracked as the 29.3 follow-up (not a new phase). The federation classes additionally build two hosts with cross-wired delivery transports, so their shared-fixture shape is more involved.
- **The fixture is non-sealed and options-driven.** `SharedHostFixture` takes an `ActivityPubHostOptions` (the existing shared bootstrap) so the host is built by the one tested `ActivityPubHostFactory.Create` path; a test class derives it to supply its own seed without duplicating the host wiring.
