## Findings (prioritized)

### High (functional gaps)
1. **Profile + actor detail: bio/summary not displayed** — the actor document's `summary` field is fetched but never rendered. Both the profile page and actor detail header lack the bio.
2. **Profile: "Refresh" button visible in card area** — the `PagedCollection` Refresh button renders inside or overlapping the profile card, creating visual clutter.

### Medium (polish)
3. **Actor detail: no follower/following count badges** — tabs show "Followers" / "Following" without counts.
4. **Directory: no actor summaries** — directory items show handle + name only; a one-line summary would improve discoverability.
5. **Object detail: no content-type label** — Articles and Notes look identical; a subtle badge would distinguish them.

### Low (nice-to-have, deferred)
6. Notifications: no activity-type icons (likes vs follows vs replies look the same).
7. Compose: no nested reply thread context (replying to a reply doesn't show the parent's parent).

## Decisions

- **No new pages needed.** All routes in the nav are implemented; `/community` is a SampleBlazorClient feature, not an Iris.Web feature.
- **Home timeline correctly excludes own posts.** The followed feed (`/feed`) shows posts from followed actors; own posts appear on `/profile`. This is standard ActivityPub behavior (verified in 34.21).
- **Pre-35.1 posts lack timestamps.** Expected — no data migration. New posts show "just now" / relative time correctly.
