# 165 — Phase 19.8.4: community view doc fields + following/followers + follow/unfollow

## Summary

The `Community` page now renders the **community document** (name/icon/summary/url, via
`ObjectView`), the community's **following** and **followers** collections (paged with `next`-link
walking, each item a clickable link to the followed/follower's actor detail), and community
**follow/unfollow** (the signed pipeline, Decision 055 learned-id for the undo). This is a coherent
slice of 19.8.4 — the rendered group fields, the following/followers collections, and the community
follow/unfollow write.

## What changed (code)

- **`samples/SampleBlazorClient/Pages/Community.razor`**
  - **Community document card**: fetches the community (a `Group`, which is an `Actor`) via
    `IActivityPubClient.GetActorAsync(communityIri)` and renders it with the shared `<ObjectView>`
    (which renders actor name/icon/summary/url — the 19.8.3 work). The IRI is shown for reference.
  - **Following card**: paged read of `{community}/following` (`client.GetCollectionAsync(
    communityIri.FollowingOf())`), each item a clickable link to `/actor?iri=...` (handles both the
    `ILink { Href }` and `IObject { Id }` shapes the server may serve). A "Load more" button walks the
    `next`-links (20.3 paged idiom, one page per click).
  - **Followers card**: same paged idiom against `{community}/followers`.
  - **Follow / unfollow card**: two buttons driving the signed pipeline — `FollowAsync(actor,
    communityIri)` (the page learns the minted id, Decision 055) and `UndoFollowAsync(actor,
    learnedId)` (the undo references the learned id). The page's `WriteBusy`/`WriteResult`/`WriteError`
    machinery mirrors the actor detail write card.
  - New `@code` state: `CommunityDoc`, `FollowersItems`/`FollowingItems` (paged, `List<T>?`),
    `FollowersHasMore`/`FollowingHasMore`, `FollowersLoadingMore`/`FollowingLoadingMore`,
    `_followersResumeFrom`/`_followingResumeFrom` (resume IRIs), `FollowersError`/`FollowingError`,
    `WriteBusy`/`WriteResult`/`WriteError`, `FollowLearnedId`.
  - New methods: `LoadInitialFollowersAsync`/`LoadMoreFollowersAsync`/`EnumerateOneFollowersPageAsync`
    + Following equivalents (mirror the actor detail paged idiom); `FollowAsync`/`UnfollowAsync`
    (signed pipeline, learned-id capture); `HandleOf(string)`/`RelayIriOf` display helpers.

## Key types / API

- `IActivityPubClient.GetActorAsync(Iri, CancellationToken)` — the community document read (a `Group`,
  which is an `Actor`, so `ObjectView`'s actor branch renders it).
- `IActivityPubClient.GetCollectionAsync(Iri, CollectionQuery?, CancellationToken)` — the paged
  following/followers reads (`{community}/following`, `{community}/followers`), 20.3 paged idiom.
- `IActivityPubClient.FollowAsync(Iri actorId, Iri targetId, CancellationToken)` /
  `IActivityPubClient.UndoFollowAsync(Iri actorId, Iri originalFollowId, CancellationToken)` — the
  community follow/unfollow (a community is followed the same way a person is; the server records the
  community's follows + followers sets, F-24).
- `Iri.FollowersOf()` / `Iri.FollowingOf()` — the collection IRI derivations.

## New tests (4, all passing)

- **`tests/SampleBlazorClient.Tests/S19CommunityViewCompletenessTests.cs`** (new):
  - `CommunityView_CommunityDoc_RendersName` — `GetActorAsync(communityIri)` returns the community
    (a `Group`) carrying its `Name`.
  - `CommunityView_FollowingCollection_ContainsFollowed` — `{community}/following` contains the actor
    the community follows (bob, seeded).
  - `CommunityView_FollowersCollection_ContainsFollowers_AfterFollow` — after `FollowAsync(alice,
    community)`, `{community}/followers` contains alice (the follower → community edge, F-24).
  - `CommunityView_FollowThenUnfollow_RoundTrips` — `FollowAsync` succeeds and mints an id;
    `UndoFollowAsync(alice, mintedId)` succeeds and clears the follower edge (followers empty again).

The harness mirrors `S19ActorDetailCompletenessTests.StartHost` (the S3-style in-memory ActivityPub
pipeline, `BaseUri = http://localhost`, so writes dial the dial base directly — not through the home
proxy — and the in-process `TestServer` handler intercepts them). A community (a `Group`) is seeded
with a name, two members, and a follow of a member (so its following collection is non-empty).

**Test detail:** the followers reads poll with `?refresh=true` (bypassing the local collection-page
response cache) so a freshly-recorded follow edge is visible — a cached empty read from before the
follow would otherwise be served (the page does a fresh page-load after a follow, so it re-reads).

## What is deliberately NOT in this slice

  is a small follow-up).
- **The 19.5 management surfaces** — community creation, membership management (add/remove member),
  and peer/follow management (the community follows/unfollows a specific actor) as dedicated UI. These
  are separate coherent slices.
