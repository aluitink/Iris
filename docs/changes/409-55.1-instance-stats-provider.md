# 55.1 — `IInstanceStatsProvider`: Real NodeInfo User Count

## Summary

54.33 found `usage.users.total` was hardcoded to 0 in the NodeInfo 2.0 response because
`NodeInfoHandler` (in `Iris.Server`) can't access `IUserAccountStore` (in `Iris.Server.Data`)
without a dependency-direction violation. This slice introduces an `IInstanceStatsProvider`
abstraction in `Iris.Server` that the persistence layer implements, so the NodeInfo metadata
reports the real account count.

## Changes

### New: `IInstanceStatsProvider` interface (`src/Iris.Server/IInstanceStatsProvider.cs`)

A single-method interface in `Iris.Server` (the server core, not the persistence layer):

```csharp
public interface IInstanceStatsProvider
{
    Task<int> GetLocalUserCountAsync(CancellationToken ct = default);
}
```

This avoids the dependency violation: `Iris.Server` defines the contract, `Iris.Server.Data`
implements it.

### New: `InMemoryInstanceStatsProvider` (`src/Iris.Server/InMemoryInstanceStatsProvider.cs`)

Default implementation returning 0. Registered via `TryAddSingleton` in `AddActivityPubServer`
so hosts without a real persistence backend (in-memory tests, minimal hosts) get a safe default.

### New: `EfInstanceStatsProvider` (`src/Iris.Server.Data/EfInstanceStatsProvider.cs`)

EF Core implementation that queries `IUserAccountStore.GetAllAsync()` and returns the count.
Registered via hard `AddSingleton` in `AddEntityFrameworkPersistence` (overrides the in-memory
default since it's called after `AddActivityPubServer`).

### Modified: `NodeInfoHandler` (`src/Iris.Server/ActivityPubServerExtensions.cs`)

Changed from a synchronous static method to an async one that accepts `IInstanceStatsProvider`
and `CancellationToken`. The `usage.users.total` field now uses `stats.GetLocalUserCountAsync(ct)`
instead of the hardcoded `0`.

### Modified: DI registration (`src/Iris.Server/ActivityPubServerExtensions.cs`)

Added `services.TryAddSingleton<IInstanceStatsProvider, InMemoryInstanceStatsProvider>()` in
`AddActivityPubServer`.

### Modified: EF Core DI registration (`src/Iris.Server.Data/EntityFrameworkPersistenceExtensions.cs`)

Added `services.AddSingleton<IInstanceStatsProvider>(sp => new EfInstanceStatsProvider(...))` in
`AddEntityFrameworkPersistence`.
