# 273 — 30.1: Configuration Surface

**Phase:** 30 (server production-readiness & hardening)
**Slice:** 30.1
**Status:** Complete

## Summary

Added an `AddActivityPubServer(IServiceCollection, IConfiguration)` overload that binds
`ActivityPubServerOptions` and all delivery/observability options from conventional
configuration sections, enabling a production host to be configured entirely from
`appsettings.json`, environment variables, or any other `IConfiguration` source without
code.

## Configuration Sections

| Section | Options Class |
|---|---|
| `Iris` | `ActivityPubServerOptions` (BaseUri, InstanceName, InstanceActorId, SharedInboxIri, NamespaceIri, ProxySettings, Media) |
| `Iris:Delivery:Retry` | `DeliveryRetryOptions` |
| `Iris:Delivery:Worker` | `DeliveryWorkerOptions` |
| `Iris:Delivery:RateLimit` | `DeliveryRateLimitOptions` |
| `Iris:Delivery:CircuitBreaker` | `DeliveryCircuitBreakerOptions` |
| `Iris:Inbound:RateLimit` | `InboundRateLimitOptions` |
| `Iris:Feed` | `FeedOptions` |
| `Iris:Health:DeliveryQueue` | `DeliveryQueueHealthOptions` |

## Design Notes

- The `Iri` struct (a `readonly record struct`) cannot be deserialized by
  `IConfiguration.Get<T>()`, so the `Iris` section's IRI-valued properties
  (BaseUri, InstanceActorId, SharedInboxIri, NamespaceIri) are bound manually from
  string config values.
- Nested option objects (ProxySettings, MediaOptions) are bound via
  `IConfigurationSection.Get<T>()` since they are plain classes with settable properties.
- The overload delegates to the existing `AddActivityPubServer(Action<ActivityPubServerOptions>)`
  for the core options, and uses `services.Configure<T>(section)` for the delivery/observability
  options, which composes correctly with the `TryAddSingleton` defaults already registered.
- No new NuGet packages were added; `IConfiguration` is available via the existing
  ASP.NET Core framework reference.
