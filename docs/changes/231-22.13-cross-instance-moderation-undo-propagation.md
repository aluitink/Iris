# 22.13 — Cross-instance moderation undo propagation (Block / Flag)

Phase 23, slice 3. **Type:** test-only (invariant lock — no production code change; the remote-side
undo handling already works).

## Problem (and why it is a test, not a fix)

The "moderation propagation" theme of Phase 23 has two halves: the outbound half (a `Block`/`Flag`
federates from A to B and B records the edge) is already pinned by
`OutboxPublishServerDeliversIntegrationTests`. This slice locks the **inverse** half end-to-end: when the
actor on A **reverses** a moderation action by publishing an `Undo(Block)` / `Undo(Flag)`, does B's
instance receive the `Undo` and **remove** the edge it had recorded?

The answer, traced through the code, is **yes — it already worked before this change**:

- A's outbox-publish handler (`OutboxPublishHandler`) records/removes A's *local* edge and **delivers**
  the `Undo` to the affected actor's inbox on B (the affected actor is a delivery target of the
  moderation activity).
- B's `UndoActivityHandler` (src/Iris.Server/Inbox/UndoActivityHandler.cs, F-07) handles the inbound
  `Undo`: when its object is a `Block` it calls `ResolveBlockEdgeAsync` to read the parties from the
  **locally-stored original** `Block` and then `IModerationStore.RemoveBlockAsync`; when its object is a
  `Flag` it does the same via `ResolveFlagEdgeAsync` + `RemoveFlagAsync`.

The subtle dependency this test locks: **B can only remove the edge if it first received and stored the
original moderation activity** (the `Undo` references the original by its server-minted IRI, and B's
handler resolves the parties from its own activity store — it does not re-fetch the original from A). So
the test exercises the real cross-instance flow: original federates A → B (B records + stores), then the
`Undo` federates A → B (B resolves the stored original and removes).

This is the same class of invariant-lock as 22.12: the behavior was already correct; the test exists to
fail loudly if a future change regresses the remote-side removal (e.g. a `Undo` handler refactor that
drops the Block/Flag branches, or a delivery-target change that stops delivering the `Undo` to the
affected actor's inbox).

## Where (tests only)

- `tests/Iris.Server.Tests/ModerationUndoPropagationIntegrationTests.cs` (2 new integration tests), a
  2-instance `TestServer` topology (A = `undo-mod-a.domain.local`/`alice`, B = `undo-mod-b.domain.local`/
  `bob`), wired per the established `OutboxPublishServerDeliversIntegrationTests` pattern (two
  `ActivityPubHostFactory.Create` instances; A's `DeliveryTransport` routes to B; A's `RoutingFetcher`
  routes by actor-IRI host; B's fetcher routes to A to fetch alice's document for signature validation):
  1. `UndoBlock_ServerDeliversToRemote_RemovesRecordedEdge` — A publishes a `Block` of bob (202; A records
     its local edge; learns the minted id from the 2xx body per decision 055); waits for B to record the
     edge (proving the Block federated **and** was stored in B's activity store); A publishes an
     `Undo(Block)` (202); waits for A to remove its local edge; waits for **B to remove its edge**;
     asserts B's inverse index (`GetBlockersAsync(bob)`) no longer lists alice.
  2. `UndoFlag_ServerDeliversToRemote_RemovesRecordedEdge` — the flag variant: A publishes a `Flag` of
     bob; B records + stores; A publishes `Undo(Flag)`; B removes; asserts B's forward flag collection
     (`GetFlagsAsync(alice)`) no longer lists bob.

  Each test asserts the edge is gone on **both** A and B, and the relevant index/collection agrees —
  pinning both the local and the cross-instance half.

## Non-vacuity (proven)

Per the loop's "prove it fails" discipline, the remote removal was temporarily disabled (the two
`RemoveBlockAsync` / `RemoveFlagAsync` calls in `UndoActivityHandler` commented out, then restored):

- With the removal disabled, **both tests fail** (they time out at 30s waiting for B's edge to clear —
  B recorded the edge in step 1 but never removes it).
- Restoring the handler turns them green.

This confirms the tests genuinely exercise the cross-instance removal (not passing vacuously because B
never recorded the edge — step 1b asserts B *did* record it).
