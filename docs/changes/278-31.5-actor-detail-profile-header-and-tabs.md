# 278 — 31.5: actor detail — profile-style header + tabs

> 2026-09-05 · Slice 31.5 · Phase 31 (explorer UI & server namespace polish)

## What was built

The `/actor` page was **one long page**: outbox, liked, followers, following,
the moderation counts/collections, follow/unfollow, inbound follows, the
moderation writes (mute/block/flag), relays, and a raw inspector — all stacked
top to bottom. Scrolling to any section was the only way to reach it. The 31.5
report asked to **organize it into tabs** and to make the **top look like an
actor profile** (show the actor's icon/picture from the document, not just the
raw object view).

Two changes:

1. **A profile-style header.** A new `ActorProfile` component renders the actor's
   icon (an avatar `<img>`, or a name-initial fallback when there is no icon),
   handle (`preferredUsername`), name, summary, and IRI in a profile card at the
   top of the page. It is a distinct presentation layer above the raw
   `<ObjectView>` (which still appears, unchanged, in the "Raw" tab). The header
   generalizes beyond `Person` — a `Group` (community) is an `Actor`, so the same
   component is reused verbatim by 31.6 (`/community`).

2. **Tabbed sections.** The page's sections are organized into tabs: **Outbox**,
   **Liked**, **Followers**, **Following**, **Raw**, and — once the target actor's
   moderation counts have loaded — **Moderation** (carrying a `mutes+blocks+flags`
   count badge on the button). The profile header and the tab bar are always
   visible; only the active tab's section renders. All state (paged lists,
   moderation counts, relays, pending follows) is loaded up front, so switching
   tabs is instant and does not lose state. `ActiveTab` resets to **Outbox** on a
   new actor load.

## Key types & files

- `samples/SampleBlazorClient/Components/ActorProfile.razor` (new) — the
  profile-style header component. Parameters: `IObject? Actor` (the actor
  document, pattern-matched per the 3rd-Party ActivityStreams rules — never a
  concrete type) and `string? ActorId` (the IRI line; defaults to the document's
  own id). Resolves the icon IRI (an `IObject` icon by `id`, an `ILink` icon by
  `href`), the handle/name/summary, and a name-initial avatar fallback. A
  non-actor document or null renders a muted placeholder (not a header).
- `samples/SampleBlazorClient/Pages/ActorDetail.razor`
  - `<PageTitle>`/`<h2>` → "Actor" (the page shows one actor).
  - The old single "Actor" card (`<ObjectView>` + IRI) is replaced by
    `<ActorProfile Actor="ActorDoc" ActorId="actorIri.Value" />` + a `<nav class="tabs">`.
  - Each section is wrapped in `@if (ActiveTab is "<key>")`: outbox/liked
    (`<PagedCollection>`), followers, following, raw (`<RawInspector>`), and
    moderation (the moderation counts/collections + follow/unfollow + inbound
    follows + moderation writes + relays cards, all inside the moderation tab).
  - New state: `string ActiveTab = "outbox"`, a `record Tab(Key, Title, Badge)`,
    a computed `Tabs` list (Moderation added only once `Moderation` is non-null,
    with the count badge), and `SetActiveTab`. `LoadByIriAsync` resets
    `ActiveTab = "outbox"` on a new actor.
- `samples/SampleBlazorClient/wwwroot/css/app.css` — `.actor-profile*` (the
  header card, the 4rem avatar frame, the initial fallback, the handle/name/
  summary/IRI) and `.tabs`/`.tab`/`.tab.active`/`.tab-badge` (the tab bar).
- `tests/SampleBlazorClient.Tests/ActorProfileTests.cs` (new) — 6 bUnit tests for
  the header contract.

## Tests

Full fast suite green (1439/1439; 1433 prior + 6 new):

- `ActorWithIcon_RendersAvatarImage` — the icon renders as an `<img>` avatar (its
  IRI as `src`, wrapped in a link out to the icon).
- `ActorWithoutIcon_RendersInitialFallback` — no icon → a name-initial fallback
  glyph (no `<img>`).
- `Actor_RendersHandleAndNameAndSummaryAndIri` — handle, name, summary, and IRI
  all render in their slots.
- `Actor_RedundantName_Omitted` — a name identical to the handle (the seeded
  actors) is omitted (29.2 visual-review convention).
- `NonActor_RendersMutedPlaceholder` — a `Note` is not a profile: a muted
  placeholder, no handle.
- `Group_RendersAsActorProfile` — a `Group` (community) is an `Actor`: the header
  presents it the same way (handle + name + icon), confirming the treatment
  generalizes (31.6 reuses this).

## Design notes

- **Header is a presentation layer, not a replacement of the raw view.** The
  `<ObjectView>` (raw document) is retained in the "Raw" tab; `ActorProfile`
  adds a human-facing profile card on top. This is the "make the top look like a
  profile, not just the raw object view" the report asked for.
- **Tabs are a pure client-side reorganization.** No data flow, wire, or server
  behavior changed — the same collections are fetched the same way; only which
  section is visible is now driven by `ActiveTab`. This keeps the change
  low-risk and fully covered by the existing integration suite (which is
  unchanged and still green) plus the new header component tests.
- **The moderation tab is conditional.** Its cards are only meaningful once the
  target actor's moderation counts are loaded; the tab (and its count badge)
  appears only then. A remote actor whose counts can't be read simply has no
  moderation tab.
- **`Icon`/`Summary` live on `IObject`, not `Actor`.** (Confirmed by reflection
  on the v0.2.4 `KristofferStrube.ActivityStreams` assembly: `IObject`/`Object`
  declare both; `Actor` inherits them; `Icon` is `IEnumerable<IImageOrLink>`.)
  Hence `ActorProfile` reads them off the cast `Actor` (an `IObject`) — and the
  non-actor guard (the whole header renders only for an `Actor`) is what keeps a
  `Note` from being rendered as a profile, since a `Note` also carries
  `Icon`/`Summary`.
- **`ActorProfile` is 31.6-ready.** It takes an arbitrary `IObject` and presents
  any `Actor` (person/community/application); `/community` can drop it in
  unchanged.
- No new NuGet packages; no server or client-library changes.
