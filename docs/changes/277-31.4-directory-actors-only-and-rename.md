# 277 — 31.4: directory search returns only actors; page renamed "Directory"

> 2026-09-05 · Slice 31.4 · Phase 31 (explorer UI & server namespace polish)

## What was built

The `/actors` page (the explorer's directory) searched the instance-wide
`GET /ap/v1/search` endpoint, which returns **both** local actors (the directory)
**and** stored content objects (notes). So a whole-directory search — or even a
search for a common substring — mixed actor cards in with note cards, and the
page was labeled "Actors" while actually returning content. The 31.4 report
asked that the page **search the actor directory only** (actors/communities) and
be **renamed "Directory"** (nav + title) to match its purpose.

The fix adds an **optional `?type` filter** to the search surface and uses it on
the directory page. The server's search service now accepts a `type` argument:
`"Actor"` runs only the actor pass (skipping content entirely), a non-actor type
(e.g. `"Note"`) runs only the content pass and filters each item by its
ActivityStreams `@type`, and a null/whitespace type is the existing full
actor + content search (backward compatible). The client's `SearchAsync` gains
`SearchOptions.Type`, appended to the request IRI as `?type=…` when set. The
`/actors` page passes `Type = "Actor"` and is renamed "Directory" in the nav and
`<PageTitle>` (the `/actors` route is unchanged, so no links break).

- `src/Iris.Client/SearchOptions.cs` — `SearchOptions` gains `string? Type = null`
  (the `?type` query parameter).
- `src/Iris.Client/ActivityPubClient.cs` — `SearchAsync` appends
  `&type={escaped}` to the search IRI when `options.Type` is set (the IRI shape is
  otherwise unchanged: `?q=…&limit=…&offset=…`).
- `src/Iris.Client/IActivityPubClient.cs` — `SearchAsync` docs note the new
  `SearchOptions.Type` option.
- `src/Iris.Server/Services/IGlobalSearchService.cs` — `SearchAsync` gains
  `string? type = null` (backward compatible; existing callers unchanged).
- `src/Iris.Server/Services/GlobalSearchService.cs` — `SearchAsync` computes
  `actorPass`/`contentPass` from the type filter: `"Actor"` → actor pass only; a
  non-actor type → content pass only (each item checked by
  `ItemMatchesType` against its `@type`, falling back to the CLR type name); no
  type → both passes (the prior behavior). A new private `ItemMatchesType`
  helper does the per-item type check.
- `src/Iris.Server/ActivityPubServerExtensions.cs` — `GlobalSearchHandler` reads
  `?type` from the request and passes it to `searchService.SearchAsync`.
- `samples/SampleBlazorClient/Pages/Actors.razor` — `<PageTitle>`/`<h2>` renamed
  "Directory"; the search box copy now says "Search the directory (empty = all
  actors)"; the results heading/count read "actors"; and `SearchAsync` now calls
  the client with `new SearchOptions { Type = "Actor" }` so the server restricts
  the result to actors.
- `samples/SampleBlazorClient/Layouts/MainLayout.razor` — nav link text
  "Actors" → "Directory" (still `href="/actors"`).

  `type: "Actor"` returns only the matching actor (the content note is excluded),

  a real client with `SearchOptions.Type = "Actor"` round-trips `?type=Actor` and
  yields only the actor.

## Design notes

- **Backward compatible.** `IGlobalSearchService.SearchAsync` and
  `SearchOptions` only gained optional members; every existing caller and the
  unfiltered endpoint behavior (actors + content) is unchanged, so the 13
  pre-existing global-search tests pass as-is.
- **`"Actor"` is a pass toggle, not a per-item check.** Every item in the actor
  pass is an `Actor`, so `type=Actor` simply runs the actor pass and skips the
  content pass (no per-item matching needed). A non-actor type instead runs the
  content pass and filters each item by its `@type` — so `?type` is a general
  single-type filter, not directory-specific.
- **The page, not the endpoint, is directory-only.** The endpoint keeps its full
  actor + content search (the F-13 general search); only the `/actors` page opts
  into `Type = "Actor"`. A future "search all" surface can call the same
  endpoint without a type filter.
- No new NuGet packages; the `/actors` route and `SearchOf` IRI derivation are
  unchanged.
