## Summary

This partial converts the three unfollow-propagation two-instance federation classes to
`SharedTwoHostFixture`:

- `PersonFollowsPersonUnfollowPropagationIntegrationTests` (2 methods) — single identity on A (alice),
  bob on B.
- `CommunityFollowsPersonUnfollowPropagationIntegrationTests` (2 methods) — multi-identity on A
  (alice + iris community), bob on B.
- `CommunityFollowsCommunityUnfollowPropagationIntegrationTests` (2 methods) — multi-identity on A
  (alice + iris community), bob + nebula community on B (4 identities total).

Combined with partials 5–6, **all 13 single-instance RISKY classes + 10 two-instance federation
classes** are now converted. Remaining: ~12 two-instance federation classes.

## What changed

### Per-class details

- **PersonFollowsPersonUnfollowPropagation** (2): A (alice) + B (bob), `BuildIdentity` on A,
  `RoutingFetcher` on A, `BuildFetcherFor` on B. `SignedRequest` takes `(Iri, KeyPair, Activity, string
  path)` (always posts to AHost). Seed: alice + bob.
- **CommunityFollowsPersonUnfollowPropagation** (2): A (alice + iris community) + B (bob),
  `BuildIdentityForA` (multi-identity), `RoutingFetcher` on A, `BuildFetcherFor` on B. Seed: alice +
  iris + bob. The `_bobKey` field is non-readonly (assigned in `InitializeAsync`) though it's not used
  by the test body (B's fetcher uses alice's key).
- **CommunityFollowsCommunityUnfollowPropagation** (2): A (alice + iris community) + B (bob + nebula
  community), `BuildIdentityForA` (multi-identity), `RoutingFetcher` on A, `BuildFetcherFor` on B. Seed:
  alice + iris + bob + nebula. The `_bobKey`/`_targetCommunityKey` fields were removed (not used by the
  test body; B's fetcher uses alice's key to validate the community C's signature).

### Notes

- All three classes use the same `SignedRequest(Iri, KeyPair, Activity, string path)` signature (no
  server param — always posts to AHost, since the authoring actor is always on A).
- The `SignedRequest` in the CrossInstance Accept/Reject classes takes a `TestServer` param (because the
  author can be on either A or B); the unfollow classes don't need that (the author is always the
  community/person on A).
