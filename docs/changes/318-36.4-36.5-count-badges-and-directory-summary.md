# 36.4 + 36.5 — Follower count badges + directory actor summary

**Phase 36 — Profile completeness & visual polish**

## What was built

### 36.4 — Follower/following count badges on actor detail tabs

`ActorDetail.razor` now fetches the first page of the actor's followers and following collections (via `GetCollectionAsync`) and displays the `totalItems` count in the tab labels:

- Before: `Posts | Followers | Following`
- After: `Posts | Followers (2) | Following (1)`

The counts are loaded fire-and-forget after the actor document loads (`LoadCountsAsync`), so they appear a moment after the initial render. A failure to fetch counts is silently ignored (best-effort — the page works without them).

**Key code:**
- `FollowerCount` / `FollowingCount` properties (`int?`)
- `LoadCountsAsync(Iri)` — fetches both collections in sequence
- `GetFirstPageTotalAsync(IActivityPubClient, Iri?)` — static helper that reads `TotalItems` from the first page

### 36.5 — Directory actor summary

`ObjectView.razor` Actor branch now renders `actor.Summary` (first entry) when present, in a muted `.object-summary` span. Seeded actors currently have no summary set (the `ActorProvisioner` only sets `Id`, `PreferredUsername`, `Name`), so the summary is invisible until profile editing lands. The code is ready for when users can set summaries.

**Key code:**
- `ObjectView.razor` line 112: `@if (actor.Summary?.FirstOrDefault() is { Length: > 0 } summary)` → `<span class="object-summary">`
- `app.css`: `.object-summary` — muted color, 0.85rem, block, margin-top 0.15rem
