# 40.3 — Community feed shows only member posts

## Summary

The community feed (`GET /ap/v1/c/{name}/feed`) now shows only community-tagged posts — posts whose `attributedTo` carries the community IRI. Personal posts (no community in `attributedTo`) are excluded from the feed. This makes the community feed a true "community channel" rather than a mirror of every member's outbox.

## Changes

### `src/Iris.Server/Services/CommunityFeedService.cs`

- Added `IsCommunityTagged(IObjectOrLink item, string communityIriValue)` and `HasCommunityInAttributedTo(IObject obj, string communityIriValue)` helper methods.
- The merge loop in `GetFeedAsync` now filters: `if (!IsCommunityTagged(item, communityIriValue)) continue;`.
- An item is "community-tagged" when its embedded object (or the object itself, for a direct object in the outbox) has the community IRI in its `AttributedTo` collection.

### `src/Iris.Server/Inbox/CommunityContentRecorder.cs`

- Added `TagActivityForCommunity(Activity activity, Iri communityIri)`: creates a new `Create` activity with a tagged copy of the embedded `Note` (community IRI in `AttributedTo`) if not already tagged.
- Added `TagNote(Note note, Iri communityIri)` and `HasCommunityInAttributedTo(ActivityObject obj, Iri communityIri)` helpers.
- `RecordToMembersAsync` now calls `TagActivityForCommunity` and records the tagged copy in members' outboxes. This ensures that when a community member posts to the community (via the community inbox), the note recorded in other members' outboxes carries the community tag — so the feed filter includes it.

### `tests/Iris.Testing/TestSeeder.cs`

- `AddCreateActivity` now accepts an optional `IEnumerable<Iri>? attributedTo` parameter (5th arg). When provided, sets `Note.AttributedTo` with the given IRIs as `Link` objects.

### `samples/SampleServer/Program.cs`

- Seeded notes (alice, bob, carla) now include the community IRI in `AttributedTo`, so the sample server's community feed returns them.

### `tests/Iris.Server.Tests/CommunityFeedFilteringIntegrationTests.cs` (new)

- 2 integration tests:
  - `CommunityFeed_ShowsOnlyCommunityTaggedPosts` — seeds a community with 2 members, each with 1 community-tagged post + 1 personal post. Asserts the feed contains only the 2 community-tagged posts.
  - `CommunityFeed_EmptyWhenNoCommunityTaggedPosts` — a new community with a member who only has personal posts. Asserts the feed is empty.

### Test updates (existing)

- `CommunityFeedCorrectnessIntegrationTests.cs`, `CommunityFeedIntegrationTests.cs`, `CommunityFeedRemoteMemberIntegrationTests.cs`, `CommunityFeedServiceModerationTests.cs`, `CommunityModerationIntegrationTests.cs`, `CommunitySearchIntegrationTests.cs`, `CommunityMembershipManagementIntegrationTests.cs`: all `AddCreateActivity` calls now pass the community IRI in `attributedTo` so the feed filter includes them.
- `CommunityFeedRemoteMemberIntegrationTests.cs`: `Feed_OnlyLocalMember_RemoteNotMember` and `Feed_RemoteMemberOutboxUnavailable_ContributesNothing` now seed posts tagged to the specific community under test (not the original community).

## Decisions

- **Tag-at-record-time, not tag-at-read-time**: The community IRI is added to `Note.AttributedTo` when the activity is recorded in members' outboxes (via `CommunityContentRecorder.TagActivityForCommunity`), not when the feed is read. This keeps the feed filter a simple membership check and avoids mutating objects in the store.
- **Feed filter checks the object's `AttributedTo`, not the activity's**: An outbox item is typically a `Create` activity wrapping a `Note`. The community tag lives on the `Note` (the object), not the `Create` (the activity). The filter unwraps the activity to its embedded object and checks the object's `AttributedTo`.
- **Personal posts remain in the member's outbox**: The filter only affects the community feed endpoint. A member's personal posts are still in their outbox and appear in their own profile/timeline — only the community feed excludes them.
