# Change 220: Advertise account settings/control as JSON-LD extensions (22.6.1)

## Summary

Settings/control surfaces are now discoverable as typed `iris:` JSON-LD extension properties on the
public actor/community document. A remote client can read the `iris:settings` IRI from the document
alone (no hardcoded endpoint paths) to discover where to publish AP-native settings change activities.

## Problem (22.6.1 review item)

The inventory of settings/control endpoints revealed:

- `manuallyApprovesFollowers` (person): echoed on the public actor doc when `true`, but NOT in
  `iris:capabilities` and no `iris:settings` extension IRI was advertised.
- `manuallyApprovesMembers` (community): stored in ExtensionData, settable via AP-native
  Add/Remove, but NOT explicitly advertised as a typed extension on the public community document.
- No `iris:settings` extension property existed; no `SettingsOf()` IRI helper existed.
- A remote client had no way to discover the settings surface from the actor/community document alone.

## Solution

### Server (Iris.Server)

1. **`iris:settings` extension property** on the public document:
   - Person: present when `manuallyApprovesFollowers` is `true`. Value = actor's outbox IRI.
   - Community: present when `manuallyApprovesMembers` is `true`. Value = community's outbox IRI.
   - The full term is `{NamespaceIri}settings` (configurable per-deployment, default
     `https://iris.example/ns#settings`).

2. **`iris:capabilities` list** includes `"settings"` when the gate is present, so a client scanning
   capabilities can tell the actor/community has a settings surface before reading the IRI.

3. **`CapabilitySettings = "settings"`** constant added to `ActivityPubServerConstants`.

4. **`SettingsTerm = "settings"`** constant added to `ActivityPubServerConstants`.

### Core (Iris.Core)

5. **`IriExtensions.SettingsOf(Iri)`** — derives the settings IRI by appending `/settings` to an
   actor/community IRI (e.g. `https://a.domain.local/ap/v1/c/devs/settings`).

### Client (Iris.Client)

6. **`IrisDocumentExtensions`** static class with:
   - `GetSettingsIri(Object, string namespaceIri)` — reads the `iris:settings` extension from a
     fetched actor/community document, returning the `Iri?` (null when absent).
   - `GetCapabilities(Object, string namespaceIri)` — reads the `iris:capabilities` extension,
     returning `IReadOnlyList<string>` (empty when absent).

### Tests

7. **10 new integration tests** (`IrisSettingsExtensionIntegrationTests`):
   - Person doc with gate: `iris:settings` present + `"settings"` in capabilities.
   - Person doc without gate: `iris:settings` absent + `"settings"` not in capabilities.
   - Community doc with gate: `iris:settings` present + `"settings"` in capabilities.
   - Community doc without gate: `iris:settings` absent + `"settings"` not in capabilities.
   - Client `GetSettingsIri` reads the extension (present/absent cases).
   - Client `GetCapabilities` includes/excludes `"settings"` (present/absent cases).
   - `SettingsOf()` IRI helper (community + person).
