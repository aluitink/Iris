# 42.1 — Community "manuallyApprovesMembers" toggle

## Summary

The community edit form (`/community?iri=…`) gains a **"Require approval for join requests"**
checkbox (visible to the community creator). When the checkbox is toggled and the form is saved,
the client calls `IActivityPubClient.SetManuallyApprovesMembersAsync` (an existing AP-native
settings write: an `Add` or `Remove` of the community's own document to its outbox), which updates
the `manuallyApprovesMembers` extension on the community's `ExtensionData` server-side.

This makes the 41.3 Requests tab functional: creators can now *enable* the gate so that inbound
`Join` activities are recorded as pending requests instead of auto-granting membership.

## Changes

### `apps/Iris.Web/Components/Pages/CommunityDetail.razor`

- **Edit form:** added a `form-group--checkbox` div with a `<input type="checkbox"
  @bind="EditApproveMembers">` labelled "Require approval for join requests" and a muted hint
  line.
- **`StartEditCommunity`:** reads the current flag via `group.GetManuallyApprovesMembers() ??
  false` and stores it in `OriginalApproveMembers` (for change detection).
- **`SubmitCommunityEditAsync`:** after the `UpdateActorAsync` call succeeds, checks
  `EditApproveMembers != OriginalApproveMembers`; when true, calls
  `client.SetManuallyApprovesMembersAsync(communityIri, EditApproveMembers)`. A failure on the
  flag call (but not the profile update) shows an error message.
- **New fields:** `EditApproveMembers` (bool, bound to the checkbox) and
  `OriginalApproveMembers` (bool, captured at edit-start for change detection).

### `tests/Iris.Web.Tests/CommunityApproveMembersToggleIntegrationTests.cs` (new)

Five integration tests booting the full app via `WebAppFactory` + `TestServer`:

| Test | Verifies |
|---|---|
| `FreshCommunity_GetManuallyApprovesMembers_ReturnsNull` | A new community has no gate (reader returns `null`). |
| `SetFlag_Enable_SetsFlagOnDocument` | `SetManuallyApprovesMembersAsync(true)` → document advertises the gate (`true`). |
| `SetFlag_Disable_ClearsFlagOnDocument` | Enable then disable → gate is removed (`null`). |
| `Flag_EnablesJoinRequestRecording` | Without the flag a Join auto-grants membership; with the flag a Join is recorded as a pending request (not a member). |
| `Flag_Disabled_Again_AllowsAutoJoin` | Enable → Join becomes a request; disable → next Join auto-grants. |

The tests use a signed `IActivityPubClient` (via `ActivityPubClientFactory` + `LazyHandler`)
for the flag-set delivery and a `SigningHandler` for the Join delivery. A
`LocalActorDocumentFetcher` (inner class) replaces the default `IActorDocumentFetcher` so the
server's signature validator resolves keys for local actors without an HTTP round-trip.

### `tests/Iris.Web.Tests/Iris.Web.Tests.csproj`

Added `ProjectReference` to `Iris.Testing` (for `LazyHandler`).

## Infrastructure (pre-existing, unchanged)

- `IActivityPubClient.SetManuallyApprovesMembersAsync` (change 217) — publishes an `Add`/`Remove`
  to the community's outbox.
- `IrisDocumentExtensions.GetManuallyApprovesMembers` — reads the flag from `ExtensionData`.
- Server outbox handler (`CommunityOutboxPublishHandler`) → `RecordCommunityAddAsync` /
  `RecordCommunityRemoveAsync` → `SetManuallyApprovesMembersAsync` (persistence).
- `ICommunityStore.HasJoinRequestAsync` / `IsMemberAsync` — membership + pending-request queries.
