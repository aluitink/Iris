# 161y — 20.4(d): browser-loadable media for external attachments

> 2026-09-02 · Slice 161y · Phase 20.4 (d) · Decision 057

## What was built

The inbound/external-read half of media (deferred by 20.2/056 (b) and scoped out by 161v): when the client
browses any **external** stream (a random user's outbox, a user's liked/featured, communities, the
followed feed, synced peers, the owner-only inbox), an object's attachment can carry a **cross-origin**
`url` that the browser cannot load (the remote host sends no CORS headers → the image is blocked).

The fix keeps the **wire 100% AP-native/verbatim** in every collection. The **client's render boundary**
rewrites each cross-origin attachment `url` to a same-origin media-proxy IRI
(`{base}/ap/v1/media/proxy?url={percent-encode(originator-url)}`); same-origin URLs pass through
unchanged. A new **public, long-cacheable** `GET /ap/v1/media/proxy?url=…` route **fetches the remote URL
once** (an unsigned outbound GET), **stores** the bytes (keyed by the source URL + a server-internal
content-hash dedupe), and **serves them from the same origin** (`max-age=31536000, immutable`). A cache
hit (the URL was already stored) serves straight from the store with **no outbound fetch**. A fetch
failure (a dead/unreachable URL) is a **502** so the client's `<img onerror>` falls back to a link-out to
the raw URL (a degraded case is a link, never a broken image). A missing or non-HTTP(S) `url` is a **400**.

**Eager-warm is on by default** (`MediaOptions.EagerWarm`): when the server *stores* an object with
attachments (inbound `Create`, followed/community content, synced peers), it pre-fetches the cross-origin
attachments by URL (best-effort, non-blocking, idempotent) so the proxy serves them instantly. Cold
external browsing is lazy-by-nature (warmed on the first proxy hit).

The **URL is the key** (the client always has the originator's attachment `url`, so a cold external object
a content hash could not cover still resolves); the **content hash (SHA-256) is a server-internal dedupe
index only** (the client never computes or uses it). No new NuGet; no id/document rewrite (055 + 056 (c)
unchanged); no collection-serializer rewrite.

## Key types & files

**New (server):**
- `src/Iris.Server/Media/IMediaFetcher.cs` — the fetch seam (`FetchAsync(Iri sourceUrl, ct)` →
  `FetchedMedia?`); `FetchedMedia(byte[] Content, string ContentType)`.
- `src/Iris.Server/Media/DefaultMediaFetcher.cs` — an unsigned outbound GET over a pre-built
  `HttpClient` (absolute HTTP(S) only; `null` on 4xx/5xx/network error/timeout).
- `src/Iris.Server/Media/IMediaWarmer.cs` — the eager-warm seam (`WarmAsync(IObject?, Iri instanceBase, ct)`).
- `src/Iris.Server/Media/DefaultMediaWarmer.cs` — best-effort pre-fetch of a stored object's cross-origin
  attachments (skips same-origin; swallows per-attachment failures; a no-op when `EagerWarm` is false).

**Changed (server):**
- `src/Iris.Server/Stores/IMediaStore.cs` — `PutBySourceUrlAsync(sourceUrl, content, contentType, baseUrl, ct)`
  and `TryGetMediaIriBySourceUrlAsync(sourceUrl, out Iri?, ct)` (the URL-keyed store + lookup).
- `src/Iris.Server/ActivityPubServerExtensions.cs` — the `GET /ap/v1/media/proxy?url=…` route
  (`MediaProxyHandler`: 400 on invalid url → cache-hit serve → fetch → 502 on failure/oversize →
  `PutBySourceUrlAsync` → serve long-cacheable); DI for `IMediaFetcher` (named `HttpClient`, 30 s timeout)
  + `IMediaWarmer`; `MediaOptions`/`EagerWarm`.
- `src/Iris.Server/ActivityPubServerOptions.cs` — `MediaOptions? Media` + the `MediaOptions` class
  (`EagerWarm = true`).
- `src/Iris.Server/Inbox/CreateActivityHandler.cs` — the eager-warm hook: after `PutObjectAsync` in
  `StoreEmbeddedObjectAsync`, calls `_mediaWarmer.WarmAsync(embedded, instanceBase, ct)` (only when
  `BaseUri` is set — tolerant; a no-op otherwise).
- `src/Iris.Server.InMemory/Stores/InMemoryMediaStore.cs` — the URL index (`urlKey → full media IRI`) + the
  content-hash dedupe index; `MediaIdFromIri` now tolerates a bare id.
- `src/Iris.Server/Persistance/Stores/FileBackedMediaStore.cs` — the same URL/hash indices persisted in the
  JSON document (`{media, urlIndex, hashIndex}`); `MediaMeta` gains `ContentHash`; `MediaIdFromIri`
  tolerant of a bare id.
- `src/Iris.Client/MediaConstants.cs` — `ProxySegment` + `ProxyQueryParam`.

**New (client):**
- `src/Iris.Core/Identity/IriMediaProxyExtensions.cs` — `ToBrowserMediaIri(this Iri, Iri instanceBase)`:
  the pure render-boundary rewrite (cross-origin HTTP(S) → same-origin proxy IRI, the url percent-encoded;
  same-origin / relative / non-HTTP(S) → passthrough).
- `samples/SampleBlazorClient/Components/ObjectView.razor` — the render boundary wired up: the
  `MediaAttachments` property rewrites each attachment's IRI via `ToBrowserMediaIri` (the instance base is
  the logged-on `ExplorerSession.DialBaseUri`, resolved lazily via `IServiceProvider` so the component
  renders standalone in the bunit tests); the `<img onerror>` fallback swaps a broken image for a link-out
  to the raw URL.

## Tests

Test count before → after: **1,325 → 1,342** (all 7 test projects green, 0 failed).

**New (+17):**
- `tests/Iris.Core.Tests/Identity/IriMediaProxyExtensionsTests.cs` (9) — the client-rewrite unit:
  cross-origin → proxy IRI (https + http), same-origin passthrough, same-host-different-port cross-origin,
  relative passthrough, non-HTTP(S) passthrough, nested-query percent-encoding (no raw `&`), trailing-slash
  base normalization.
- `tests/Iris.Server.Tests/Media/MediaProxyIntegrationTests.cs` (8) — over a real in-process `TestServer`
  with a deterministic `IMediaFetcher` fake (registered via the host factory's `ExtraServices`):
  fetch-stores-serves-same-origin (+ long-cache + store mapping), cache-hit no-refetch, 502 on a dead URL,
  400 on a missing url, 400 on a relative url, public no-auth, eager-warm (an inbound signed `Create` with a
  cross-origin attachment pre-fetches once → the proxy is a cache hit), eager-warm-disabled (no warm → the
  proxy fetches lazily).

**Changed:**
- `tests/Iris.Server.Tests/Inbox/CreateActivityHandlerTests.cs` — `BuildHandler` now passes a no-op
  `IMediaWarmer` + a default `IOptions<ActivityPubServerOptions>` (no `BaseUri` → the warm hook is skipped;
  these unit tests do not exercise warming).
