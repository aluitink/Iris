# 244: 26.5 Delivery-Worker Dead-Letter Store Wiring (F-22)

**Status:** Done
**Date:** 2026-09-04

## Summary

Added an end-to-end integration test locking the delivery-worker dead-letter store
wiring in a real 2-instance `TestServer` topology. When a cross-instance delivery
exhausts its retry budget, the job is moved to the `IDeliveryDeadLetterStore`
singleton with the correct metadata.

## What was built

- `tests/Iris.Server.Tests/DeliveryDeadLetterIntegrationTests.cs` (1 test, 259 lines).

### Topology

Two in-process `TestServer` instances:
- **A** (alice) — the delivering instance. Its `DeliveryTransport` is a
  `FailingInboxHandler` that wraps B's handler and returns 500 for POSTs to
  bob's inbox.
- **B** (bob) — the receiving instance. Bob's actor doc is served normally.

### Scenario

1. Bob (on B) posts a signed `Follow` to alice's inbox on A.
2. A validates bob's key (fetching B's actor doc), records the follow edge, and
   auto-constructs an `Accept` (actor = alice, object = the follow).
3. A enqueues the `Accept` for delivery to bob's inbox on B.
4. A's `DeliveryWorker` picks up the job and delivers via the `FailingInboxHandler`
   (which returns 500). The worker retries per the default `DeliveryRetryOptions`
   (5 attempts, 1s base delay, exponential backoff: 1s + 2s + 4s + 8s = 15s).
5. After all 5 attempts fail, the worker calls `DeadLetterAsync`, which adds a
   `DeadLetterEntry` to A's `IDeliveryDeadLetterStore`.

### Assertions

- The dead-letter store holds exactly 1 entry.
- `InboxIri` == bob's inbox IRI.
- `ActorIri` == alice's IRI (the acting actor of the auto-Accept).
- `FailureKind` == `NonSuccessStatus`.
- `FailureDetail` == `"500"`.
- `Attempts` == 5 (the default `MaxAttempts`).
- The dead-lettered activity is the `Accept` (non-null `Id`).

## Key decision

**Used default `DeliveryRetryOptions` (5 attempts, 1s base) instead of overriding
via `ExtraServices`.** The `IOptions<T>` resolution in .NET caches the first
resolved `T` instance; a later `AddSingleton<T>` registration does not override
the cached value. Rather than fighting the DI options system (which would require
registering a custom `IConfigureOptions<T>` or `IOptionsFactory<T>`), the test
uses the production defaults and a 30s wait timeout. The test runs in ~15s (the
total backoff time), which is acceptable for an integration test.

## Non-vacuity proof

Forcing the "no store" path in `DeadLetterAsync`
(`if (_deadLetter is not { } store || true)`) makes the test fail: the store
stays empty, 5 500s are served, and the wait for `Count == 1` times out after 30s.
Restoring the code makes the test pass in ~15s.
