# 276 — 31.3: sample should not seed fake `remote.example` activities

> 2026-09-05 · Slice 31.3 · Phase 31 (explorer UI & server namespace polish)

## What was built

The sample server seeded a third actor, **carla**, on the `remote.example` host
label (an in-process stand-in for a peer instance) with her own note, a like of
alice's note, and follow edges to/from alice. Because all of it was served by the
one server, the seeded graph read as cross-instance federation when it was not —
the sample's default data was dishonest. The 31.3 report asked to **remove the
fake remote-host seed (or gate it behind an explicit opt-in)** so the default is
honest.

The fix **gates** the carla seed behind `Iris:Seed:RemoteStandIn` (default
`false`) rather than deleting it: the federation, persistence, and community-
signing suites all exercise carla's Ed25519 remote-actor path, so removing her
would tear out real test coverage. Gating keeps that coverage (the tests opt in)
while making the **default** sample one honest instance.

## Key types & files

- `samples/SampleServer/Program.cs`
  - `SeedSampleData` gains a `bool remoteStandIn = false` parameter. When off,
    carla's actor/key are not minted and none of her follow edges, note, or like
    are seeded. The `SeedMetadata` (handles + key set) excludes carla accordingly.
  - `GetSeededKeyIris` gains a `remoteStandIn` overload (the no-flag overload
    delegates with `false`, so the default seed never registers carla's key with
    the `IKeyProvider`).
  - `CreateWebHostBuilder` now passes the host's resolved configuration into
    `ConfigureServices` (`.ConfigureServices((context, services) =>
    ConfigureServices(services, context.Configuration))`). This is the load-bearing
    change: a bare `IWebHostBuilder.ConfigureServices(services => …)` injects the
    *default* (env/args) configuration, **not** the one a `TestServer` test
    replaces via `UseConfiguration` — so the `Iris:Seed:RemoteStandIn` switch
    (and `Iris:PersistenceDirectory`) were invisible to `ConfigureServices` in the
    in-process test surface. Using `context.Configuration` makes the host's
    authoritative config the one the seed reads.
- `tests/SampleServer.Tests/SampleServerFederationTests.cs` — fixture opts in via
  `Iris:Seed:RemoteStandIn=true`; **new** `DefaultSample_DoesNotSeedRemoteStandIn`
  (hosts a default server and asserts no carla actor, no alice→carla edge, empty
  carla outbox).
- `tests/SampleServer.Tests/SampleServerCommunitySigningTests.cs` — fixture opts
  in; `GetSeededKeyIris_IncludesCommunity` uses `remoteStandIn: true`; **new**
  `GetSeededKeyIris_Default_ExcludesRemoteStandIn`.
- `tests/SampleServer.Tests/SampleServerPersistenceTests.cs` — the file-backed
  re-seed test passes `remoteStandIn: true` (its carla-like durability assertion
  now exercises the opt-in path).
- `samples/SampleServer/README.md` — documents `Iris:Seed:RemoteStandIn` and marks
  carla opt-in.

## Design notes

- **Gate, not remove.** carla is the only seeded actor that exercises the
  non-RSA (Ed25519) key load path and the "remote-host actor is unresolvable by
  the inbound resolver" honest-federation boundary. Deleting her would drop that
  coverage; gating it behind an explicit switch keeps the coverage and makes the
  default honest — exactly the "remove it **or** gate it" the report allows.
- **The config-injection fix is the subtle part.** `UseConfiguration` on
  `IWebHostBuilder` replaces the host's configuration, but the
  `ConfigureServices(Action<IServiceCollection>)` overload hands `ConfigureServices`
  the *default* configuration (env/args only), not the replaced one. That is why
  the switch had to be read from `context.Configuration`. This also means
  `Iris:PersistenceDirectory` was only ever honored via the env-var path in the
  in-process tests (the `BuildServer` helper's `UseConfiguration` for that key
  was effectively a no-op for `ConfigureServices`); the fix makes per-host config
  authoritative for both.
- No new NuGet packages; `SeedSampleData`'s public signature is backward
  compatible (the new parameter has a default).
