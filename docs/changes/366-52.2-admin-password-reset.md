# 52.2: Admin-Assisted Password Reset

## Summary

Admins can now reset any user's password from the `/admin/users` page. This provides an
account-recovery path when a user forgets their password.

## Changes

### Server (`apps/Iris.Web/WebAppFactory.cs`)

- Added `POST /local/v1/admin/users/{id}/password-reset` endpoint (Admin role).
  - Accepts `AdminPasswordResetRequest` JSON body with `password` field.
  - Validates minimum length (8 chars, reusing `RegistrationService.MinPasswordLength`).
  - Looks up the user by ID, hashes the new password, persists via
    `IUserAccountStore.UpdatePasswordHashAsync`.
  - Returns 200 with `{ success, username }` on success, 400 with `{ error }` on
    validation failure, 404 if user not found.
- Added `AdminPasswordResetRequest` record.

### Client (`apps/Iris.Web.Client/Components/Pages/AdminUsers.razor`)

- Fixed the page to use `IHttpClientFactory` with the named "iris" client instead of a
  bare constructor-injected `HttpClient` (which had no BaseAddress in WASM).
- Fixed `AdminUserDto.Role` from `string` to `int` (server serializes the `UserAccountRole`
  enum as a number) with a computed `RoleLabel` property for display.
- Added "Action" column with a "Reset password" button per user row.
- Inline password-reset form: clicking "Reset password" reveals a password input + Set/Cancel
  buttons below the table. Client-side minimum-length check before submit.
- Success/error messages displayed inline.

## Decisions

- The reset form is inline (no modal) to keep the page simple and consistent with the
  settings-page pattern.
- No confirmation step (no "type the username to confirm") — the admin is already
  authenticated and the action is clearly labeled.
