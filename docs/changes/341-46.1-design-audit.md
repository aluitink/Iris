## Design findings

### P1 — High impact, low effort

1. **Nav bar is cramped at 1280px.** All 9 links (Iris, Home, New post, Notifications, Directory, Communities, Profile, Settings, Search, Log out) fit on one line but are tightly packed with no visual grouping. At 375px the nav truncates to "Com…" (Communities) with no scroll or hamburger. **Decision:** add a hamburger menu below 768px; group related nav items (e.g. "Explore" dropdown for Directory/Communities/Search) at desktop.

2. **Post cards lack visual hierarchy between author and content.** The author handle is the same weight/size as the content. On the home timeline, `andrew` and `Hi` look like peers. **Decision:** make the author handle slightly bolder or a different color (e.g. `--accent` or `font-weight: 600`), and reduce the content's visual weight slightly.

3. **Timestamp placement is inconsistent.** On home timeline posts, the timestamp is top-right of the card. On profile "Your posts," the timestamp is the only visible content (no author, no content — just "27m ago"). This looks like a rendering bug. **Decision:** profile posts should show the same card layout as the home timeline (author + content + timestamp + engagement bar).

4. **Empty space below content is excessive.** Most pages have the content in the top half and the bottom half is empty dark space. The content column is centered but the page doesn't use the vertical space well. **Decision:** add a max-width (e.g. 680px) to the content column and center it; on tall screens, consider a subtle background pattern or gradient to reduce the "void" feeling.

### P2 — Medium impact

5. **Buttons are all the same blue.** "Refresh," "Follow," "Block," "Mute," "Report," "Post," "Mark all as read" are all the same `--accent` blue. This makes it hard to distinguish primary actions (Post, Follow) from secondary (Refresh) from destructive (Delete, Block). **Decision:** introduce a button hierarchy — primary (accent blue), secondary (neutral/ghost), destructive (red). "Refresh" should be secondary/ghost. "Delete" is already red. "Block" should be a warning color (amber/orange).

6. **No avatars in the directory or home timeline.** The directory shows handle + name + summary but no avatar circle. The home timeline cards show only the handle text. The actor detail page has a large avatar circle, but it's not repeated in the feed cards. **Decision:** add a small (24px) avatar circle next to the handle in feed cards and directory rows.

7. **The "Iris" brand in the nav is just a text link.** It's the same style as the other nav links (just colored). It should feel like a brand mark. **Decision:** make it slightly larger, bolder, and possibly add a small icon/logo next to it.

8. **Tab bars (Profile, Actor, Community, Settings) are plain text.** "Your posts | Replies | Likes" is just underlined text. No visual indication of the active tab beyond the underline. **Decision:** add a subtle background to the active tab, or use a pill/segmented-control style.

### P3 — Low impact / polish

9. **Footer is minimal.** "Iris — an ActivityPub social platform." is the only content. No links, no instance stats, no social links. **Decision:** add a few links (About, NodeInfo, Source) + instance stats (post count, user count) in the footer.

10. **The "An unhandled error has occurred" bar is always visible** at the bottom of every page (the Blazor WASM error boundary). It's a thin bar with "Reload" + "×" buttons. It's functional but visually noisy. **Decision:** hide it until an error actually occurs (CSS `display: none` by default, shown by the error boundary).

11. **Search page description is too technical.** "the server's `GET /ap/v1/search`, F-13" is developer-facing jargon. **Decision:** simplify to "Search across the instance for people and posts."

12. **Community list rows lack structure.** "Iris Communityiris" and "Test Communitytest-community" show the name and handle concatenated without visual separation. **Decision:** add a line break or different styling for the handle (e.g. `@handle` in a lighter color below the name).

13. **Compose page has a lot of empty space below the form.** The form is in the top third, the rest is empty. **Decision:** add a "Tips" or "Formatting help" section below the form, or reduce the empty space.

14. **Notification rows show raw IRIs.** "https://iris.luit.ink/ap/v1/u/alice/notes/06G7ZEQYYGGTX9R7QSS8TVXPG8" is shown as the notification detail. This should be a human-readable reference (e.g. "liked your post 'Valid PNG test'" with a link). **Decision:** resolve the IRI to the note's content (truncated) + author, and make it a link to the object detail page.
