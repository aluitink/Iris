# 57.1 — Feed query profiling and index review

## Summary

Profiled all EF Core queries in `Iris.Server.Data` against the feed hot paths (home feed, public feed, outbox, inbox). Fixed the critical N+1 in `GetBoxAsync`, added a missing index for the collection read path, removed two redundant indexes, and replaced a full-table-scan count with `COUNT(*)`.

## Findings (ranked by impact)

### CRITICAL

1. **N+1 in `EfActivityStore.GetBoxAsync`** — per-item `FirstOrDefaultAsync` on `ActivityEntity` in a loop. Affects every feed/outbox/inbox read. For a page of 30 items: 31 round trips. Fixed by batching into a single `WHERE Id IN (...)` query.

2. **N+1 in `EnrichCollectionItemsAsync`** — per-item `GetLikersAsync` + `GetAnnouncersAsync` + `GetRepliesAsync` (+ `HasLikedAsync` + `HasAnnouncedAsync`). For M=200 items: ~1000 queries. **Deferred to 57.4** (requires adding batch methods to store interfaces; larger change).

### HIGH

3. **Missing index `BoxItems(Direction, ActorId, Position)`** — `GetBoxAsync` orders by `Position` which is not in the composite PK, forcing a sort. Added the index.

4. **`ListObjectsAsync` / `ListActorsAsync` full-table-scan with jsonb deserialization** — called by search and public feed. **Deferred to 57.4** (requires pagination + text-search indexing).

### MEDIUM

5. **`EfInstanceStatsProvider` loads all users to count** — replaced with `COUNT(*)` via a new `IUserAccountStore.CountAsync` method.

6. **`UserAccountEntity.Username` `ToLower()` defeats the index** — **Deferred** (requires `citext` column or expression index; low priority pre-launch).

### LOW

7. **Redundant index on `Edges (Kind, Source, Target)`** — duplicated the composite PK. Removed.

8. **Redundant index on `Media (Id)`** — duplicated the PK. Removed.

9. **Unused index on `Activities.ActivityType`** — no query filters on it. Kept (harmless, may be useful for future admin queries).

## Changes

### `src/Iris.Server.Data/Stores/EfActivityStore.cs`
- `GetBoxAsync`: replaced the per-item `FirstOrDefaultAsync` loop with a batch `WHERE Id IN (...)` query + in-memory dictionary lookup. Reduces 1+N queries to 2.

### `src/Iris.Server.Data/IrisDbContext.cs`
- Added `HasIndex(e => new { e.Direction, e.ActorId, e.Position })` on `BoxItems` — the collection read path is now an ordered index scan with no sort.
- Removed the redundant `HasIndex(e => new { e.Kind, e.Source, e.Target }).IsUnique()` on `Edges` (duplicated the composite PK).
- Removed the redundant `HasIndex(e => e.Id)` on `Media` (duplicated the PK).

### `src/Iris.Server.Data/Accounts/IUserAccountStore.cs`
- Added `Task<int> CountAsync(CancellationToken ct = default)`.

### `src/Iris.Server.Data/Accounts/EfUserAccountStore.cs`
- Implemented `CountAsync` using `db.Set<UserAccountEntity>().CountAsync(ct)` (translates to `SELECT COUNT(*)`).

### `src/Iris.Server.Data/Accounts/InMemoryUserAccountStore.cs`
- Implemented `CountAsync` returning `_accounts.Count`.

### `src/Iris.Server.Data/EfInstanceStatsProvider.cs`
- `GetLocalUserCountAsync` now calls `_accounts.CountAsync(ct)` instead of loading all accounts.

### `src/Iris.Server.Data/Migrations/`
- Regenerated single migration (`InitialCreate`) per the pre-launch squash policy.
