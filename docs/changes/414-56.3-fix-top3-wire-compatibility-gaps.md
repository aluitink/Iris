# 56.3 — Fix Top-3 Wire Compatibility Gaps

## Summary

Implemented fixes for the three highest-impact wire compatibility gaps identified in 56.1 (Mastodon) and 56.2 (Pleroma/Akko):

1. **`updated` timestamp** — stamp on content object edits in `UpdateActivityHandler`
2. **`source` field** — emit raw markdown source in `ComposeNote.Build`
3. **`summary` decoupled from `sensitive`** — CW is now independent of the sensitive flag

## Changes

### 1. `updated` timestamp on edits

**File:** `src/Iris.Server/Inbox/UpdateActivityHandler.cs`

Before storing the updated object, the handler now stamps `updated` with `DateTime.UtcNow` (or the `published` timestamp if that is later — ensuring `updated >= published`). This only applies to content objects (Notes, Articles), not actor profile documents (which use field-merge semantics in `HandleActorUpdateAsync`).

**Why:** Mastodon and Pleroma both set `updated` on edited notes. Without it, remote clients cannot detect that a note was edited (no "edited" marker, no re-fetch trigger).

### 2. `source` field with raw markdown

**File:** `src/Iris.Core/Compose/ComposeNote.cs`

When `markdownHtml` is provided (Markdown was rendered to HTML), `ComposeNote.Build` now emits a `source` field into `ExtensionData`:

```json
"source": { "content": "<raw markdown>", "mediaType": "text/markdown" }
```

The raw markdown (the `content` parameter) is preserved alongside the rendered HTML (in `content`), so remote clients (Mastodon, Pleroma) can re-render or display the original markdown.

**Why:** Both Mastodon and Pleroma emit `source` for markdown notes. Without it, a Mastodon client receiving an Iris note has no markdown source to display or edit.

### 3. `summary` independent of `sensitive`

**File:** `src/Iris.Core/Compose/ComposeNote.cs`

The `summary` (content warning) is now emitted whenever it's non-empty, regardless of the `sensitive` flag. Previously, `summary` was only set when `sensitive` was also `true`.

**Why:** Mastodon and Pleroma treat `summary` (CW) as independent of `sensitive` (NSFW flag). A post can have a content warning without being marked sensitive.

## Decisions

- `updated` is stamped on the server side (in `UpdateActivityHandler`), not the client side. The server is the timestamp authority (it already stamps `published`). The client's `SaveEditAsync` doesn't need to change.
- `source` is written into `ExtensionData` (Rule 6) since the ActivityStreams library doesn't model a `source` property.
- The `source.content` carries the **raw markdown** (the `content` parameter to `Build`), not the rendered HTML. The rendered HTML is in the note's `content` field.
- `summary` is now independent of `sensitive` — a note can have a CW without being marked sensitive, matching Mastodon/Pleroma behavior.
