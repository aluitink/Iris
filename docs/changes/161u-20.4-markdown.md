# 161u — Phase 20.4 (c): markdown rendering in the object view

## Summary

Phase 20.4 (sub-part **c**) makes a note's `content` that is **Markdown** render properly in the object
view — headings, inline/fenced code, links, unordered/ordered lists, and emphasis — instead of as escaped
raw text. A small, **dependency-free** `Markdown` renderer (sample-local) converts the Markdown subset the
object view needs to safe HTML, and the object view renders `content` through it.

## Decision: dependency-free, not a markdown NuGet

The ROADMAP left the approach open ("a dependency-free renderer or a small markdown lib; note any new
NuGet"). We chose **dependency-free**, for:

- **Proportionality.** A markdown engine (Markdig, CommonMark.NET, …) is a general-purpose library with
  a non-trivial surface (tables, footnotes, reference links, …) — most of which the object view never
  uses. Adding it to the *sample* (a UI host, not a library) just to render a few constructs is heavier
  than warranted.
- **Security control.** A hand-rolled renderer gives us an explicit, auditable security model: HTML is
  escaped first and link schemes are allow-listed. A full markdown engine's HTML-output options would
  need careful configuration to be equally safe.
- **The codebase is strict about dependencies** (Central Package Management, "no new NuGet without a
  ROADMAP note + justification"). A ~250-line pure function is easier to review and maintain than a
  transitive dependency.

**Trade-off accepted:** the renderer is intentionally *not* a general markdown engine — it supports the
subset the object view needs (headings `#`–`######`, inline code `` ` ``, fenced code ``` ``` ```,
links `[text](url)`, `-`/`*`/`1.` lists, `**bold**`/`*italic*`, paragraphs, hard line breaks). Tables,
blockquotes, reference-style links, etc. are out of scope (they render as their escaped literal text).

## What changed (code)

- **`samples/SampleBlazorClient/Markdown.cs`** (new) — a static, dependency-free `Markdown.ToHtml(string?)`
  renderer:
  - **Escapes HTML first** (`& < > " '` → entities) so any raw markup in the content is inert and rendered
    as text.
  - **Fenced code blocks** are pulled out as placeholders first (so a `#`/`-` inside a fence is literal),
    then emitted as `<pre><code class="language-{lang}">`.
  - **Blocks** split on blank lines: a **heading** (`#`–`######`) → `<h1>`–`<h6>`; a **list** (every line an
    item) → `<ul>`/`<ol>`; otherwise a **paragraph** (hard line breaks → `<br/>`).
  - **Inline:** code spans first (contents not further transformed), then **links** `[text](url)` →
    `<a href rel="nofollow noopener" target="_blank">` (the url is **allow-listed**: only
    `http://`/`https://`/`mailto:` survive — a `javascript:` or any other scheme renders the text as plain
    text, never a live link), then `**bold**` → `<strong>`, `*italic*` → `<em>`.
- **`samples/SampleBlazorClient/Components/ObjectView.razor`** — the content block now renders through
  `Markdown.ToHtml(JoinStrings(obj.Content))`, emitted as a `MarkupString` (a `RenderedContent` computed
  property). The **sensitive-notice** path renders the markdown only **after reveal**, exactly as before
  (the content stays out of the DOM until the viewer opts in).
- **`samples/SampleBlazorClient/wwwroot/css/app.css`** — styling for the rendered elements (headings,
  paragraphs, links, inline `<code>`, `<pre>`, lists) in the app palette.

## New tests (32, all passing)

- **`tests/SampleBlazorClient.Tests/MarkdownTests.cs`** (new, +25) — unit tests for the renderer (it is
  pure string→string, so unit tests are appropriate): null/blank; plain → `<p>`; headings h1–h6; a heading
  with inline markdown; inline code (and its contents not further transformed); fenced code (with/without
  language, contents not transformed); links (http + mailto → anchor with `rel`/`target`); **unsafe-scheme
  rejection** (`javascript:`, relative, `ftp:` → the link is dropped, the text remains); unordered
  (`-`/`*`) and ordered (`1.`) lists; a list item with inline markdown; bold/italic (and `**` → bold, not
  two italics); **raw-HTML escaping** (`<script>`/`<img onerror>` escaped, never emitted live); hard line
  breaks; multiple blocks; `&` escaping.
- **`tests/SampleBlazorClient.Tests/S20MarkdownObjectViewTests.cs`** (new, +7) — bUnit object-view tests
  (mirroring the sensitivity tests): a note with a markdown heading renders a real `<h1>` (not escaped raw
  text); a markdown link renders a real `<a>` with the href; inline code renders a `<code>`; a list renders
  `<li>`s; plain content renders as a `<p>`; **raw HTML in content is escaped** (no live `<script>`); a
  sensitive note's markdown renders only after reveal.

## What is deliberately NOT in this slice

- **Full CommonMark** — tables, blockquotes, reference-style links, autolinks, images, etc. are out of
  scope (they render as their escaped literal text). The subset covers the ROADMAP's listed cases (links,
  code, lists, headings) + emphasis.
- **(a) Media** — compose upload → Create object with attachment → stored/served → rendered in the object
  view (builds on 20.2's attachment-rewrite decision).
- **Authoring markdown** — the compose UI posts plain text; the renderer handles *displaying* markdown
  content (which is what arrives from ActivityStreams `content`).
