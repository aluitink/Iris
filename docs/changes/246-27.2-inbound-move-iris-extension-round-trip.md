## Context

When a `Move` activity carrying `iris:`-namespaced extension properties (e.g. `iris:reason`) is
delivered to a follower's inbox, the receiving instance must preserve the extensions through the
full wire round-trip: JSON deserialize → `ExtensionData` → store → read back → serialize.

The ActivityStreams library (`KristofferStrube.ActivityStreams`) stores unknown JSON properties in
the `Object.ExtensionData` dictionary (keyed by the full JSON-LD IRI, e.g.
`https://iris.example/ns#reason`). When the activity is deserialized from the wire, the `iris:`
extensions land in `ExtensionData`. When the receiving instance stores the activity (via
`IActivityStore.TryAddActivityAsync`) and later serves it (via the object-document endpoint or a
re-federation), the `ExtensionData` is serialized back out.

This slice locks that invariant with an integration test.

## Topology

- **Instance A** (`move-ext-a.domain.local`): alice (the migrating actor, seeded with a key).
- **Instance B** (`move-ext-b.domain.local`): bob (a local follower of alice).

Bob (on B) follows alice (on A). Alice migrates to a new IRI on B and delivers a `Move` (carrying
an `iris:reason` extension) to bob's inbox on B. B validates the signature (fetches alice's actor
doc from A to resolve her key), stores the `Move`, and re-points bob's follow edge.

## Test

`MoveExtensionRoundTripIntegrationTests.Inbound_Move_WithIrisExtension_PreservesExtensionOnStoreAndGet`:

1. Build a `Move` with `Id`, `Actor` (old alice IRI), `Object` (new alice IRI), and an
   `iris:reason` extension property in `ExtensionData`.
2. Deliver the `Move` to bob's inbox on B, signed as the OLD alice (her key is on A).
3. Assert B returned `202 Accepted`.
4. Assert B stored the `Move` in its activity store (signature validated).
5. Assert the stored `Move` preserves the `iris:reason` extension (value `domain migration`).
6. Assert B's `MoveActivityHandler` re-pointed bob's follow edge (old IRI → new IRI).

## Non-Vacuity

The test exercises the full inbound path: wire JSON with `iris:reason` → ActivityStreams
deserialize → `ExtensionData` → `InMemoryActivityStore` → read back → assert `iris:reason` present.
If the library dropped `ExtensionData` during the serialize/deserialize cycle, the stored `Move`
would not have the `iris:reason` key and the test would fail. No code change was needed — the
ActivityStreams library already preserves `ExtensionData` through the round-trip.
