# 61.3 — Notification filtering + grouping

## Summary

Added server-side notification filtering and type-based grouping to the notifications
endpoint, plus a revamped WASM client UI with filter tabs and "Load more" pagination.

## Changes

### Server (`apps/Iris.Web/WebAppFactory.cs`)

- **New endpoint:** `GET /local/v1/notifications?type=&limit=&offset=`
  - Reads the actor's inbox from persistence
  - Applies user prefs (disabled types, muted actors) via `FilterInboxByPrefs`
  - Supports optional `?type=` filter (e.g. `?type=Like` for likes only)
  - Returns paged JSON: `{ items: [...], totalItems: N, nextPage: "..." | null }`
  - `limit` clamped to 1–100 (default 20), `offset` clamped to ≥ 0

### WASM Client (`apps/Iris.Web.Client/`)

- **`NotificationService.cs`** — added `GetNotificationsAsync(type, limit, offset, ct)`
  method and `NotificationPage` record for deserializing the paged response.
- **`Notifications.razor`** — replaced the raw AP inbox `PagedCollection` with a
  server-side filtered list:
  - Filter tabs: All / Follows / Likes / Boosts / Replies
  - "Load more" button for pagination (replaces next-link walking)
  - Items deserialized from `JsonElement` via `ActivityJson.Deserialize<IObjectOrLink>`
- **`app.css`** — added styles for `.notif-filter-tabs`, `.filter-tab`, `.notif-list`,
  `.notif-item`, `.notif-pagination`.
