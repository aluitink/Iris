## Defects Found

### D-60.1-1 (HIGH) — Search endpoint returns 500 for any query [FIXED]

**Page:** `/search?q=…` (any non-empty query)
**Repro:** Navigate to `https://iris.luit.ink/search?q=test`.
**Expected:** Search results rendered (actors first, then notes).
**Actual:** UI shows "Sign in to search" (misleading — user is signed in).
Console shows `500` from `/ap/v1/search?q=test&limit=100&offset=0`.

**Root cause:** `EfActorStore.CountSearchMatchesAsync` / `SearchActorsAsync` and
`EfObjectStore.CountSearchMatchesAsync` / `SearchObjectsAsync` used
`EF.Functions.Like(e.Document, pattern, "\\")` where `Document` is a CLR `string`
mapped to a Postgres `jsonb` column. Npgsql translates the 3-arg `Like` to
`like_escape(jsonb_col, @pattern, '\')` which Postgres rejects:
`function pg_catalog.like_escape(jsonb, unknown) does not exist` (SQLState 42883).

**Fix:** Replaced the EF `Like` call with `FromSqlRaw` using an explicit
`Document::text ILIKE {0} ESCAPE '\'` cast. The `::text` cast makes the `ILIKE`
operator valid on the jsonb column. Applied to all four store methods
(`EfActorStore.SearchActorsAsync`, `EfActorStore.CountSearchMatchesAsync`,
`EfObjectStore.SearchObjectsAsync`, `EfObjectStore.CountSearchMatchesAsync`).

### D-60.1-2 (MEDIUM) — Negative OFFSET in search pagination [FIXED]

**Page:** `/search` (pagination, page 2+)
**Repro:** `GET /ap/v1/search?limit=2&offset=2` (empty query, 4 total items).
**Expected:** Page 2 returns items 3–4.
**Actual:** 500 — `OFFSET must not be negative` (SQLState 22025).

**Root cause:** `GlobalSearchService.SearchPagedAsync` computed
`contentOffset = offset < actorTotal ? offset - actorTotal : 0`. When
`offset < actorTotal` (e.g. offset=2, actorTotal=4), this yields
`contentOffset = 2 - 4 = -2` — a negative offset passed to the store's
`.Skip(-2)` → `OFFSET -2` in SQL. The `contentLimit` also did not account for
actor items already taken in the page.

**Fix:** Changed to `contentOffset = Math.Max(0, offset - actorTotal)` and
tracked `actorTaken` to compute `remaining = limit - actorTaken`, so the content
slice only fills the remaining page slots. Applied to both the no-type-filter
and type-filter branches.

### D-60.1-3 (LOW) — 410 Gone console noise on Notifications [NOTED]

**Page:** `/notifications`
**Repro:** Open Notifications while following remote actors whose instances have
gone offline (flipboard.social, c.im, fairy.id, mastodon.cloud, etc.).
**Expected:** No console errors.
**Actual:** ~28 console `410 Gone` errors from `/ap/v1/proxy/…` (avatar/icon
fetches for deleted remote actors). UI renders gracefully; console noise only.

**Severity:** Low. The proxy could suppress avatar fetches for known-gone actors
(cached 410 responses), but this is a performance/UX polish item, not a
functional defect. Promoted to Phase 60 Up Next (60.2).

**Expected:** Page renders.
**Actual:** One transient `Failed to fetch` for
`System.Resources.Reader.o5l4jqkn.wasm` → "An unhandled error has occurred".
Reload fixes it. The file is served correctly (HTTP 200, `application/wasm`).

**Severity:** Informational. Post-restart artifact (Blazor WASM resource cache
invalidation). Not a code bug. No action needed.
