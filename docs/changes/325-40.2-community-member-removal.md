# 325 — Phase 40.2: Community member management

## Summary

The community creator can now remove members from the Members tab of the community detail page. A "Remove" button appears next to each member row (visible only to the creator, and hidden for the creator's own row). Clicking it calls a new local, Basic-authenticated endpoint that verifies the requester is the community's creator before removing the membership edge.

## Changes

### Server: `CommunityRemoveMemberHandler`

- **New endpoint:** `POST /local/v1/c/{name}/members/remove/{**target}` (route in `ActivityPubServerExtensions.cs:1022`).
- **Handler** (`ActivityPubServerExtensions.cs:5576`):
  1. Resolves the community IRI from the route's `name` segment.
  2. Verifies the community exists (404 if not).
  3. Parses the member IRI from the catch-all `target` route value (400 if invalid).
  4. Verifies the member is actually a member (404 if not).
  5. Authenticates the requester via Basic auth (`IActorCredentialValidator`).
  6. Iterates over the community's `AttributedTo` IRIs and validates the credentials against each (the creator is the one whose credentials match).
  7. Calls `persistence.Communities.RemoveMemberAsync` to remove the membership edge.
  8. Invalidates the members collection page cache.
  9. Returns 204 on success, 403 if the requester is not the creator, 404 if the community or member doesn't exist.

- **Helper** `ExtractHandleFromIri` (`ActivityPubServerExtensions.cs:5704`): extracts the final path segment from an actor IRI (e.g., `https://host/ap/v1/u/alice` → `alice`).

### Client: `RemoveCommunityMemberAsync`

- **`ILocalModerationClient.RemoveCommunityMemberAsync(Iri communityId, Iri memberId, ...)`** (interface + `LocalModerationClient` implementation): builds the local request URI `/local/v1/c/{name}/members/remove/{memberId}` from the community's IRI and sends a Basic-authenticated POST. Two overloads: one using the configured `LocalCredentials`, one with explicit `ProxyCredentials`.

- **`IActorSessionAccessor.LocalModeration`** (new property): lazily creates and caches an `ILocalModerationClient` bound to the signed-in user's actor, so Blazor components can access the local moderation client.

### UI: `CommunityDetail.razor`

- **Members tab:** the `MemberTemplate` (converted from a field to a property to allow instance-member references) now shows a "Remove" button next to each member row when:
  - The current user is the community's creator (`IsCreator`).
  - The member is not the current user themselves.
- **`RemoveMemberAsync` method:** calls `Session.LocalModeration.RemoveCommunityMemberAsync`, invalidates the membership cache on success, and refreshes the member count. Shows an error message on failure.
- **State:** `IsRemovingMember` (disables the button during the request) and `MemberRemoveError` (shows the error message).

### Tests: `CommunityMemberRemovalIntegrationTests`

Five new integration tests in `tests/Iris.Server.Tests/CommunityMemberRemovalIntegrationTests.cs`:

1. **`RemoveMember_Creator_RemovesMember`** — creates a community, adds a member, the creator removes the member via the local endpoint → 204, member gone.
2. **`RemoveMember_NonCreator_ReturnsForbidden`** — a non-creator's credentials → 403, member still present.
3. **`RemoveMember_NonMember_ReturnsNotFound`** — removing a non-member → 404.
4. **`RemoveMember_NonExistentCommunity_ReturnsNotFound`** — removing from a non-existent community → 404.
5. **`RemoveMember_NoAuth_ReturnsForbidden`** — no auth header → 403.
