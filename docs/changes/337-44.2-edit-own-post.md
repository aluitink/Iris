# 44.2 — Edit own post

**Status:** COMPLETE
**Commit:** `086e3cc`
**Tests:** 5 new integration tests (full suite: 1615 passing)

## What

A user can edit a note they previously authored. The object-detail page gains an **Edit**
button (visible only on the signed-in user's own posts, beside the existing **Delete**). It
enters an inline edit mode pre-filled with the note's current content (HTML stripped to plain
text). **Save** posts the change back through the ActivityPub pipeline; a later read of the
note serves the new content, and the change is federated to remote followers.

This is the F-02 "edit own post" feature. The server half (`UpdateActivityHandler`) and the
actor-profile half (`UpdateActorAsync`) already existed from earlier slices; this slice adds the
**note-edit client method** and the **UI**.

## Changes

### `src/Iris.Client/IActivityPubClient.cs` / `ActivityPubClient.cs`

- New `UpdateNoteAsync(Iri actorId, Note updatedNote, CancellationToken ct = default)`: builds an
  ActivityStreams `Update` (actor + embedded note) and delivers it through the signed outbox
  pipeline to `actorId.OutboxOf()`. The embedded note's `id` is the note's IRI (learned when it was
  posted) — the server matches on it, and a mismatch is a no-op. The server's `UpdateActivityHandler`
  refreshes the stored object in place (a later `GET` of the note's IRI serves the new content) and
  propagates the update to the author's remote followers (the federated half of F-02). Only the
  author may edit: the server rejects an update from an actor that is not the stored note's
  `attributedTo` (owner guard).

### `apps/Iris.Web/Components/Pages/ObjectDetail.razor`

- **Edit** button in the action row, rendered only when `IsOwnPost` (the same gate as **Delete**),
  and only when not already in edit mode.
- `BeginEditAsync()` enters edit mode, pre-filling `EditContent` with the note's content (HTML tags
  stripped so the user edits plain text).
- `SaveEditAsync()` builds an updated `Note` (same IRI, `attributedTo`, and `to` — only `content`
  changes) and posts it via `client.UpdateNoteAsync`. On success the page re-fetches the note to
  render the server's refreshed copy and exits edit mode; on failure an error is shown.
- The object body swaps between the read-only `ObjectView` and the inline editor (`IsEdit`).

### `apps/Iris.Web/wwwroot/css/app.css`

- `.object-edit` (column layout), `.object-edit label`, `.object-edit .compose-content`, and
  `.object-edit-actions` for the inline editor.

### `tests/Iris.Web.Tests/EditOwnPostIntegrationTests.cs` (new)

5 integration tests booting the real app in-process via `WebAppFactory` + `TestServer`:

1. `UpdateNote_RefreshesStoredContent` — post a note, `UpdateNoteAsync` with new content; assert the
   stored object's content is the new text and no longer the original.
2. `UpdateNote_PreservesSensitiveAndSummary` — post a sensitive note with a summary, edit the
   content while carrying `sensitive` + `summary`; assert both survive on the stored object.
3. `UpdateNote_NotAuthor_IsNoOp` — a second, distinct actor attempts to edit the note; the server's
   owner guard rejects it, so the stored content is unchanged.
4. `UpdateNote_ServesUpdatedContentOnGet` — after an edit, a fresh `GetObjectAsync` of the note's
   IRI serves the updated content (the path the object-detail page uses).
5. `UpdateNote_UpdatesPublishedNoteTwice` — two successive edits; the second wins.

The `FindCreatedNoteAsync` helper scans the actor's outbox for a `Create` **or** `Update` whose
embedded object's content contains a fragment (after an edit the outbox holds the `Update`), resolves
the object IRI, and reads the stored object back via
`IPersistenceProvider.Objects.TryGetObjectAsync`. `SeedRemoteActorAsync` seeds a fresh local actor
(key pair in **both** the persistence and DI key stores, registered with the DI `IKeyProvider`, plus
a `Person` document with a `publicKey` `ExtensionData`) so a second signed client can act as a
non-author. A `LocalActorDocumentFetcher` inner class is registered as `IActorDocumentFetcher` so the
server can verify signatures without a round-trip HTTP fetch.

## Design notes

- The edit is an **`Update` activity**, not a new `Create`: the note keeps its IRI (links to it —
  replies, boosts, the object URL — remain valid) and the `updated` timestamp is what consumers use
  to detect the change. The `Update` carries the full updated note (not a diff), matching the
  ActivityPub convention and the existing `UpdateActivityHandler`.
- `SaveEditAsync` carries the original note's `attributedTo` and `to` unchanged so the server's owner
  guard passes and the audience is preserved; only the content changes.
- The server's `UpdateActivityHandler` already existed (it handles both actor-profile and note-object
  updates); this slice only adds the note-edit client method + UI, so no server change was needed.
