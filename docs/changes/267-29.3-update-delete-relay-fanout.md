## What changed

### Per-class details

- **UpdateDeleteRelayFanOut** (3): The tests sign a `Create`/`Update`/`Delete` request as bob and POST it
  to B's outbox (`/ap/v1/u/bob/outbox`); B's server records the activity, routes `Update`/`Delete` to
  `UpdateActivityHandler`/`DeleteActivityHandler` (which fan out to the relay via F-06), and delivers to
  R's inbox. R validates the signature against bob's actor document (fetched from B) and applies the
  Update (refreshing its stored Note) or Delete (tombstoning its stored Note). The fixture seeds bob +
  relay with keys ONCE; B's identity + `RoutingFetcher` (routes by host IRI to B or R) + `DeliveryTransport`
  to R; R's fetcher reaches B (lazily, via `LazyHandler`). The bob→relay subscription edge is recorded in
  B's relay store in `SeedForFixture`.

### Test breakdown

1. `OutboxPublish_Update_IsFannedOutToRelay` — Create then Update; R refreshes its stored Note
2. `OutboxPublish_Delete_IsFannedOutToRelay` — Create then Delete; R tombstones its stored Note
3. `OutboxPublish_Update_WithNoSubscribedRelays_IsNotFannedOut` — carol (no relay) Update not fanned out

### Notes

- The `RoutingFetcher` is a nested `internal sealed class` in the test class (no namespace collision
  with other `RoutingFetcher` nested classes in other test files).
- The third test seeds a fresh `carol` on B (a non-subscriber) via `TestSeeder.SeedPersonWithKey` and
  asserts the relay stored nothing for carol.
