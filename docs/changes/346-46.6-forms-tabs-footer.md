# 46.6 — Forms + tabs + footer

## Scope

Address P2-8 (tab style), P3-9 (footer links), P3-11 (search description) from the 46.1 design audit. P3-13 (compose tips) was already completed in 46.5.

## Changes

### app.css (client + server-side copy)

- **P2-8 Tab style**: Converted `.tab-bar` from an underline-based design to a pill/segmented-control style. The bar now has a `--surface` background with 8px border-radius and 3px padding. Each `.tab` has 6px border-radius, 0.9rem font-size, and a hover state with `--bg` background. The active tab (`.tab--active`) has `--bg` background + `font-weight: 500` for a subtle elevation. This applies to all tab bars: Profile, Actor Detail, Community Detail, Settings.

### Search.razor

- **P3-11 Search description**: Replaced the developer-facing jargon ("the server's `GET /ap/v1/search`, F-13") with plain English: "Search across the instance for people and posts."

### MainLayout.razor

- **P3-9 Footer links**: Added WebFinger (`/ap/v1/webfinger?resource=acct:admin@iris.luit.ink`) and Status (`/ap/v1/health`) links alongside the existing NodeInfo link.

### Dockerfile

- **WASM build fix**: The `BuildAndCopyClient` MSBuild target in `Iris.Web.csproj` was not reliably building `Iris.Web.Client` during `dotnet publish` inside Docker (the incremental build condition `!Exists(...)` was not triggering a rebuild). Fixed by explicitly running `dotnet build apps/Iris.Web.Client/Iris.Web.Client.csproj -c Release` before `dotnet publish` in the Dockerfile. Without this fix, the container served a stale WASM binary and source changes to Razor components were not reflected in the running app.

## Design decisions

- **Pill tabs over underline tabs**: The segmented-control style provides a stronger visual affordance for the active state (background fill vs. a 2px underline). The `--surface` background on the bar creates a contained "group" feel that distinguishes tabs from the page content. The 3px padding + 6px border-radius on tabs gives a soft, modern look without being overly rounded.
- **Footer links are instance-identity links**: NodeInfo, WebFinger, and Status are all machine-readable endpoints that identify the instance. They serve as a lightweight "about" section without requiring a dedicated About page. No user counts or post stats (would require a new endpoint or a DB query on every page load).

## Verification

- Build clean, all tests green (951 server + 63 web + 32 sample + other suites, 0 failures).
- Docker rebuilt with the Dockerfile fix; WASM now includes all source changes.
- Playwright at 1280×800 + 375×812: profile tab bar shows pill style; search description is plain English; footer shows NodeInfo + WebFinger + Status. Zero console errors.
