## Wire observations

- The log-on used the dial-base resolution from change 205: address `alice@localhost` with an **empty**
  base URL → the map derived `http://localhost:8081`; the actor IRI carried the advertised FQDN
  (`https://iris-dev1.luit.ink/ap/v1/u/alice`); the "Dialing" line confirmed `http://localhost:8081/`.
- The **only** console errors across the pass were the pre-existing **429 (Too Many Requests)** on the
  external-FQDN proxy route (`/ap/v1/proxy/https://iris-dev1.luit.ink/…`) — the documented
  external-FQDN reverse-proxy blocker (the FQDN does not resolve from the browser in this env). These
  are not new and do not affect the local dial-base route.
- The Object page's "Object not found: …" error state is the same 429 proxy route surfacing as a
  consistent error (the object IRI carries the FQDN, which the proxy cannot reach in this env).
