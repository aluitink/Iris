# 54.9 — Possible duplicate home-feed fetch

Phase 54 slice. A Playwright session observed what looked like two calls to the
feed endpoint on first `/home` load. The slice description hypothesized a Blazor
Web App **prerender + WASM circuit double-mount**.

## Investigation

`Iris.Web.Client` is a **pure Blazor WebAssembly** app (`WebAssemblyHostBuilder`,
`builder.RootComponents.Add<App>("#app")`) — there is **no server-side
prerendering**. So the "prerender + circuit" hypothesis is **ruled out**: the
entire UI renders client-side after the WASM boots, and `/home` is not SSR'd.

Tracing the only feed consumer on `/home` (`HomeTimeline` → one `PagedCollection`),
the code as written predicts a **single** feed fetch: `OnParametersSet` fires the
initial load once per distinct `CollectionIri` (gated by the `_loadedFor`
tracker), and `Client` (the session's signed ActivityPub client) is built once
and cached, so it does not flicker.

However, the guard had a real flaw that *could* produce a duplicate under a
transient re-render:

- `OnParametersSet` reset `_loadedFor = null` **whenever `Client` was null**.
- The initial load is dispatched **fire-and-forget** (`_ = LoadInitialAsync()`)
  with no in-flight guard.
- So if `Client` dipped to `null` on any re-render between the dispatch and the
  fetch's completion (a transient re-auth flicker, a cascading parent re-render
  re-supplying parameters, or a session-expiry/refresh), `_loadedFor` reset to
  `null`, and the next render re-fired `LoadInitialAsync` for the **same**
  collection — a second `GET /feed` while (or after) the first was still in
  flight.

The reset was also **redundant** for the normal path: the initial load already
fires when `Client` first becomes available with a non-null `CollectionIri`,
because `_loadedFor` is still `null` at that point and `iri != null`.

## Fix

`PagedCollection.razor` — two changes:

1. **Removed the harmful reset.** When `Client is null`, `OnParametersSet` no
   longer resets `_loadedFor`. A transient null-`Client` no longer re-arms the
   initial load.
2. **Added an in-flight guard.** A new `_loadingInitial` flag is set when the
   initial load is dispatched and cleared in `LoadInitialAsync`'s `finally`.
   `OnParametersSet` fires the load only when
   `iri != _loadedFor && !_loadingInitial`, so a concurrent second dispatch for
   the same collection is impossible. The `finally` also clears on error so a
   failed load can be retried, and a *genuinely new* collection (a different
   `CollectionIri`) still triggers its own initial load once the in-flight one
   completes.

Net effect: exactly one initial `GET /feed` per distinct collection, regardless
of how many times `Client` or the parameters re-render during the load.
