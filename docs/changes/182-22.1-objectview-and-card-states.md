# 182 — Phase 22.1: `ObjectView` updated timestamp (US-19) + object-page raw inspector + consistent card loading (US-23)

## Summary

Closes the final two 22.1 sub-slices — the `ObjectView` deep-dive (US-19) and the card
loading/empty/error pattern (US-23) — so the "shared components first" item is complete. This is the
last sub-slice before Phase 22.2 (detail pages built on the shared components).

- **US-19 — `ObjectView` now shows `published`/`updated`.** A new `IriExtensions.GetUpdated()` boundary
  read exposes the ActivityStreams `updated` term (when the content was last edited). `ObjectView`
  renders an `updated {time}` line next to the published time when present, so an edited post is
  distinguishable from a fresh one at a glance on **every** collection card and detail page (the
  component is reused everywhere, so the improvement lands app-wide).
- **US-21 follow-through on the object page.** `ObjectPage` gains a `RawInspector` card (the raw
  ActivityStreams/ActivityPub JSON of the loaded object), matching the escape hatch already on
  `ActorDetail`. US-21 asked for the inspector on *every* detail page (actor, community, object,
  instance); object is the gap this slice fills.
- **US-23 — consistent card loading state.** A shared `.card-loading` spinner (a compact rotating arc +
  a `Loading…` label) replaces the bare `Loading…` text in `PagedCollection` (first-page fetch and
  "Load more" in flight) and `ObjectPage` (load). A fetching card now never renders blank.

This is the 22.1 "shared components first" working order, following the identity-bar / back-links
sub-slice (change 181).

  - New `public static DateTime? GetUpdated(this IObject? obj)` — returns `obj?.Updated` (the AS
    `updated` term), `null`-safe. Follows the existing read style (the sibling `GetPublished`-shaped
    reads in this file: `GetSummary`, `IsSensitive`, `GetParentIri`, etc.).

- **`samples/SampleBlazorClient/Pages/ObjectPage.razor`**
  - Adds a `<RawInspector Document="ObjectDoc" Title="Raw inspector" />` card between the object card
    and the replies card.
  - The `Busy` (load-in-flight) state now uses the shared `.card-loading .card-loading-inline` spinner
    instead of a bare `Loading…` span.

- **`samples/SampleBlazorClient/Components/PagedCollection.razor`**
  - The initial-load state (`Items is null`) and the "Load more" in-flight state (`LoadingMore`) both
    now render the shared `.card-loading` spinner instead of a bare `Loading…` span.

- **`samples/SampleBlazorClient/wwwroot/css/app.css`**
  - `.object-updated` (muted italic, slightly smaller than the published line).
  - The `.loading-spinner` arc styling is split: the size stays on the `.loading-spinner` element and a
    new `.loading-spinner-circle` carries the rotation animation + stroke (so the same SVG can be sized

- **`tests/Iris.Core.Tests/Identity/IriExtensionsTests.cs`**
  - Three tests for `GetUpdated`: present (returns it), absent (null), null receiver (null).

## Key types / API

- `IriExtensions.GetUpdated(this IObject?)` — the new boundary read. `Id`/IRI terms are handled
  elsewhere in this file; `updated` is a plain `DateTime?` on `IObject`, so the read is a one-liner
  (no IRI parsing). The renderer converts to local time, exactly as it does for `published`.
- The card-loading spinner is pure markup + CSS (no new component, no new state) — the three call
  sites inline the same small SVG, sized by the surrounding `.card-loading` class.

## Decisions

- **Like/boost counts — no new field.** US-19 lists "like/boost counts" as an `ObjectView`
  responsibility, but the ActivityStreams library (v0.2.4) exposes **no** like/boost *count* property
  — only the `Likes` / `Shares` *collections* (`Collection`). Counting those collections belongs at the
  page edge (where the client + the loaded object are in scope), not inside the pure renderer. The
  counts are already rendered on `ObjectPage` (decision 056(d)); no static field is added to
  `ObjectView`. The renderer stays a pure function of the object document.
- **`updated` is a plain read, not an IRI transform.** Unlike `GetParentIri` / `GetMentionIris` (which
  map `string?` IRI fields to the Iris `Iri` type at the boundary), `updated` is a `DateTime?` on
  `IObject`, so `GetUpdated` simply returns it. The local-time formatting happens in the renderer,
  mirroring the existing `published` handling.
- **Card spinner is shared markup, not a component.** The loading indicator is a ~4-line SVG repeated
  at the three call sites and sized by the `.card-loading` class. Extracting it into a component would
  add a component + DI surface for a static, stateless fragment; the inline markup keeps the change
  minimal and the `PagedCollection` / `ObjectPage` call sites self-contained. (A shared `CardState`
  component remains a candidate for 22.2 if the empty/error branches diverge.)
