## Console-error triage (no new gaps)

The only console errors across the pass are, each accounted for:

- **`favicon.ico` 404** — cosmetic (the static host serves no favicon).
- **`/ap/v1/u/alice/inbox` 403** (direct + via the same-origin home proxy) — **by-design**: the inbox is
  owner-only; on a plain session the client treats the 403 as an *empty* collection, so the Inbox
  `PagedCollection` shows its "No activities delivered." empty state (no error card, no broken UI). This
  is the expected behavior confirmed by change 191.
- **`https://iris.luit.ink/…` CORS failures** — the **external reverse-proxy FQDN** (the public
  `iris.luit.ink` route). Unreachable from this environment (the reverse proxy is not reachable here);
  the `InstanceBaseUrls` map correctly overrode it to the local `8081` base for the session, so these
  are the unreachable external-FQDN route, not a regression.

No error introduced by the slice-4 (Actor mutes/blocks/flags) or prior 22.6 consolidations; all four
`PagedCollection` consolidations (changes 191–194) render correctly in the full explorer context.
