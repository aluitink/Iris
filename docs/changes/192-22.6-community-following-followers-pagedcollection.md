# 192 — 22.6 Implementation sweep: consolidate Community following/followers onto `PagedCollection`

**Phase 22.6** (implementation sweep + manual test pass), second slice.

## What changed

The **Community** page's read-only **Following** and **Followers** cards (19.8.4) were hand-rolling the
load / empty / error / "Load more" / next-link-walking logic the shared
[`PagedCollection`](../../samples/SampleBlazorClient/Components/PagedCollection.razor) component
already implements. This slice consolidates both cards onto that component.

- `samples/SampleBlazorClient/Pages/Community.razor`
  - The two `<div class="card">` blocks (their `FollowingItems`/`FollowersItems` / `*HasMore` /
    `*LoadingMore` / `*Error` state, their loading/empty/error markup, their `Load more` buttons) are
    replaced by two `<PagedCollection … ItemTemplate="@ActorLinkTemplate" />` components (driven by
    `communityIri.FollowingOf()` / `communityIri.FollowersOf()`).
  - The `CommunityIri is not null` guard becomes `CommunityIri is { } communityIri` (a non-null local)
    so the `CollectionIri` attributes can call `communityIri.FollowingOf()` / `.FollowersOf()`.
  - A new `private static RenderFragment<IObjectOrLink> ActorLinkTemplate` field renders each entry as a
    link to that actor's detail page (`/actor?iri=…`, `title` = the IRI, text = the short
    `HandleOf` handle), or a `<code>` relay-IRI fallback when the entry has no resolvable IRI. One
    template serves both cards (they share the same item shape).
  - Removed: the `FollowersItems`/`FollowingItems`/`FollowersHasMore`/`FollowingHasMore`/
    `FollowersLoadingMore`/`FollowingLoadingMore`/`FollowersError`/`FollowingError` fields, the
    `_followersResumeFrom`/`_followingResumeFrom` cursors, the reset lines, the initial-load calls in
    `LoadAsync`, and the six methods (`LoadInitial{Followers,Following}Async` / `LoadMore{…}Async` /
    `EnumerateOne{…}PageAsync`).

## Note

`HandleOf(string)` and `RelayIriOf(IObjectOrLink)` are **kept** — they are still used by the Inbound
follows, Members, and Search cards (and now by `ActorLinkTemplate`). Only the following/followers state
and methods were removed. This is the **second** application of the field-based `RenderFragment<T>`
`ItemTemplate` pattern established in change [191](191-22.6-inbox-pagedcollection-consolidation.md)
(the inline lambda attribute form is unreliable on net10.0 Razor).

## Behavior parity

Both cards' states (loading spinner, empty "Not following anyone." / "No followers recorded.", error,
Load more) now come from `PagedCollection`, identical to the Outbox/Inbox/Liked cards. The item markup
(href/title/text) is byte-for-byte the same as the previous hand-rolled `<li>` markup.
