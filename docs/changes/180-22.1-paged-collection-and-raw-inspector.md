# 180 — Phase 22.1: shared `PagedCollection` + `RawInspector` components

## Summary

Adds the two shared building blocks for the Phase 22 functional-explorer rebuild and refactors the
first two consumer pages onto them:

- **`PagedCollection`** (US-20) — a reusable next-link-walking paged-collection card: first page on
  load, one server page per "Load more" click, with consistent loading / error / empty / list states
  and a pluggable item template (default `<ObjectView Item=…/>`).
- **`RawInspector`** (US-21) — a "Show / Hide raw JSON" card that lazily serializes the loaded
  document only when first expanded — the explicit AP-native escape hatch.

`Feed` (the home timeline) and `ActorDetail` (the Outbox card + the Raw inspector card) now render
through these components instead of hand-rolled paging state.

This is the first vertical slice of Phase 22's "shared components first" working order (22.0). The
remaining paged cards (ActorDetail followers/following/inbox/moderation, Community feed/members/
follows/moderation, etc.) are deferred to later 22.x slices, which will swap each onto
`PagedCollection` one at a time.

## What changed (code)

- **`samples/SampleBlazorClient/Components/PagedCollection.razor`** (new)
  - Params: `Client` (`IActivityPubClient?`), `CollectionIri` (`Iri?`), `Title`, `Description`,
    `HeaderContent` (`RenderFragment?`), `PageSize` (`int?` → `CollectionQuery.Limit`), `BypassCache`
    (`bool` → `CollectionQuery.BypassCache`, the `?refresh=true` path), `ItemTemplate`
    (`RenderFragment<IObjectOrLink>?`), `EmptyMessage`.
  - Loads the first page in `OnParametersSet` when `Client`/`CollectionIri` are present and the IRI
    differs from the last-loaded IRI (so a new actor/community re-loads). "Load more" fetches exactly
    one page per click by resuming `GetCollectionAsync` from the stored next-page IRI and taking the
    first yielded page (`break`), so each click is one server round-trip.
  - Renders: title/description/header, an error line, `Loading…` until the first page lands, the
    empty message when there are no items and no next page, the item list (each item via
    `ItemTemplate` or the default `<ObjectView Item=…/>`), and the "Load more" button when a next
    page exists (disabled while loading the next page).

- **`samples/SampleBlazorClient/Components/RawInspector.razor`** (new)
  - Params: `Document` (`object?` — the deserialized `IObject`/`Actor`/`Group`/…), `Title`
    (defaults to "Raw inspector"), `Description` (defaults to the "as served … escape hatch" line).
  - Owns the `ShowRaw` toggle. Serializes lazily (only on first expand) with
    `JsonSerializerOptions { WriteIndented = true, Encoder = UnsafeRelaxedJsonEscaping }` — the same
    options the inline per-card code used, so the rendered JSON is identical. Collapses and drops the
    cached JSON when `Document` goes null (a reload/new actor).

- **`samples/SampleBlazorClient/Pages/Feed.razor`**
  - The home timeline now renders through `<PagedCollection Client=… CollectionIri=… PageSize="5"
    EmptyMessage=… />`. `FeedClient` / `FeedIri` are computed properties (the session's client + the
    actor's `{actor}/feed` IRI). The hand-rolled feed paging state is removed.

- **`samples/SampleBlazorClient/Pages/ActorDetail.razor`**
  - The **Outbox** card renders through `<PagedCollection Client="@Session.GetClient()"
    CollectionIri="@(ActorIri?.OutboxOf())" …/>`.
  - The **Raw inspector** card renders through `<RawInspector Document="ActorDoc" />`.
  - Removed: the outbox item/next-page state fields, the `ShowRaw`/`RawJson` fields, and the
    outbox `LoadMore*`/`Enumerate*PageAsync`/raw-JSON methods. `@ActorIri.Value` usages made null-safe
    (`@(ActorIri?.Value)`).

- **`samples/SampleBlazorClient/wwwroot/css/app.css`**
  - `pre.raw-json` styling (dark code block, capped height, scroll, `white-space: pre-wrap`).

- **Formatting:** `dotnet format` applied to the tree — pre-existing whitespace/final-newline
  violations only (non-semantic), across `src/` and `tests/` (43 files). The tree is now
  `dotnet format --verify-no-changes` clean. No logic changed by the format pass.

## Key types / API

- `IActivityPubClient.GetCollectionAsync(Iri, CollectionQuery?, CancellationToken)` — the paged
  collection read. Yields one `CollectionPage` per server page, walking `next`; each page exposes
  `Items`, `IsLastPage`, and `NextPage`. `PagedCollection` takes one page per click and resumes from
  `NextPage`.
- `CollectionQuery(Limit, BypassCache)` — the per-page limit and the `?refresh=true` cache bypass.
- `Iri.OutboxOf()` — the outbox-IRI derivation (generic segment append, works for `/u/{handle}` and
  `/c/{name}`).
- `ExplorerSession.GetClient()` / `ResolvedActorIri` / `IsLoggedIn` — the session seams the pages use
  to gate on a logged-on identity and dial the active instance.

## Scope / limits

- Only **two consumer pages** are on the new components in this slice: `Feed` and `ActorDetail`
  (Outbox + Raw inspector). The other paged cards remain hand-rolled (the 22.2+ slices will swap each
  onto `PagedCollection` in turn: ActorDetail followers/following/inbox/moderation-collections,
  Community feed/members/follows/moderation-collections, search).
- `PagedCollection`'s **"Load more"** is wired (one server page per click, resume from `NextPage`)
  but was not exercised by a multi-page local collection in this pass — every seeded local collection
  is a single page (≤10 items: alice outbox = 10, bob outbox = 4, feed = 6). The multi-page path is
  covered by the existing `GetCollectionAsync` integration tests; it will be visually confirmed on a
  page that has a `PageSize` smaller than a populated collection (e.g. the Community feed, 14 items,
  once it moves to `PagedCollection` in 22.2).
- **No new NuGet packages.** The components use only `Iris.Client`, `Iris.Core`, the
  `KristofferStrube.ActivityStreams` types, and `System.Text.Json`.
