# 35.2 + 35.3 — Relative timestamps verified + Home timeline content filter

**Phase 35 — Timeline actions & content completeness**

## 35.2: Timeline cards — show relative timestamps (verification)

Verified as part of 35.1's implementation: new posts display "just now" (or "2m ago", "1h ago", etc.) in `<time class="object-time">` elements with the full ISO 8601 timestamp in the `title` attribute. The `ObjectView` component's existing `RelativeTime` helper handles the formatting. No additional code needed.

Note: posts created before 35.1 do not have `published` set (no migration performed), so they show no timestamp. This is acceptable — the data simply wasn't recorded.

## 35.3: Home timeline — filter to content-only items

### What changed

- `PagedCollection.razor`: new optional `ItemFilter` parameter (`Func<IObjectOrLink, bool>?`). When set, items that don't pass the predicate are excluded from rendering. Pagination is unaffected (filtered items are still consumed from the page).
- `HomeTimeline.razor`: passes `ItemFilter="IsContentItem"` — a static method that returns true only for `Create` (with Note/Article embedded object), `Announce`, or bare `Note`/`Article` items. Social activities (Follow, Accept, Reject, Like, Move, Add, Remove, Flag, Mute, Undo, Update, Delete) are excluded.

### Decision

Filter in the UI layer, not the server. The server's `/feed` endpoint continues to return all activity types (it's a general-purpose API; other clients may want the full feed). The web UI applies the content-only filter at render time. This keeps the server API flexible and the filter simple (a Blazor predicate, no extra HTTP round-trip or query parameter).
