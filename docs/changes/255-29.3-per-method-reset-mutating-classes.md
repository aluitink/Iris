## What was built

The 29.3 slice (doc 254) added the `SharedHostFixture` (build-the-host-once per xunit collection) and converted the two cleanest **read-only** single-instance classes. The **mutating** classes (those whose methods write to persistence and assert on absolute counts) could not share a host because they needed a **per-method persistence reset** that didn't exist. This slice adds that missing piece and converts 3 RISKY single-instance classes.

Each store in `Iris.Server.InMemory/Stores/` gains a `Clear()` method that empties its internal `ConcurrentDictionary` (or nested dicts):

|---|---|
| `InMemoryActivityStore` | `_activities`, `_outboxes`, `_inboxes` |
| `InMemoryActorStore` | `_actors` |
| `InMemoryAnnounceStore` | `_announced`, `_announcedBy` |
| `InMemoryCommunityStore` | `_communities`, `_members`, `_follows`, `_followers`, `_blocks`, `_flags`, `_mutes`, `_joinRequests` |
| `InMemoryCreateIndex` | `_creates` |
| `InMemoryFollowStore` | `_followers`, `_following` |
| `InMemoryLikeStore` | `_liked`, `_likedBy` |
| `InMemoryMediaStore` | `_media`, `_urlToMediaId`, `_hashToMediaId` |

| `InMemoryObjectStore` | `_objects` |
| `InMemoryRelayStore` | `_relays` |
| `InMemoryReplyStore` | `_replies` |

The `InMemoryKeyStore` (in `Iris.Core/Identity/`) already has a `Dispose()` that clears + disposes keys. It is **not** cleared by the reset (see below).

### 2. `InMemoryPersistenceProvider.Reset()`

A new `Reset()` method on the provider that calls `Clear()` on all 12 data stores. The **key store is left intact** — the host's signing infrastructure (the local actor's signing key) is bound to the key store at construction, and disposing/clearing it would break the host's ability to sign outbound deliveries.

### 3. `Clear()` on the cache chain

The `LocalCollectionPageCache` (the server's response cache for paged collection endpoints, 60s TTL) was **leaking between methods** on a shared host: a method that GETs `/followers` (empty) caches the empty page; the next method resets the store + adds 2 followers, but the GET returns the **cached** empty page (the cache entry is still valid within the TTL). This was the root cause of the first conversion failure.

Added `Clear()` up the chain:
- `MemoryCache<TValue>` — clears `_list` + `_lru`, sets `Count = 0` (under the lock).
- `CachingReadThrough<TValue>` — delegates to `MemoryCache<TValue>.Clear()` (casts; the `ICache<TValue>` interface has no `Clear`).
- `LocalCollectionPageCache` — delegates to `CachingReadThrough<TValue>.Clear()`.

### 4. `SharedHostFixture.Reset()`

A new `Reset()` method on the fixture that:
1. Calls `InMemoryPersistenceProvider.Reset()` (clears all data stores, leaves the key store intact).
2. Calls `LocalCollectionPageCache.Clear()` (resolved from the server's DI container at construction; clears the response cache).

This is the single call a mutating test class makes in `IAsyncLifetime.InitializeAsync` to get a clean slate before each method.

### 5. Three RISKY single-instance classes converted

Each converted class now:
- Is annotated `[Collection("<name>")]` and takes the fixture in its constructor.
- Implements `IAsyncLifetime`: `InitializeAsync` calls `_fixture.Reset()` + `SeedForFixture(persistence)` (reset + reseed before each method); `DisposeAsync` disposes the `HttpClient`.
- Exposes an `internal static SeedForFixture(InMemoryPersistenceProvider)` for the fixture's initial seed + the per-method reseed.

| Class | Methods | Collection | Notable |
|---|---|---|---|
| `CommunityEndpointIntegrationTests` | 11 | `CommunityEndpoint` | Community endpoints (document, members, followers, following, inbox auth) |
| `ObjectEndpointIntegrationTests` | 11 | `ObjectEndpoint` | Object document endpoint (stored/updated/tombstoned objects) |
| `CommunityModerationIntegrationTests` | 12 | `CommunityModeration` | Community moderation (blocks/flags/mutes collections, Basic-auth mute endpoint, feed exclusion). The fixture also sets the `CredentialValidator` (Basic auth for the community operator) at construction. |

## Key design decisions

1. **Key store is not cleared by `Reset()`.** The host's signing infrastructure is bound to the key store at construction. Clearing it would dispose the signing keys, breaking the host's ability to sign outbound deliveries. The key store is left intact; only the data stores are cleared.

2. **The collection-page response cache must be cleared alongside persistence.** The `LocalCollectionPageCache` is a DI singleton on the shared host with a 60s TTL. When tests share a host, a cached response from one method is still valid (within the TTL) when the next method runs, even after the underlying store is reset. Clearing the cache in `Reset()` ensures each method sees fresh data.

3. **`Clear()` on `MemoryCache<TValue>` is under the lock.** The `_list` and `_lru` fields are guarded by `_gate`; `Clear()` acquires the lock to avoid a race with concurrent reads/writes.

4. **`CachingReadThrough<TValue>.Clear()` casts to `MemoryCache<TValue>`.** The `ICache<TValue>` interface has no `Clear()` method (adding it would be a breaking change for all implementers). The cast is safe in practice (the only `ICache<TValue>` implementation used in tests is `MemoryCache<TValue>`).

5. **Per-method reset + reseed via `IAsyncLifetime.InitializeAsync`.** The fixture is per-collection (constructed once), but `IAsyncLifetime.InitializeAsync` runs before each test method. The test class calls `_fixture.Reset()` (clears persistence + cache) then `SeedForFixture(persistence)` (re-seeds the baseline state) in `InitializeAsync`, giving each method a clean, freshly-seeded state while amortizing host construction across the collection.
