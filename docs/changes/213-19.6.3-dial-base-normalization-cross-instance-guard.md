# 213 — 19.6.3: dial-base normalization cross-instance guard

**Phase:** 19.6 (C2S invariants) / 19.6.3 (server-delivers, signature identity)

**Problem:** `NormalizeLocalActorObjectIriAsync` (the Docker-only-routable IRI
normalization on the outbox publish path) rewrote a Follow's `object` reference
to the local actor whenever the target's **handle** matched a local actor,
regardless of the target's **host**. A Follow of `alice@iris-dev2.luit.ink`
(handle `alice`, host `iris-dev2.luit.ink`) was rewritten to
`alice@iris-dev1.luit.ink` (handle `alice`, host `iris-dev1.luit.ink`) because
`alice` exists locally on iris-dev1. The recorded follow edge and the
federated activity both pointed at the wrong actor.

**Root cause:** The normalization extracted the handle from the target IRI's
path, built a candidate IRI using the local advertised base, checked that the
local actor existed, and rewrote. It never compared the target IRI's host to
the local base's host or the request's host.

**Fix:** The rewrite now applies only when the target IRI's host (port-stripped)
is one of:
- the advertised base's host (already canonical — the rewrite is a no-op),
- the request's host (the dial base the client used to reach this instance),
- a local-looking host (`localhost`, `127.0.0.1`).

A genuinely foreign public hostname (e.g. `iris-dev2.luit.ink` when this
instance is `iris-dev1.luit.ink`) is left untouched, even if the handle
matches a local actor.

**Files changed:**
- `src/Iris.Server/ActivityPubServerExtensions.cs` — `NormalizeLocalActorObjectIriAsync`
  gains a `requestHost` parameter and the host-match guard.
- `tests/Iris.Server.Tests/OutboxDialBaseIriNormalizationIntegrationTests.cs` —
  new regression test `OutboxPublish_Follow_RemoteTarget_SharedHandle_NotRewritten`
  pins the fix (4 tests total in the class, all green).

**Verification:** 1,301 tests green (811 Server, up from 810). Playwright MCP
manual pass confirmed the bug (Follow of iris-b's alice from iris-a's alice
recorded `object: iris-dev1.luit.ink/ap/v1/u/alice` instead of
`iris-dev2.luit.ink/ap/v1/u/alice`) before the fix; the fix is CI-pinned by
the new integration test.
