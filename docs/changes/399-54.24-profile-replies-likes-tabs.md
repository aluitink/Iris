# 54.24 — Profile "Replies" and "Likes" Tabs Don't Populate

## Problem

On the own-profile page, the **Replies** and **Likes** tabs rendered empty instead of the
actor's actual replies and liked posts. Both tabs were configured to read from the
actor's **Inbox** (`InboxClient` + `InboxIri`) instead of the **Outbox** (`OutboxClient`
+ `OutboxIri`).

- The **Inbox** contains activities *sent to* the actor (e.g. other people's replies to
  the actor's posts, other people's likes on the actor's posts). It never contains the
  actor's own `Create` activities (replies) or the actor's own `Like` activities.
- The **Outbox** contains all activities *posted by* the actor, including `Create`
  activities whose embedded `Note` has `inReplyTo` set (the actor's replies) and
  `Like` activities (the posts the actor liked).

Since the inbox never contains the actor's own activities, the `IsReply` filter
(`Create` with `inReplyTo` set) and the `IsLike` filter (`Like` type) matched nothing,
and both tabs showed their empty-state messages.

## Solution

In `Profile.razor`, changed the `PagedCollection` for both the **Replies** tab (line 77–85)
and the **Likes** tab (line 87–97) from:

```razor
Client="@InboxClient"
CollectionIri="@InboxIri"
```

to:

```razor
Client="@OutboxClient"
CollectionIri="@OutboxIri"
```

Also switched the `ItemTemplate` from `NotificationTemplate` (a `NotificationRow`, which
renders "verb + actor handle") to `PostTemplate` (an `ObjectView`, which renders the full
post: avatar, handle, timestamp, content, media, engagement bar). This is a better fit
for the "what you replied to / liked" context — the user sees the actual post content,
not just a "Liked alice" row.

The `IsReply` and `IsLike` filter methods were already correct — they filter the outbox
items by activity type and embedded-object properties. The bug was purely the wrong
collection IRI.
