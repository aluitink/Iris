# 42.2 — Person "manuallyApprovesFollowers" toggle

**Status:** COMPLETE
**Commit:** `c119412`
**Tests:** 5 new integration tests (full suite: 1225 passing)

## What

A "Require approval for follow requests" checkbox in the profile edit form. When enabled,
inbound Follow activities to the actor are NOT auto-accepted (no `Accept` activity is sent
to the follower); the operator must explicitly Accept or Reject. The flag is stored in the
actor's `ExtensionData` under the `manuallyApprovesFollowers` key and is echoed onto the
public actor document.

## Changes

### `apps/Iris.Web/Components/EditProfileForm.razor`

- New `InitialApproveFollowers` parameter (bool).
- New checkbox in the form: "Require approval for follow requests" with a muted
  description line.
- `OnSubmit` delegate signature changed from `Func<string, string, Task>` to
  `Func<string, string, bool, Task>` (name, summary, approveFollowers).

### `apps/Iris.Web/Components/Pages/Profile.razor`

- `StartEdit()` captures the current flag value into `_originalApproveFollowers`.
- `EditProfileForm` receives `InitialApproveFollowers` from
  `ActorObj?.GetManuallyApprovesFollowers() ?? false`.
- `SubmitEditAsync(string, string, bool)`: after `UpdateActorAsync` succeeds, if the
  flag value differs from `_originalApproveFollowers`, calls
  `client.SetManuallyApprovesFollowersAsync(actorId, approveFollowers)`. If that call
  fails, a save error is shown and the form stays open.

### `tests/Iris.Web.Tests/ProfileApproveFollowersToggleIntegrationTests.cs` (new)

5 integration tests booting the real app in-process via `WebAppFactory` + `TestServer`:

1. `FreshActor_GetManuallyApprovesFollowers_ReturnsNull` — a fresh actor has no flag.
2. `SetFlag_Enable_SetsFlagOnDocument` — `SetManuallyApprovesFollowersAsync(true)`
   round-trips; `GetManuallyApprovesFollowers()` returns `true`.
3. `SetFlag_Disable_ClearsFlagOnDocument` — enable then disable; flag is `null`
   (removed from ExtensionData).
4. `Flag_Set_AppearOnPublicActorDocument` — the flag is visible in the raw JSON of the
   public actor document (GET `/ap/v1/u/alice`).
5. `Flag_Clear_RemovedFromPublicActorDocument` — after clearing, the flag key is absent
   from the public document.

## Design notes

- The follow-gate behavior (no auto-Accept when the flag is set) is already tested at
  the server level in `PersonSettingsIntegrationTests.SetGate_ThenInboundFollow_SurfacesInOutbox_WithoutAutoAccept`.
  The integration tests here focus on the client-facing contract: the flag round-trips
  through the signed outbox pipeline and is visible on the public document (which is
  what the UI reads to render the checkbox state).
- The `DeliverFollowAsync` helper from the 42.1 community tests was not reused because
  the TestServer's outbound HTTP (used by the `DeliveryWorker` to send the `Accept`
  back to the follower) cannot reach the in-process TestServer; the follow-edge
  recording is identical in both flag states (the edge is always recorded — only the
  auto-Accept is suppressed), so inbox-based assertions are not reliable in this
  topology.
