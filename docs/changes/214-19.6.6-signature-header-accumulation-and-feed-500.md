# 214 — 19.6.6: signature header accumulation + feed 500 on actor-doc throw

**Phase:** 19.6 (C2S invariants) / 19.6.6 (cache bypass, signature correctness)

**Problem:** Two linked defects surfaced by growing signature headers on failing
feed requests:

1. **Signature header accumulation.** `SigningHandler.SendAsync` wrote
   `Date`/`X-Signature-Date`/`Signature` via `TryAddWithoutValidation` without
   first removing pre-existing values. A re-signed or re-dispatched request
   (a retry clone that copies all headers, a reused `HttpRequestMessage`)
   stacked the headers. The receiving peer's validator
   (`HttpSignatureValidator`) comma-joins all `Signature` headers into one
   string, so a second signature made the header malformed → `401`.

2. **Feed 500 on actor-doc fetch throw.**
   `FeedService.FetchRemoteOutboxAsync` called
   `IActorDocumentFetcher.GetActorAsync` **outside** its only `try/catch` (the
   outbox walk was guarded; the actor-doc fetch was not). The contract says
   "return null, do not throw" on fetch failure, but a transport error,
   timeout, or a `SigningHandler` `KeyNotFoundException` in the outbound
   actor-doc fetch still threw, propagating uncaught through the feed handler
   → `500` on the whole feed.

**Fix:**

- `SigningHandler.SendAsync` (`src/Iris.Client/Pipeline/SigningHandler.cs`):
  removes the three signature headers (`Date`, `X-Signature-Date`,
  `Signature`) before adding the fresh ones. This preserves the "exactly one
  `Signature` header" invariant the signing-handler tests assert via
  `.Single()`.
- `FeedService.FetchRemoteOutboxAsync`
  (`src/Iris.Server/Services/FeedService.cs`): the actor-doc fetch is now
  wrapped in a `try/catch` the same way the outbox walk already was. A broken
  remote actor-document contributes nothing; the feed falls back to the
  conventional `{actor}/outbox` IRI and still completes.

**Files changed:**
- `src/Iris.Client/Pipeline/SigningHandler.cs` — header removal before sign.
- `src/Iris.Server/Services/FeedService.cs` — actor-doc fetch guarded.
- `tests/Iris.Client.Tests/Pipeline/SigningHandlerTests.cs` — new regression
  test `ResignedRequest_DoesNotStackSignatureHeaders`.
- `tests/Iris.Server.Tests/Services/FeedServiceTests.cs` — new regression
  tests `Feed_RemoteFollow_DocumentFetchThrows_ContributesNothing_Not500` and
  `Feed_RemoteFollow_DocumentFetchThrows_NoOutbox_ContributesNothing` + a
  `ThrowingActorDocumentFetcher` stub.

**Verification:** 1,304 tests green (813 Server, up from 811; 148 Client, up
from 147).
