# Change 209 — 19.8.7: Error & empty states (live verification)

## What

A Playwright MCP pass to drive each error/empty state through the browser and confirm the rendered
message is clear. No new code or tests (verification-only slice, per Phase 22 rule 5).

| 5 | Proxy-fallback failure (unreachable `remote.example`) | Object | "TypeError: Failed to fetch" | PASS |

## Key findings

1. **All error states render clear, specific messages** — not raw stack dumps, not generic "error".
   The Object page 404 gap shows "Object not found: {IRI}"; the proxy-fallback failure shows
   "TypeError: Failed to fetch".
2. **All empty states render clear, actionable messages** — not generic "no items". The Feed page
   empty state tells the user what to do ("Follow an actor (Actor detail → Follow) to populate your
   timeline."); the collection empty states use a consistent pattern ("No {collection} recorded." or
   "No {collection}." or "Nothing {verb}.").
3. **The messages are consistent across pages** — the same pattern is used for similar states
   (e.g., "No mutes recorded." on both the Community and Actor detail pages).
4. **The only console errors** are:
   - 429 (Too Many Requests) on the external-FQDN proxy route (rate limiting — the documented
     external-FQDN reverse-proxy blocker).
   - 403 (Forbidden) on the owner-only inbox (by design, decision 056).
   - CORS errors on the unreachable `remote.example` seed host (expected in this env — the proxy's
     error response for an unresolvable upstream lacks CORS headers, but the UI renders a clear
     "TypeError: Failed to fetch" error state).

## Wire observations

- The Object page 404 gap was tested with a non-existent note IRI
  (`https://iris-dev1.luit.ink/ap/v1/u/alice/notes/nonexistent`). The server returned a 404, and the
  UI rendered "Object not found: {IRI}" (a clear, specific error message).
- The proxy-fallback failure was tested with an unreachable remote object IRI
  (`http://remote.example/ap/v1/u/carla/notes/1`). The proxy attempted to fetch from
  `remote.example` (unresolvable), the proxy's error response lacked CORS headers, and the browser
  reported "TypeError: Failed to fetch" — which the UI rendered as a clear error state.
