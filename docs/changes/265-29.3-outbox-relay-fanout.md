## What changed

### Per-class details

- **OutboxRelayFanOut** (3): The tests sign a `Create`/`Announce` request as alice and POST it to A's
  outbox (`/ap/v1/u/alice/outbox`); A's server (not the client) delivers the activity to the relay's inbox
  on B, signed as alice. B validates the signature against alice's actor document (fetched from A) and
  stores the activity. The fixture seeds alice + relay with keys ONCE; A's identity + `DelegatingFetcher`
  (fetches the relay's actor doc from B, all others from A) + `DeliveryTransport` to B; B's fetcher
  reaches A (lazily, via `LazyHandler`). The third test seeds a fresh `bob` on A (a non-subscriber) and
  asserts the activity is NOT recorded for bob (no relay subscription → no fan-out).

### Key resolution pattern

The alice key is resolved from A's key store in `InitializeAsync` (after `Reset()` + `SeedForFixture`):
```csharp
_aPersistence.Keys.TryGetKey(new Iri($"{aliceIri.Value}#key-1"), out var aliceKey);
_aliceKey = (KeyPair)aliceKey!;
```
This works because `Reset()` clears the 12 data stores but leaves the key store intact.
