# 51.2 — View own blocks/mutes/flags

**Phase 51, Slice 2: Moderation tab in Settings showing the user's own block/mute/flag lists with undo buttons.**

## What

A new "Moderation" tab on `/settings` lists the signed-in user's blocked, muted, and
reported (flagged) actors. Each list shows the actor's handle (linked to their profile)
and an undo button (Unblock / Unmute / Remove). The lists are loaded from the actor's
`blocks`/`mutes`/`flags` collections via `IActivityPubClient`.

For blocks and flags, the undo requires the server-minted activity IRI (the original
Block/Flag's ID, not the target actor's IRI). The tab reads the actor's outbox to build
a map of target → activity IRI, then passes the correct IRI to `UnblockAsync` /
`UnflagAsync`. For mutes, `ILocalModerationClient.UnmuteAsync` takes the target IRI
directly (no minted ID needed).

## Files changed

- `apps/Iris.Web.Client/Components/Pages/Settings.razor` — added Moderation tab with
  three sections (Blocked, Muted, Reported); `LoadModerationAsync` reads the three
  collections; `CollectActivityIrisAsync` reads the outbox to build target→activity
  maps; `UnblockAsync`/`UnmuteAsync`/`UnflagAsync` perform the undo and update the
  local list.

## Known issue (pre-existing, out of scope)

The local mute endpoint (`POST /local/v1/u/{handle}/mutes/{target}`) returns 400 for
URL-encoded target IRIs. Muting via the UI (EngagementBar/ModerationActions) works
because it uses `ILocalModerationClient.MuteAsync` which constructs the URL differently.
The Settings tab's Unmute button uses the same client path.
