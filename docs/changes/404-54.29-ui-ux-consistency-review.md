# 54.29 — General UI/UX consistency review

**Date:** 2026-09-09
**Branch:** `phase-32-production-app`

## Summary

Full visual/UX pass across all pages to find and fix inconsistencies accumulated slice-by-slice.

## Inconsistencies found and fixed

1. **Duplicate button CSS** — `button`/`.button` (padding `0.45rem 1rem`, font-size `0.9rem`) and `.btn` (padding `0.55rem 1.2rem`, font-size `0.95rem`) defined overlapping styles with different values. Pages used both interchangeably, causing subtle size differences. Fixed by consolidating `.btn` to match `button`/`.button` dimensions.

2. **Duplicate disabled states** — `button:disabled` used `opacity: 0.5; cursor: default` while `.btn:disabled` used `opacity: 0.6; cursor: not-allowed`. Fixed `.btn:disabled` to match.

3. **Login/Register pages had no card wrapper** — unlike every other page, the auth forms floated on the bare page background with no visual container. Fixed by wrapping both pages in `<div class="card auth-card">` with a `max-width: 28rem` constraint for a comfortable form width.

4. **Stat-card colors used wrong design tokens** — `.stat-value` used `var(--color-accent, #4a6cf7)` and `.stat-label` used `var(--color-muted, #6b7280)`, neither of which are defined in the `:root` design system. The fallback `#4a6cf7` was a different shade of blue than the app's actual accent `#5b8cff`. Fixed to use `var(--accent)` and `var(--muted)`.

## Files Changed

- `apps/Iris.Web/wwwroot/css/app.css` — consolidated `.btn` styles, fixed `.btn:disabled`, added `.auth-card`, fixed `.stat-value`/`.stat-label` colors.
- `apps/Iris.Web.Client/Components/Pages/Login.razor` — wrapped content in `.card.auth-card`.
- `apps/Iris.Web.Client/Components/Pages/Register.razor` — wrapped content in `.card.auth-card`.

## Design decisions

- Kept `.btn` as a class alias rather than removing it (many pages reference it; removing would be a large mechanical change with no visual benefit).
- Used `max-width: 28rem` for the auth card (conventional form width; matches the visual density of the existing `.card` padding).
- Left the notifications page description paragraph in place — it provides genuinely useful context that other pages don't need.
