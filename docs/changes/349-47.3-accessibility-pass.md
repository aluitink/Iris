# 47.3 — Accessibility pass

Audited and fixed high-impact accessibility issues: ARIA labels on icon-only controls, decorative SVGs hidden from AT, keyboard navigation for interactive elements.

## Defects fixed

### 1. Icon-only buttons/links without accessible names

**Files:** `EngagementBar.razor`

**Before:** Like/Boost buttons and Reply link had only `title` attributes (unreliable for screen readers). The "More options" toggle was a `<div>` with no role, no tabindex, no keyboard handler.

**After:**
- Like button: `aria-label="Like"`, `aria-pressed="@_liked"`
- Boost button: `aria-label="Boost"`, `aria-pressed="@_boosted"`
- Reply link: `aria-label="Reply"`
- More options: `<div>` → `role="button"`, `tabindex="0"`, `aria-label="More options"`, `aria-expanded`, `@onkeydown` handler (Enter/Space toggles)

### 2. Decorative SVGs exposed to assistive technology

**Files:** `MainLayout.razor`

**Before:** Brand icon SVG and hamburger menu SVG lacked `aria-hidden="true"`.

**After:** Both SVGs now have `aria-hidden="true"` (the parent elements have visible text labels).

### 3. Icon-only button without aria-label

**File:** `Compose.razor`

**Before:** Attachment remove button (`✕`) had no `aria-label`.

**After:** `aria-label="Remove attachment"` added.

## Audit results (no issues found)

- All loading spinner SVGs already have `aria-hidden="true"` on the parent `<svg>`.
- Notification row SVG icons already have `aria-hidden="true"`.
- All form inputs have associated labels.
- Navigation buttons have proper `aria-label` and `aria-expanded`.

## Files changed

- `apps/Iris.Web.Client/Components/EngagementBar.razor` — ARIA labels, aria-pressed, role/tabindex/keydown on more-options toggle.
- `apps/Iris.Web.Client/Components/Layout/MainLayout.razor` — `aria-hidden="true"` on brand and hamburger SVGs.
- `apps/Iris.Web.Client/Components/Pages/Compose.razor` — `aria-label` on attachment remove button.
