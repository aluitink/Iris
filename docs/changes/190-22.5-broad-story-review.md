# 190 — Phase 22.5: broad story review (US-1…US-24 play together)

## Summary

Performs the **Phase 22.5 broad story review** (step 5 of the
[22-sample-ui-user-stories.md](../plans/22-sample-ui-user-stories.md) working order): reads the full
story set (US-1…US-24) together and confirms the pages/components **play well with each other** — shared
components in use, no contradictions, consistent navigation + error/empty/loading states — before the
22.6 implementation sweep. The review surfaced **one concrete consistency gap** (the Community page was
missing the US-21 raw-JSON inspector) and a **known consolidation opportunity** (deferred, not a
contradiction). The gap is fixed here; the rest of the story set is confirmed consistent.

## The review (what was checked, and the verdict)

The story set was cross-checked against the sample UI surface (9 pages, 4 shared components, the
`MainLayout` shell, and the `ExplorerSession` state):

- **US-19 shared `ObjectView`** — every object-rendering surface renders through the single
  `ObjectView.razor` (actor, note, media, replies, raw). ObjectPage, ActorDetail, Community (members /
  search / feed / inbound-follows), Actors, and Home all drop in `<ObjectView Item=… />`. Consistent.
- **US-20 `PagedCollection`** — `Feed.razor` and the `ActorDetail` outbox/liked collections use the
  reusable paged card (loading / empty / error / Load-more / next-link walking all handled in one place).
  Consistent where it applies.
- **US-21 `RawInspector`** — present on all three detail pages: ObjectPage, ActorDetail, **and now
  Community** (the fix below). The Instance and Actors pages are not detail pages, so they correctly have
  none.
- **US-22 back links** — every detail page (Object, Actor, Community) renders `<BackLink />`, which
  targets the session's navigable state (object → actor → home) and updates reactively. The non-detail
  pages (Home, Instance, Actors, Feed, Compose, Deliver) are top-level and correctly have no back link.
- **US-3 identity bar** — `MainLayout` shows the resolved actor IRI + dial base and updates on
  instance switch (verified in 189). Consistent.
- **US-23 loading/empty/error states** — every page gates on `IsLoggedIn` with the same
  "Log on to an instance…" message; every card has a loading ("Loading…"), an empty ("No …"), and an
  error (`<div class="error">`) branch. Errors surface as `ex.Message` into named error properties —
  **no raw stack-trace dumps** anywhere. Consistent.
- **US-24 cross-server** — `ProxyFallbackHandler` routes cross-host GETs through the home proxy (188);
  the identity bar makes the dial base explicit; recents + one-click switch work (189). Consistent.

**Verdict:** the stories play together. No contradictions found. One consistency gap (Community raw
inspector) was found and fixed.

## What changed (code)

- **`samples/SampleBlazorClient/Pages/Community.razor`** — added the missing
  `<RawInspector Document="CommunityDoc" Title="Raw inspector" />` at the end of the logged-on,
  loaded-community region (mirroring ObjectPage/ActorDetail). The community detail page is named in the
  plan's component inventory as serving **US-21**, but it was the only detail page without the raw-JSON
  inspector. The inspector is lazy (fetches + formats on first expand), so it costs nothing until opened.

No other page/component changed; no new package; no seam change.

## Manual verification (Playwright MCP, local compose stack)

Booted the local compose stack (iris-a 8081, iris-b 8082, iris-ui 8090), logged on to iris-a
(`alice@localhost` → `http://localhost:8081`), navigated in-SPA to the **Community** page, and loaded
the `iris` community. The **Raw inspector** card now renders with a "Show raw JSON" toggle; expanding it
shows the community's formatted ActivityStreams `Group` document (id, type, outbox/inbox/followers,
members, feed, search, mutes/blocks/flags, publicKey, capabilities) and the toggle flips to "Hide raw
JSON" — identical behavior to ObjectPage/ActorDetail. Build clean, format clean, full solution green
(1,274 tests).

## Known consolidation opportunity (deferred to 22.6, not a contradiction)

The community's read-only `following`/`followers` collections (and ActorDetail's `inbox`) are still
hand-rolled paged cards that duplicate the loading/empty/Load-more logic `PagedCollection` encapsulates.
They are **functionally consistent** (same states, same next-link walking) — not a bug or a contradiction
— but they are the clearest dedup candidates. They are **not** converted in this slice: the
`PagedCollection` template renders each item as a navigable object link, whereas these cards render
handle-only links (and, on ActorDetail, attach management buttons), so converting them faithfully
requires a small template generalization + a manual re-check of the management interactions. That
generalization is the right shape of work for the **22.6 implementation sweep**, where it can be done
together with a full manual pass. Record here so 22.6 knows to consider it.

## Decision

**Fix the one real gap now; defer the cosmetic dedup.** The Community raw-inspector gap was a genuine
consistency miss against US-21 (the plan explicitly names Community.razor as serving US-21), so it is
fixed and verified in this slice. The hand-rolled read-only collections are a consolidation opportunity,
not a contradiction, and converting them cleanly needs a `PagedCollection` template generalization that
belongs in the 22.6 sweep (with its manual pass) rather than being rushed into the review slice.

## Remaining (22.5)

- None. 22.5 is complete: the story set is reviewed and confirmed consistent, the one gap is fixed and
  verified, and the deferred consolidation is recorded for 22.6.
