# 171 — Phase 19.8.1 gap (b): Instance page recent-instances list

## Summary

The `/instance` page now shows a **"Recent instances"** card (the session's
`ExplorerSession.RecentInstances`) with one-click instance switching, mirroring the Home page's
surface. The current instance (dial-base match) is marked **"(current)"** instead of offering a
switch button. This closes **19.8.1 gap (b)** — "the Instance page shows no recent-instances list."

## What changed (code)

- **`samples/SampleBlazorClient/Pages/Instance.razor`**
  - New "Recent instances" card (rendered when `Session.RecentInstances.Count > 0`), listing each
    recent instance by handle + host.
  - The current instance (its `DialBaseUri` equals the session's active `DialBaseUri`) is shown with
    a **"(current)"** marker and no switch button.
  - Other instances show a **"Use"** button (selects the switch target) → re-enter password →
    **"Switch"** button.
  - New state: `SwitchTarget`, `SwitchPassword`, `SwitchBusy`, `SwitchError`.
  - New methods: `SelectSwitchTarget(RecentInstance)` (selects the target) and `SwitchAsync(RecentInstance)`
    (re-enters the password, calls `Session.SwitchInstanceAsync`, then re-loads the new instance's
    NodeInfo).
- **`tests/SampleBlazorClient.Tests/S19InstanceRecentInstancesTests.cs`** (new)
  - `InstancePage_RecentInstances_RendersListWithCurrentMarker` — logs on as alice + bob (two recent
    instances), renders the full Instance page (bUnit + in-process SampleServer, the session injected
    via `ctx.Services.AddSingleton`), and asserts the list renders both entries with the current one
    (bob) marked "(current)".
  - `InstancePage_SingleRecentInstance_CurrentMarkedNoSwitchButton` — a single recent instance renders
    the list with the current one marked "(current)" and no switch button.
- **`.gitignore`** — added `.tmp-bunit-probe/` (a scratch reflection-probe project used while
  discovering the bUnit 2.9 service-registration API).

## Key types / API

- `ExplorerSession.RecentInstances` (`IReadOnlyList<RecentInstance>`) — the most recent logged-on
  instances (newest first).
- `ExplorerSession.SwitchInstanceAsync(RecentInstance, string password, CancellationToken)` — logs out
  the current identity and logs on to the selected recent instance (the switch button's action).
- `RecentInstance` (record) — `Handle`, `Host`, `Scheme`, `DialBaseUri`, `ActorIri`.
- The bUnit 2.9 service-registration API: `ctx.Services.AddSingleton(instance)` (the
  `BunitServiceProvider` implements `IServiceCollection`; the parameterless `new BunitContext()` is
  used — the older `TestContextOptions` constructor was removed in 2.9).

## Why this is a code slice (not just live)

The recent-instances data (`ExplorerSession.RecentInstances`) and the switch action
(`SwitchInstanceAsync`) were already implemented + tested (S3, §4.2 one-click instance switching).
What was missing was the **UI surface on the Instance page** — the Home page already had it, but the
`/instance` page (the natural "where am I / which instance" screen) did not. This slice adds the
surface + the "(current)" detection (the current instance is not switchable).
