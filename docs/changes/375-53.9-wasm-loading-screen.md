# 53.9 — Branded WASM Loading Screen

## Summary

Replaced the bare "Loading…" text shown during the initial WASM boot (before Blazor initializes and replaces `#app`) with a branded loading screen: the Iris logo (pulsing), a spinner, the "Iris" wordmark, a tagline, and a "Loading…" status. It uses the app's existing design tokens and matches the dark theme.

## Changes

### `apps/Iris.Web.Client`
- `wwwroot/index.html`: The `#app > .splash` markup now contains a `.splash-logo` (the Iris SVG, matching the favicon), a `.splash-spinner`, the `.splash-title` wordmark, the `.splash-sub` tagline, and a `.splash-status` (with `role="status"` for accessibility).
- `wwwroot/css/app.css`: Added `.splash` (full-viewport flex column, centered), `.splash-logo svg` (64px, pulsing animation), `.splash-spinner` (border spinner, `splash-spin` animation), `.splash-title`, `.splash-sub`, `.splash-status`, the `splash-spin`/`splash-pulse` keyframes, and a `prefers-reduced-motion` override.

## Verification

- Build clean, all tests pass (Server.Tests 951 passed / 0 failed; full suite green — the one transient failure under parallel load was the known flaky federation test).
- Live-verified via Playwright with browser cache disabled: the `.splash` element computes to `display:flex`, `min-height:100vh`, centered; the logo and spinner are horizontally centered in the viewport with the correct animations (`splash-pulse` / `splash-spin`) applied. The splash HTML and CSS are served fresh (the earlier stale-CSS symptom was the known WASM/browser caching pitfall, resolved by clearing the browser cache).
