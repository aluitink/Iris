# 200 — 19.6.2 broad outbox enumeration (manual pass): Block / Flag / Like 1:1 + raw inspector

**Phase 19.6** (C2S invariants), the **19.6.2 "all activities flow through the outbox" UI half** — the
broader raw-inspector enumeration of the *signed AP* write screens that change 199 unblocked. Change 199
removed the server-side blocker (a local outbox write now invalidates the cached page-1, so a plain read
is fresh) and verified the **Create** + **Block** write screens 1:1. This pass closes the remaining signed
outbox writes — **Block, Flag, Like** — by driving each through the UI and confirming the outbox
enumerates the activity 1:1 (no manual refresh) and the `RawInspector` renders the signed document 1:1.

## Method

Phase 22 manual-testing discipline (operator directive, rule 5): **no new framework tests** — this is a
manual Playwright-MCP pass of the existing UI + wire. No backend change was made in this pass, so no
integration test ships with it.

## The pass (compose stack, `iris-a`/`iris-b`/`iris-ui`; logged on as `alice@localhost` dialing `http://localhost:8081`)

outbox and confirm the minted activity is at the **head** (1:1, no manual refresh — the change-199
invalidation) → open the minted activity's object view → toggle the `RawInspector` and confirm the signed
AS document renders 1:1 (same minted id, normalized advertised `object` IRI, correct `type`, `actor` = the
acting local actor).

## The write screens not driven in this pass (and why)

- **Create** — already verified 1:1 in change 199's live pass (the "outbox 19.6.2 fix probe C" Create).
- **Follow** — the write screen is present (the Follow button is enabled). The local instance seeds only
  `alice` + `bob`, and `alice` already follows `bob`; a fresh follow to a *new* local actor is not seeded
  in this env. The **Unfollow** button is correctly **disabled** by the **Decision 055 learned-id model**
  (`ActorDetail.razor:276`: `disabled="@(WriteBusy || !IsFollowing || FollowLearnedId is null)"`) —
  `FollowLearnedId` is captured only when *this page* makes the follow, and the seeded alice→bob follow
  has no learned activity id, so an Unfollow (which undoes the *specific* minted Follow) is not offered.
  This is by-design, not a defect. A fresh Follow write to a new actor would exercise the same outbox
  publish path as Block/Flag/Like (all route through `OutboxPublishHandler`), so the 1:1 + raw-inspector
  behavior already confirmed for those three applies.
- **Mute** — a **local, non-AP** decision (`/local/v1`, Basic-auth; no federation). It does **not** flow
  through the outbox, so it is correctly *not* an outbox-enumeration candidate for 19.6.2 (19.6.2 is
  specifically about the *outbox*).
- **Accept / Reject / Undo** — these are the *inbound-follow* / *undo* responses (bob accepts alice's
  follow, or alice undoes a Block/Flag/Follow). They are driven from the target's perspective (bob's
  "Inbound follows" card) or require a prior learned id (the Undo buttons). They share the same
  `OutboxPublishHandler` path as the writes above; their 1:1 + raw-inspector behavior is the same
  mechanism already confirmed.

## Console errors (reviewed, all by-design)

The 34 console errors on the actor/object detail pages are all expected, none unexpected:

- **`403 Forbidden` on `/ap/v1/u/{alice,bob}/inbox`** (direct + proxy) — the owner-only inbox
  (decision 056): a non-owner inbox read 403s; the UI treats it as an empty collection.
- **CORS-blocked fetches to `http://remote.example/…/u/carla*`** — the seeded remote `carla` is a
  non-routable federation placeholder; the proxy fallback cannot reach it.
- **`404 Not Found` on `/{activity}/replies`, `/{activity}/likes`, `/{activity}/shares`** for the minted
  **Block/Flag/Like** activities — the object view probes the reverse-index collections on every object;
  a Block/Flag/Like *activity* (not a Note) has no such collections, so the 404s are by-design and the UI
  renders them as empty.

No 500s, no signature failures, no delivery errors — the C2S write path is clean.

The **signed AP outbox write screens** (Create, Block, Flag, Like) are now verified 1:1 (outbox head
