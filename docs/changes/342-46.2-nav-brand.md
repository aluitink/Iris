# 46.2: Nav + brand

## Scope

Three design changes from the 46.1 audit:

1. **Brand mark** (P2-7) — "Iris" text is now accompanied by a small iris/eye SVG icon (concentric circles), bumped to 1.4rem, displayed as an inline-flex row.
2. **Hamburger menu below 768px** (P1-1) — the horizontal nav is replaced by a hamburger toggle button on mobile. Tapping it reveals a full-width dropdown menu with all nav items stacked vertically. The old horizontal-scroll nav (640px breakpoint) is removed.
3. **Hide the Blazor WASM error bar** (P3-10) — `#blazor-error-ui` is hidden by default (`display: none`). A small `error-ui.js` script handles the dismiss button. The bar only appears when Blazor's built-in error handler adds the `show` class.

## Design decisions

- **768px breakpoint** (was 640px): matches the audit's "below 768px" requirement. The hamburger appears at ≤768px.
- **No JS resize handler**: the menu is pure CSS (`.nav-open` class) + Blazor `@onclick`. When the user resizes above 768px, the nav reverts to the horizontal layout via the media query (the `nav-open` class has no effect at that width since `.main-nav` is always `display: flex` there). No JS needed.
- **Dropdown positioning**: `position: absolute; top: 100%` relative to the header (`position: relative`). Full-width, panel background, border-bottom.
- **Error bar**: Blazor's built-in error handler (`blazor.webassembly.js`) adds `show` to `#blazor-error-ui` on unhandled errors and removes it on dismiss. The CSS `display: none` / `display: flex` pair works with this. The `error-ui.js` script is a safety net for the dismiss button (Blazor's built-in already handles it, but the script ensures it works even if the built-in behavior changes).
