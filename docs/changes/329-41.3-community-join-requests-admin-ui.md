# 41.3 — Community membership requests (admin UI)

## Summary

The community detail page gains a **Requests** tab (visible only to the community's creator) that lists pending join requests — actors who sent a `Join` activity while the community's `manuallyApprovesMembers` flag is set. Each request has **Accept** and **Reject** buttons.

- **Accept** adds the actor as a member of the community and removes the pending request.
- **Reject** removes the pending request (no membership granted).

## Server endpoints

All three endpoints are creator-only: the server verifies the authenticated person (via Basic auth + `IActorCredentialValidator`) is the community's creator (the `Group`'s `AttributedTo`).

| Method | Route | Description |
|---|---|---|
| `GET` | `/local/v1/c/{name}/requests` | Lists pending join-request actor IRIs (JSON array). |
| `POST` | `/local/v1/c/{name}/requests/accept/{**actorIri}` | Accepts the request: adds the actor as a member, removes the pending request. Returns 204. |
| `POST` | `/local/v1/c/{name}/requests/reject/{**actorIri}` | Rejects the request: removes the pending request. Returns 204. |

Returns 404 when the community or request is unknown; 403 when the requester is not the creator.

The pending-join-request lifecycle is managed by the existing `ICommunityStore` API (`AddJoinRequestAsync`, `RemoveJoinRequestAsync`, `HasJoinRequestAsync`, `GetJoinRequestsAsync`), which is populated by `MembershipActivityHandler` when a `Join` arrives at a community with `manuallyApprovesMembers` set.

## Client

`ILocalModerationClient` / `LocalModerationClient` gain three methods (each with an explicit-credentials overload):

- `GetCommunityJoinRequestsAsync(Iri communityId, CancellationToken ct)`
- `AcceptCommunityJoinRequestAsync(Iri communityId, Iri actorId, CancellationToken ct)`
- `RejectCommunityJoinRequestAsync(Iri communityId, Iri actorId, CancellationToken ct)`

These are Basic-authenticated requests to the community's home instance (the same pattern as `RemoveCommunityMemberAsync`).

## UI

`CommunityDetail.razor`:

- A **Requests** tab appears in the tab bar when the current user is the community's creator. The tab shows a count badge when requests are pending.
- Selecting the tab loads the pending requests (lazy — loaded on first tab switch).
- Each request row shows the actor's handle (linked to their profile) with **Accept** and **Reject** buttons.
- After a successful Accept/Reject, the list is reloaded and the member count is refreshed.
