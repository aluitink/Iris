# 56.2 — Pleroma/Akko Wire-Compatibility Check

## Summary

Audited Iris's ActivityPub wire format against Pleroma/Akko's AP implementation. **No new inbound gaps** — Iris preserves all Pleroma-specific fields via `[JsonExtensionData]` round-trip. Outbound, Pleroma surfaces the same 5 Mastodon gaps plus 2 Pleroma-specific ones.

## Inbound: Clean

Iris preserves every Pleroma-specific inbound field (`source`, `updated`, `conversationId`, `threadContext`, `emoji`, `pleroma:*`) through the ActivityStreams library's `[JsonExtensionData]` round-trip. Verified live and by existing tests:

- `MastodonExtensionPassthroughIntegrationTests` — `toot:emoji`, `sensitive`, `poll` round-trip.
- `MoveExtensionRoundTripIntegrationTests` — namespaced `iris:reason` (full-IRI ExtensionData key) preserved.
- The audience-rewrite only touches the authoring path, not inbound Pleroma objects.

## Outbound: 7 Gaps

| # | Gap | Mastodon impact | Pleroma impact | Status |
|---|---|---|---|---|
| 1 | `updated` not set on edit | High | High (Pleroma renders edit-time) | Missing |
| 2 | `source` field missing | High | High | Missing |
| 3 | Direct/followers-only visibility incorrect (followers always cc'd) | High (DM leak) | High (strict `to`/`cc`) | Incorrect |
| 4 | `summary` only when `sensitive` true | Medium | Medium | Restricted |
| 5 | Scalar vs array for 1-element `to`/`cc`/`attributedTo` | Low | Low (Pleroma marginally stricter) | Library artifact |
| 6 | `conversationId` never set | N/A (Mastodon ignores) | **Yes** (Pleroma uses for thread grouping) | Missing (Pleroma-only) |
| 7 | `emoji` (custom) never set | N/A (Mastodon uses `toot:emoji`) | **Yes** (Pleroma renders custom emoji) | Missing (Pleroma-only) |

### Pleroma-specific findings

**`conversationId`:** Pleroma sets a stable thread-root IRI on every note; Pleroma clients use it for thread grouping. Iris never sets it. Low impact (Mastodon ignores it too) but a genuine "Pleroma would catch" gap.

**`emoji` (custom):** Pleroma renders custom emoji from the `emoji` array (`{name, imageUrl, shortCode}`). Iris authors no `emoji` field. An Iris post with a custom emoji would arrive at Pleroma as a bare shortcode with no image mapping.

**`threadContext`:** Pleroma-only, never set outbound, preserved inbound. Low impact (redundant with `inReplyTo`).

## Key Structural Finding

The storage model is serialize → store JSON string → deserialize (not raw passthrough, not field-by-field). Because `Object.ExtensionData` is `[JsonExtensionData]`, all unknown fields survive the round-trip. This is why inbound Pleroma objects are preserved without special handling.

## Decisions

- **No code changes in this slice.** Analysis only.
- The top-3 gaps for 56.3 (combined Mastodon + Pleroma priority):
  1. `updated` timestamp (helps both ecosystems, low fix complexity)
  2. `source` field (helps both, medium complexity)
  3. Visibility modes + conditional `cc` merge (helps both, medium complexity)
- `conversationId` and `emoji` are Pleroma-specific, lower priority — deferred to a future phase.
- Scalar-vs-array (rank 5) is a library-level `OneOrMultipleConverter` behavior; fixing requires a custom converter. Lowest priority.

## Test counts

No new tests (analysis only). Existing suite unchanged.
