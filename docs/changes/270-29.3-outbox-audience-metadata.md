## Summary

Converted `OutboxAudienceMetadataIntegrationTests` (3 tests, 3-host topology A/B/C) from building its

## What changed

- **`tests/Iris.Server.Tests/OutboxAudienceMetadataIntegrationTests.cs`** — replaced per-method
  `StartAuthorServer`/`StartServer` calls with `SharedThreeHostFixture` (3 hosts built once per
  collection). The test class now:
  - Takes `OutboxAudienceMetadataSharedHost` in its constructor (concrete fixture type, xunit
    requirement).
  - Implements `IAsyncLifetime`: `InitializeAsync` calls `_fixture.Reset()` then `SeedForFixture`
    (restores alice/bob/carol with their existing keys + bob→alice follow edge on A).
  - `SeedForFixture` is `internal static` so the fixture can call it during construction (before
    `Reset()` clears data stores, the key stores survive).
  - `RoutingHandler` (B/C by host) and `RoutingFetcher` (A/B/C) are now `internal sealed` (accessible
    from the derived fixture class).
  - `BuildFetcherFor` is `private static` (used only by `RoutingFetcher` in the test class); the
    fixture has its own `BuildFetcherForLazy` for B/C's fetcher → A.
  - Removed the local `WaitForAsync` helper (now uses `TestFederation.WaitForAsync` from Iris.Testing).

- **`OutboxAudienceMetadataSharedHost`** (new, same file):
  - Extends `SharedThreeHostFixture`.
  - `BuildOptions()` creates 3 `InMemoryPersistenceProvider`s, seeds alice/bob/carol with
    `SeedPersonWithKey`, records bob→alice follow on A, resolves `ServerRefFor` for all three, builds
    A's identity (RoutingFetcher + RoutingHandler delivery to B/C) and B/C's identity (each with a
    fetcher reaching A via `LazyHandler`).
  - `BuildFetcherForLazy` builds an `IActorDocumentFetcher` for B or C that reaches A's handler lazily.
