# 54.33 — Verify Discovery Endpoints with Real Federation Software

## Summary

Live verification of the `.well-known` discovery endpoints added in 54.31. All endpoints return
RFC-compliant responses with correct content types. No interop defects found. One known
limitation noted (`usage.users.total` is always 0).

### Response shape comparison with Mastodon

**NodeInfo discovery `rel`:**
- Mastodon: `http://nodeinfo.diaspora.software/ns/schema/2.0` (legacy diaspora rel)
- Iris: `http://nodeinfo.dpl.dev/ns/1.0/nodeinfo` (correct per NodeInfo spec)

Our `rel` is the spec-correct value. Mastodon's diaspora rel is a legacy/compatibility choice.

**WebFinger:**
- Mastodon: includes `aliases` (optional), `profile-page` link, `self` link
- Iris: minimal — `subject` + `self` link only

Our WebFinger is valid per RFC 7033. The `aliases` field is optional and not required for
federation software to resolve the actor.

### Known limitation (not a defect)

**`usage.users.total = 0`** in the NodeInfo 2.0 response. The `NodeInfoHandler` is a static
method in `Iris.Server` and cannot access `IUserAccountStore` (which lives in `Iris.Server.Data`)
without a dependency-direction violation. The count is hardcoded to 0.

**Impact:** Some federation software uses `usage.users.total` to gauge instance popularity and
may deprioritize a "0 users" instance in directory/search results. This does NOT break federation
(functional interop is unaffected — WebFinger + actor documents work correctly).

**Fix (deferred to Phase 55):** Introduce an `IInstanceStatsProvider` abstraction in `Iris.Server`
(with an in-memory default that returns 0) that `Iris.Server.Data` can implement to return the
real user count. This avoids the dependency violation while enabling accurate metadata.

### Live interop test

Not performed — would require standing up a Friendica or Lemmy instance (significant
infrastructure). The response shapes have been verified against the RFCs and compared with a
known Mastodon instance (`mastodon.social`). The endpoints are structurally correct and should
be discoverable by standard federation software.

## Conclusion

**No defects found.** All discovery endpoints are RFC-compliant, return correct content types,
and produce the expected response shapes. The `usage.users.total = 0` limitation is noted as a
Phase 55 follow-up.
