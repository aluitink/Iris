# Change 210 — 19.8.5: Cross-instance navigation (live verification)

## What

A Playwright MCP pass to drive a real iris-a → iris-b peer-item selection through the browser and
confirm the remote object renders. No new code or tests (verification-only slice, per Phase 22 rule 5).

## Test scenario

1. **Log on to iris-a** as `alice@localhost` (dial base `http://localhost:8081`).
2. **Navigate to the Object page** and enter the IRI of an iris-b object:
   `https://iris-dev2.luit.ink/ap/v1/u/alice/notes/1`.
3. **Confirm the remote object renders:** the UI showed the Note (content "Welcome to the Iris sample
   server!", by alice, with a "View on originating instance" link).
4. **Navigate to the iris-b actor detail:** clicked the "alice" link in the object view; the UI
   rendered the Person (alice, IRI `https://iris-dev2.luit.ink/ap/v1/u/alice`) with the Outbox,
   Followers, and Following sections populated.
5. **Test the "Continue where you left off" card:** navigated to the Home page; the "Continue where
   you left off" card showed a link back to the iris-b object. Clicked it; the UI navigated back
   correctly.

## Key findings

1. **Cross-instance object navigation works:** the iris-b object was fetched via the proxy fallback
   (the 22.4 US-8 proxy fallback, ch.188) and rendered correctly in the UI.
2. **Cross-instance actor navigation works:** the iris-b actor detail page rendered correctly, with
   the Outbox, Followers, and Following sections populated from iris-b.
3. **The "Continue where you left off" card works:** the navigable state is preserved across instance
   switches, and the card correctly shows the last item viewed (the iris-b object). Clicking the card
   navigates back to the item on the current instance.
4. **The "View on originating instance" link is present:** the object view includes a link to the
   originating instance (iris-b), allowing the user to view the object on its home server.

## Wire observations

- The iris-b object was fetched via the proxy fallback (the browser requested
  `http://localhost:8081/ap/v1/proxy/https://iris-dev2.luit.ink/ap/v1/u/alice/notes/1`, and the
  proxy fetched the object from iris-b).
- The iris-b actor detail was fetched via the proxy fallback (the browser requested
  `http://localhost:8081/ap/v1/proxy/https://iris-dev2.luit.ink/ap/v1/u/alice`, and the proxy
  fetched the actor from iris-b).
