# 39.1 — Community join/leave

## Summary

Adds a Join/Leave button to the community detail page. A signed-in user can join a
community (delivers a `Join` activity to the community's inbox) or leave (delivers a
`Leave` activity). The membership is recorded/removed in the `Edges` table
(`EdgeKind.CommunityMember`).

## Changes

### `IActivityPubClient` / `ActivityPubClient`
- Added `RequestLeaveAsync(Iri actorId, Iri communityIri, CancellationToken ct)` —
  builds a `Leave` activity (actor=user, object=user) and delivers it to the
  community's inbox.
- Fixed `RequestJoinAsync` to set the `Id` on the `Join` activity (the inbox endpoint
  requires `Id: not null`; the server does not mint ids for inbox-received activities).
- Fixed `RequestJoinAsync` `Object` field to be the actor (not the community) — the
  `MembershipActivityHandler` reads `object` to determine who to add.

### `JoinButton.razor` (new)
- Blazor component that shows a "Join" or "Leave" button based on the current
  membership state. On click, calls `RequestJoinAsync` or `RequestLeaveAsync` and
  updates the UI state + invalidates the `UiContext` membership cache.

### `UiContext`
- Added `IsMemberAsync(Iri communityIri)` — walks the community's `/members`
  collection (with `BypassCache: true` to avoid stale server-side cache) and caches
  the result per-circuit for 2 minutes.
- Added `InvalidateMembership(Iri communityIri)` — clears the cached membership set.
- Added `AppendSegment` helper.

### `CommunityDetail.razor`
- Wired `<JoinButton CommunityActor="CommunityDoc" />` next to the FollowButton.

### CSS
- Added `.join-button` styles.

### Test mocks
- Added `RequestLeaveAsync` stub to all `IActivityPubClient` mock implementations
  in test projects.

## Verification
- Build clean, all tests green (154 + 32 + 10 + 942 + 53).
- Docker rebuild + Playwright: join → button toggles to "Leave", membership edge
  recorded in `Edges` table (Kind=8). Leave → button toggles to "Join", membership
  edge removed.
