# 194 — 22.6 Implementation sweep: consolidate Actor-detail mutes/blocks/flags onto `PagedCollection`

**Phase 22.6** (implementation sweep + manual test pass), fourth slice.

## What changed

The **Actor detail** page's read-only **Moderation (this actor's collections)** card — three hand-rolled
**Mutes** / **Blocks** / **Flags** sub-sections (21.1.2) showing who the *target* actor has
muted/blocked/flagged — each re-implemented the load / empty / error / "Load more" / next-link-walking
logic the shared
[`PagedCollection`](../../samples/SampleBlazorClient/Components/PagedCollection.razor) component already
implements. This slice consolidates all three onto that component, the last dedup candidate in the sweep.

- `samples/SampleBlazorClient/Pages/ActorDetail.razor`
  - The three `<h4>Mutes</h4>`/`<h4>Blocks</h4>`/`<h4>Flags</h4>` sub-sections (their
    `TargetMutes*`/`TargetBlocks*`/`TargetFlags*` state, their loading/empty/error markup, their
    `Load more` buttons) are replaced by three `<PagedCollection … ItemTemplate="@ActorLinkTemplate" />`
    components (driven by `actorIri.MutesOf()` / `.BlocksOf()` / `.FlagsOf()`), each titled
    "Mutes"/"Blocks"/"Flags" with a plain `Description`.
  - The card's `<h3>Moderation (this actor's collections)</h3>` + the long muted description (which
    contains markup — `<em>`/`<c>` — and so cannot go in the `Description` string attribute) is kept as a
    plain header card directly above the three `PagedCollection`s.
  - Added `ActorLinkTemplate` (a field-based `RenderFragment<IObjectOrLink>` — Razor does not reliably
    parse multi-statement inline render-fragment attributes), reusing the same body as the Community page's
    template: each entry (a link or an object with an `id`) renders as a link to that actor's detail page
    (`/actor?iri=…`, title = IRI, text = `HandleOf`), or a `<code>` relay-IRI fallback.
  - Removed: the `TargetMutesItems`/`TargetBlocksItems`/`TargetFlagsItems` / `*HasMore` / `*LoadingMore` /
    `*Error` fields, the `_targetMutesResumeFrom`/`_targetBlocksResumeFrom`/`_targetFlagsResumeFrom`
    cursors, the three initial-load calls in `LoadAsync`, and the six methods
    (`LoadMoreTarget{Mutes,Blocks,Flags}Async` / `EnumerateOneTarget{…}PageAsync`).

## Note

`HandleOf`/`RelayIriOf` (already on the page) are now used by `ActorLinkTemplate`; the Inbox
`PagedCollection` (change 191) is unchanged.

## Behavior parity

Each card's states (loading spinner, empty "No mutes/blocks/flags recorded.", error, Load more) now come
from `PagedCollection`, identical to the Outbox/Inbox/Following/Followers/Community cards. The item markup
is the same as the previous hand-rolled `<li>` markup (a link to the moderated actor's detail).
