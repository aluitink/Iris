# 46.4 — Object detail + notifications

## Scope

Address P3-14 from the 46.1 design audit: notification rows showed raw IRIs (hard to read), and the object detail page heading was generic ("Note" / "Article" instead of the author).

## Changes

### NotificationRow.razor

- **Target preview**: Added `TargetPreview(IObjectOrLink?)` — extracts the target object's content (HTML-stripped, truncated to 120 chars) when the activity's object is a full `ActivityObject` with content.
- **Short label fallback**: Added `ShortLabel(Iri)` — when no content preview is available (the common case: inbox activities carry links, not embedded objects), displays the last two path segments (e.g. "notes 06G7ZE…") truncated to 40 chars. This replaces the full raw IRI.
- **CSS**: Replaced `word-break: break-all` on `.notification-target` with a cleaner ellipsis layout. Added `.notification-target-link` with hover accent color.

### ObjectDetail.razor

- **Page heading**: `PageHeading` now resolves the subject object's `AttributedTo` first segment and displays `@handle` (e.g. "@alice") instead of the generic type name ("Note" / "Article"). Falls back to the type name when no author is resolvable.

## Design decisions

- **No async fetch for target content**: The inbox API returns activities with link objects (IRIs only), not embedded objects. Fetching each target to extract a content preview would require N+1 requests per page of notifications. The short label (last two path segments) is a reasonable MVP tradeoff — it's human-parseable and links to the full object.
- **40-char truncation**: Keeps the label compact on mobile without breaking layout. The full IRI is still available in the `title` attribute on hover.

## Verification

- Build clean, all tests green (951 server + 63 web + other suites).
- Playwright: notification row shows "notes 06G7ZEQYYGGTX9R7QSS8TVXPG8" (not the full IRI). Clicking navigates to the object detail.
- Playwright: object detail page heading shows "@alice" (not "Note"). No console errors.
