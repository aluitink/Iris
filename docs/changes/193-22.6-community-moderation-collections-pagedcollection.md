# 193 — 22.6 Implementation sweep: consolidate Community mutes/blocks/flags onto `PagedCollection`

**Phase 22.6** (implementation sweep + manual test pass), third slice.

## What changed

The **Community** page's read-only **Moderation (this community's collections)** card — three hand-rolled
**Mutes** / **Blocks** / **Flags** sub-sections (21.2.1) — each re-implemented the load / empty / error /
"Load more" / next-link-walking logic the shared
[`PagedCollection`](../../samples/SampleBlazorClient/Components/PagedCollection.razor) component already
implements. This slice consolidates all three onto that component.

- `samples/SampleBlazorClient/Pages/Community.razor`
  - The three `<h4>Mutes</h4>`/`<h4>Blocks</h4>`/`<h4>Flags</h4>` sub-sections (their
    `CommunityMutes*`/`CommunityBlocks*`/`CommunityFlags*` state, their loading/empty/error markup, their
    `Load more` buttons) are replaced by three `<PagedCollection … ItemTemplate="@ActorLinkTemplate" />`
    components (driven by `communityIri.MutesOf()` / `.BlocksOf()` / `.FlagsOf()`), each titled
    "Mutes"/"Blocks"/"Flags" with a plain `Description`.
  - The card's `<h3>Moderation (this community's collections)</h3>` + the long muted description (which
    contains markup — `<em>`/`<c>` — and so cannot go in the `Description` string attribute) is kept as a
    plain header card directly above the three `PagedCollection`s.
  - Removed: the `CommunityMutesItems`/`CommunityBlocksItems`/`CommunityFlagsItems` / `*HasMore` /
    `*LoadingMore` / `*Error` fields, the `_communityMutesResumeFrom`/`_communityBlocksResumeFrom`/
    `_communityFlagsResumeFrom` cursors, the reset lines, the three initial-load calls in `LoadAsync`, and
    the six methods (`LoadMoreCommunity{Mutes,Blocks,Flags}Async` / `EnumerateOneCommunity{…}PageAsync`).

## Note

`ActorLinkTemplate` (the field-based `RenderFragment<IObjectOrLink>` added in change
[192](192-22.6-community-following-followers-pagedcollection.md)) is reused unchanged — the mutes/blocks/
flags items share the same shape as following/followers (a link to the moderated actor's detail).
`HandleOf`/`RelayIriOf` are still used by it and by the Inbound follows / Members / Search cards.

## Behavior parity

Each card's states (loading spinner, empty "No mutes/blocks/flags recorded.", error, Load more) now come
from `PagedCollection`, identical to the Outbox/Inbox/Following/Followers cards. The item markup is the
same as the previous hand-rolled `<li>` markup.

## Verification

- `dotnet build` clean under `TreatWarningsAsErrors` (0 warnings / 0 errors); `dotnet format
  --verify-no-changes` exit 0.
- `dotnet test`: full suite green (1,274 tests; no change).
- Playwright-MCP manual pass on the local compose stack (`iris-ui`:8090): log on as `alice@localhost` →
  `/community` → Load `iris`. The **Mutes** / **Blocks** / **Flags** `PagedCollection`s each render their
  heading + description + empty state ("No mutes/blocks/flags recorded."); the header card with the muted
  description is preserved above them. Zero console errors.
