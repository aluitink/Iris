## Summary

This partial converts three more two-instance federation classes to `SharedTwoHostFixture`:

- `CrossInstanceRejectPropagationIntegrationTests` (2 methods) — multi-identity signing on A
  (alice + iris community), bob on B.
- `ModerationUndoPropagationIntegrationTests` (2 methods) — single identity on A (alice), bob on B.
- `RelayLifecycleIntegrationTests` (1 method) — bob on B (with Basic-auth credential validator),
  relay on R.

Combined with partial 5, **all 13 single-instance RISKY classes + 7 two-instance federation classes**
are now converted. Remaining: ~15 two-instance federation classes.

## What changed

### Per-class details

- **CrossInstanceRejectPropagation** (2): A (alice + iris community) + B (bob), `BuildIdentityForA`
  (multi-identity signing), `RoutingFetcher` on both hosts. Seed: alice + iris + bob. B has its own
  `RoutingFetcher` (not just a single `BuildFetcherFor`) because it needs to fetch both its own document
  (to validate bob's Reject signature) and the follower's document (to validate the federated Follow
  signature).
- **ModerationUndoPropagation** (2): A (alice) + B (bob), `BuildIdentity` on A, `RoutingFetcher` on A,
  `BuildFetcherFor` on B. Seed: alice + bob.
- **RelayLifecycle** (1): B (bob, with `BasicAuthCredentialValidator`) + R (relay), `BuildIdentity` on
  both, `RoutingFetcher` on B, `BuildFetcherFor` on R. Seed: bob + relay. The `CredentialValidator`
  closure captures `bobIri` (computed from the known IRI) + the `Password` const — no per-instance state.

### Notes

- `OutboundSignatureIdentityIntegrationTests` was **skipped** (it uses a `CapturingHandler` + a
  `DeliveryWorker` directly, not two `TestServer` hosts — a different topology that doesn't fit the
  `SharedTwoHostFixture` shape).
