# 54.1 — Full Manual Playwright Regression Pass (v1.0.0 Post-1.0 Polish)

## Summary

Swept every user-facing page of the deployed WASM UI (`https://iris.luit.ink`) via Playwright and fixed the **5 defects** the sweep surfaced. No new coded tests (Phase 45+ is the manual-test phase); verification is live against the running instance.

## Defects found & fixed

| # | Severity | Page | Defect | Fix |
|---|----------|------|--------|-----|
| 1 | High (security + UX) | `/admin/dashboard`, `/admin/users`, `/admin/moderation`, `/admin/instance` | A non-admin (or signed-out) user who navigated to an admin page saw a raw WASM JSON exception — `ExpectedStartOfValueNotFound, < Path: $ \| LineNumber: 0 \| BytePositionInLine: 0.` — because `[Authorize(Policy="Admin")]` is not enforced in the WebAssembly host and the page deserialized the server's login-redirect HTML as JSON, surfacing `ex.Message` verbatim. | New `AdminGuard` helper (`Components/AdminGuard.cs`) classifies the signed-in user's role and returns a friendly access-denied message; each admin page now awaits `Session.EnsureReadyAsync()` (to prime the auth state) before gating on `AdminGuard.AccessDenied`. On a 401/403 the page shows "This page is only available to instance administrators…" rather than calling the API into a failure. |
| 2 | Medium | `/notifications` | The fallback verb `type.ToLowerInvariant() + "ed"` misspelt "Flag" as **"flaged"** and rendered "blocked"/"muted" in lowercase. | `NotificationRow.VerbFor` now has explicit cases for `Flag`/`Block`/`Mute`/`Reject`/`Add`/`Remove` ("flagged you", "blocked you", "muted you", "declined", "added you", "removed you") and a capitalised, no-suffix fallback for any other type. |
| 3 | Medium | Mobile (≤375px), footer | `.footer-links` was `inline-flex` with no wrap, so the link row overflowed horizontally (scrollWidth 403 > clientWidth 375). | Added `flex-wrap: wrap` + `row-gap` to `.footer-links` in both CSS mirrors (`Iris.Web.Client` and `Iris.Web` server host). |
| 4 | Low (a11y) | Any post's engagement bar | `aria-pressed="@_liked"` (bool) rendered `aria-pressed=""` when active and was absent when not. | `EngagementBar` now binds `aria-pressed="@(_liked ? "true" : "false")"` (and the same for Boost), so the toggle state is always an explicit `"true"`/`"false"`. |
| 5 | Medium | `/actor` "Posts" tab (outbox) | The actor's outbox rendered **empty cards** (a bare timestamp, no content) for non-content activities (Flag, Block, Undo, …) because `<ObjectView>` expects a content object. | New shared `OutboxFilter.IsContentItem` (`Components/OutboxFilter.cs`) — a `Create` of a `Note`/`Article` — applied via `PagedCollection.ItemFilter` on the actor-detail outbox (the Profile page's private filter now delegates to it too). Only notes/articles render. |

Also replaced the **load-time** raw `ex.Message` with user-friendly copy in the four admin pages, `Profile.razor`, and `CommunityDetail.razor` (the 47.2 edge-case-hardening principle: never leak raw exception text to the user). The remaining ~27 **action-time** `ex.Message` occurrences (save/delete/join/moderation handlers, which already surface server-provided error JSON on failure) are noted for the 54.2 empty/loading-state audit rather than expanded here.

- `apps/Iris.Web.Client/Components/Pages/AdminDashboard.razor` — `EnsureReadyAsync` + `AdminGuard` gate; friendly load/save errors.
- `apps/Iris.Web.Client/Components/Pages/AdminUsers.razor` — same; plus reset/delete action errors.
- `apps/Iris.Web.Client/Components/Pages/AdminModeration.razor` — same; plus dismiss action error.
- `apps/Iris.Web.Client/Components/Pages/AdminInstance.razor` — same; plus save action error.
- `apps/Iris.Web.Client/Components/Pages/Profile.razor` — `IsContentItem` delegates to `OutboxFilter`; load error friendly.
- `apps/Iris.Web.Client/Components/Pages/CommunityDetail.razor` — load error friendly.
- `apps/Iris.Web.Client/Components/Pages/ActorDetail.razor` — outbox `PagedCollection.ItemFilter="OutboxFilter.IsContentItem"` + updated description.
- `apps/Iris.Web.Client/Components/NotificationRow.razor` — explicit moderation-verb cases + capitalised fallback.
- `apps/Iris.Web.Client/Components/EngagementBar.razor` — explicit `aria-pressed` strings.
- `apps/Iris.Web.Client/wwwroot/css/app.css` + `apps/Iris.Web/wwwroot/css/app.css` — `.footer-links` `flex-wrap`.

## Verification (live, Playwright against the running instance)

- **Admin pages (all 3 cases):** signed-out → "Please sign in with an administrator account to view this page."; signed-in non-admin (bob) → "This page is only available to instance administrators. If you believe you should have access, contact your instance admin."; admin (alice) → real data (dashboard stats + registrations, users table, moderation queue, instance form). No raw exception in any case.
- **Notification verb:** bob reported (flagged) alice; alice's notifications render **"flagged you"** (was "flaged").
- **Footer (375×812):** `getComputedStyle(.footer-links).flexWrap === "wrap"`, `scrollWidth (335) === clientWidth (335)`, no horizontal overflow.
- **aria-pressed:** active Like → `aria-pressed="true"`; inactive Like/Boost → `aria-pressed="false"`; Reply (non-toggle) → no attribute.
- **Outbox:** bob's "Posts" tab shows only his 1 real note (the 6 Flag/Block/Undo empty cards are gone); alice's "Posts" tab shows her 4 real notes with engagement bars and the new description.

Build clean (`dotnet build` on `Iris.Web.Client` and `Iris.Web`: 0 warnings / 0 errors). Deployed via `docker compose build iris-web && up -d --force-recreate`.

## Notes

- The Playwright CDP cache-disabling intermittently caused `.wasm` asset fetch failures (`ERR_FAILED`) during the pass — the known WASM browser-caching harness artifact, not an app defect; a clean `page.goto` reset resolved each occurrence.
- A test flag (bob → alice) was created to verify defect #2 and left in place (harmless on this dev instance; dismissible via `/admin/moderation`).
