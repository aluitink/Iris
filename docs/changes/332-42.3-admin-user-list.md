# 42.3 — Instance admin user list

**Status:** COMPLETE
**Commit:** `90f6cf9`
**Tests:** 5 new integration tests (full suite: 1230 passing)

## What

An `/admin/users` page restricted to accounts with the `Admin` role. It lists every local
browser-session account with the handle (username), role (as a colored badge), and creation
date. The page reads `IUserAccountStore.GetAllAsync()` directly (in-process, via the Blazor
circuit's DI scope) — no HTTP round-trip needed.

## Changes

### `apps/Iris.Web/WebAppFactory.cs`

- `AddAuthorization()` now registers an `"Admin"` policy:
  `options.AddPolicy("Admin", policy => policy.RequireRole("Admin"))`.

### `apps/Iris.Web/Components/Pages/AdminUsers.razor` (new)

- `@page "/admin/users"` with `[Authorize(Policy = "Admin")]`.
- Injects `IUserAccountStore` via constructor (Blazor interactive server DI).
- `OnInitializedAsync` calls `GetAllAsync()` and orders by username.
- Renders a table: Handle | Role (badge) | Created (yyyy-MM-dd).
- Loading spinner while the store call is in flight; error card on failure.

### `apps/Iris.Web/wwwroot/css/app.css`

- `.admin-table` — full-width, collapsed borders, muted uppercase headers.
- `.badge` / `.badge--admin` / `.badge--user` — pill-shaped role indicators.

### `tests/Iris.Web.Tests/AdminUsersIntegrationTests.cs` (new)

5 integration tests booting the real app in-process via `WebAppFactory` + `TestServer`:

1. `Unauthenticated_AdminUsers_RedirectsToLogin` — a request to `/admin/users` without a
   session cookie gets a 200 (followed redirect to the login page) or 3xx.
2. `RegisteredAccount_AppearInGetAll` — an account created via `RegistrationService` is
   visible in `GetAllAsync()`.
3. `RegisteredAccount_HasValidFields` — a registered account has a non-default `CreatedAt`,
   a non-zero `ActorId`, and the `User` role.
4. `GetAll_ReturnsAllRegisteredAccounts` — two registered accounts both appear in the list.
5. `FindByUsername_IsCaseInsensitive` — `FindByUsernameAsync("CASECHECK")` finds the
   account registered as `"casecheck"`.

## Design notes

- The page reads the account store directly (Blazor in-process DI) rather than through an
  HTTP endpoint. This avoids the TestServer cookie/auth complexity for the data path and
  is the natural pattern for a Blazor interactive server component. The authorization
  gate (`[Authorize(Policy = "Admin")]`) is enforced by the ASP.NET Core pipeline before
  the component renders.
- No new HTTP endpoints are added. The admin user list is a purely local, non-federated
  surface with no external consumers.
- The `AdminBootstrapper` (which creates the first admin account from `App:Admin:Username`
  / `App:Admin:Password` config) is unchanged; it runs at startup and is idempotent.
