# 161t — Phase 20.4 (b): content-sensitivity support in the object view

## Summary

Phase 20.4 (sub-part **b**) makes the ActivityStreams **content-sensitivity** extension visible in the
sample-UI: a **content-sensitive object** (one carrying the `sensitive` term + a `summary`) now renders
**behind a notice** in the object view, with its real content **absent from the DOM** until the viewer
reveals it. A sensitive object shows its `summary` (the warning/preview) + a "This content may be
sensitive." label + a **Show/Hide** toggle; only after the viewer clicks **Show** is the real content
rendered. Non-sensitive objects render exactly as before (no notice, content shown directly).

This is the **read-side** sensitivity slice: it reads the extension off a served object and renders it
conditionally. It does **not** change how objects are authored (the compose UI does not yet let a user
*mark* a note sensitive — that is part of the broader 20.4 feature work).

## What changed (code)

- **`src/Iris.Core/Identity/IriExtensions.cs`** — two read helpers (the established home for "read a
  field off an `IObject`", next to `GetAudienceIris`/`GetParentIri`):
  - **`IsSensitive(this IObject? obj)`** — reports whether the object carries a JSON-boolean
    `sensitive` of `true`. The library does **not** model `sensitive` as a property, so the term surfaces
    via the library's `ExtensionData` (the `[JsonExtensionData]` catch-all, per the 3rd-Party
    ActivityStreams Rule 6). Reads it with the Rule 6 pattern (`ExtensionData` → `TryGetValue` →
    `JsonValueKind.True`). Returns `false` when the term is absent or not a boolean.
  - **`GetSummary(this IObject? obj)`** — joins the object's typed `summary` (`IEnumerable<string>?`)
    into a single string (whitespace parts dropped; `null` when there is no usable summary). This is the
    text a client shows in place of a sensitive object's content.
- **`samples/SampleBlazorClient/Components/ObjectView.razor`** — the content block now branches on
  `IsSensitive`:
  - **Sensitive:** renders an `.object-sensitive` wrapper holding an `.object-sensitive-notice` (the
    `summary`, the "may be sensitive" label, and a **Show/Hide** reveal button). The real `.object-content`
    is rendered **only when `Revealed` is `true`** — so while hidden the sensitive content is not in the
    DOM at all (not merely blurred). `Revealed` is per-instance `@code` state toggled by the button.
  - **Non-sensitive:** renders `.object-content` directly, exactly as before.
  - New `@code`: `IsSensitive` (`Obj?.IsSensitive() ?? false`), `Summary` (`Obj?.GetSummary()`), and the
    `Revealed` bool.
- **`samples/SampleBlazorClient/wwwroot/css/app.css`** — styling for the notice box, summary, label, and
  reveal button, in the app's palette (muted green accent `#8fd3a7`, dark notice background).

## Why `sensitive` is read from `ExtensionData`

The `KristofferStrube.ActivityStreams` v0.2.4 `Object` type exposes `summary` as a typed
`IEnumerable<string>` but **does not model `sensitive`** as a property — the term lands in the
`[JsonExtensionData] Dictionary<string, JsonElement> ExtensionData`. A probe against the v0.2.4 assembly
confirmed: `Summary` is `IEnumerable<string>` (typed), `Sensitive` is absent, and a `sensitive` JSON
boolean set in `ExtensionData` **round-trips** through `ActivityJson` (serialize → deserialize →
`ExtensionData["sensitive"]` present). Reading it from `ExtensionData` follows the 3rd-Party rules (Rule 6:
non-standard/unsupported fields go in `ExtensionData`, never a re-declared property) and works for both
locally-posted and remotely-received objects.

## What is deliberately NOT in this slice

- **Authoring a sensitive note** (the compose UI has no "mark as sensitive" control yet) — part of the
  broader 20.4 feature work.
- **(a) Media** — compose upload → `Create` object with attachment → stored/served → rendered in the
  object view (builds on 20.2's attachment-rewrite decision).
- **(c) Markdown rendering** — the object view still renders `content` as-is (escaped text); a markdown
  renderer (links, code, lists, headings) is a follow-up. (A sensitive note's `summary`/`content` render
  as text for now; markdown rendering would upgrade that path too.)
