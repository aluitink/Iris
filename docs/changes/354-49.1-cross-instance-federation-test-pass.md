## Limitations

- **No "follow remote actor" UI**: The app's UI (Directory, Search) is local-only. Following
  a remote actor requires the ActivityPub protocol (signed Follow → remote inbox), which is
  exercised by the integration test suite (951 tests in `Iris.Server.Tests` covering
  follow/unfollow/re-follow, cross-instance delivery, convergence) but not by the UI.
- **Real cross-instance follow requires public DNS**: The app advertises `https://iris.luit.ink`
  but the Docker stack is on `localhost:8088`. For a remote instance to deliver content back,
  `iris.luit.ink` must resolve to this host and the HTTPS reverse proxy (48.1) must be
  configured. This is a deployment prerequisite, not an app defect.
- **Mastodon requires signed requests** for actor documents (expected — the app signs its
  requests using the instance actor's key when making outbound federation calls).

## Conclusion

The app's federation surface (WebFinger, NodeInfo, actor documents, inbox, outbox, health,
metrics) is working correctly. The integration test suite already covers the full federation
protocol (follow, delivery, convergence, undo, moderation propagation). No defects found.
