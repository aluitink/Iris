# 52.3: Login Rate Limiting

## Summary

Login rate limiting was already implemented in `LoginService` + `SlidingWindowLoginRateLimiter`
(5 failed attempts per username+IP per 15-minute window). This slice surfaces the `RetryAfter`
hint in the user-facing error message and makes the thresholds configurable via environment
variables.

## Changes

### Server (`apps/Iris.Web/WebAppFactory.cs`)

- **`POST /login` endpoint**: When the `LoginResult.RetryAfter` is non-null (rate-limited),
  appends "Try again in about N minutes." to the error message shown to the user.
- **DI registration**: The `SlidingWindowLoginRateLimiter` is now configurable via:
  - `IRIS_LOGIN_MAX_ATTEMPTS` (or `Iris:Login:MaxAttempts`) — default 5. Set to 0 to disable.
  - `IRIS_LOGIN_RATE_WINDOW_MINUTES` (or `Iris:Login:WindowMinutes`) — default 15.

## Existing Infrastructure (unchanged)

- `ILoginRateLimiter` interface + `SlidingWindowLoginRateLimiter` implementation
  (`apps/Iris.Web/Accounts/LoginRateLimiter.cs`) — sliding-window counter per key.
- `LoginService.LoginAsync` — checks `IsBlocked` before verifying, calls `RecordFailure`
  on bad username/password, calls `Clear` on success. Returns `RetryAfter` in the result.
- Rate-limit key: `{username}|{remoteIp}` (lowercase).

## Decisions

- The rate limiter was already in place from an earlier phase; this slice only surfaced the
  retry-after hint and added env-var configurability. No new components.
- The retry-after message uses "about N minutes" (rounded up, minimum 1) rather than exact
  seconds, matching the 15-minute window granularity.
