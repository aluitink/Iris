# 43.1 — Moderation actions on posts (Block/Mute/Flag)

**Status:** COMPLETE
**Commit:** `f011100`
**Tests:** 6 new integration tests (full suite: 1236 passing)

## What

A "⋯" (more options) dropdown on the `EngagementBar` — the like/boost/reply bar under each post.
When the post's author is a different actor from the signed-in user, a three-dot button appears.
Clicking it reveals a small popover menu with three actions:

- **Block** — sends a signed `Block` activity to the target actor's inbox via
  `IActivityPubClient.BlockAsync`. The server records the block edge in `IModerationStore`.
- **Mute** — sends a local Basic-authenticated request to `POST {actor}/mutes/{target}` via
  `ILocalModerationClient.MuteAsync`. The server records the mute edge locally (not federated).
- **Report** (Flag) — sends a signed `Flag` activity to the target actor's inbox via
  `IActivityPubClient.FlagAsync`. The server records the flag edge in `IModerationStore`.

After any action succeeds, the menu closes. The user can navigate away and the moderation
relationship persists server-side.

## Changes

### `apps/Iris.Web/Components/EngagementBar.razor`

- New `AuthorIri` parameter (`Iri?`): the post author's IRI (the moderation target).
- `CanModerate` computed property: true when `AuthorIri` is set, `Session.ActorId` is set,
  and they differ.
- "⋯" button (`.engagement-more`) rendered when `CanModerate` is true.
- Popover menu (`.engagement-menu`) with three buttons: Block, Mute, Report.
- `BlockAsync()`, `MuteAsync()`, `FlagAsync()` methods call the appropriate client.
- `@onclick:stopPropagation` on the menu prevents the toggle from closing it when clicking
  inside the menu.

### `apps/Iris.Web/Components/ObjectView.razor`

- `EngagementBar` calls for `Create` items now pass `AuthorIri="ActivityActorIri"`.
- `Announce` items don't pass `AuthorIri` (the original author isn't available without an
  extra fetch; moderation on boosts is deferred).

### `apps/Iris.Web/wwwroot/css/app.css`

- `.engagement-more` — relative-positioned trigger button.
- `.engagement-menu` — absolute-positioned popover (bottom: 100%, right: 0), card background,
  border, shadow, z-index 10.
- `.engagement-menu-item` — full-width button, hover state, disabled state.

### `tests/Iris.Web.Tests/PostModerationIntegrationTests.cs` (new)

6 integration tests booting the real app in-process via `WebAppFactory` + `TestServer`:

1. `Block_RecordsEdgeInModerationStore` — `BlockAsync` → `IsBlockedAsync` returns true.
2. `Flag_RecordsEdgeInModerationStore` — `FlagAsync` → `HasFlaggedAsync` returns true.
3. `Mute_RecordsEdgeInModerationStore` — `MuteAsync` → `IsMutedAsync` returns true.
4. `Unblock_RemovesEdgeFromModerationStore` — Block then `UnblockAsync` (Undo) → edge gone.
5. `Unmute_RemovesEdgeFromModerationStore` — Mute then `UnmuteAsync` → edge gone.
6. `Unflag_RemovesEdgeFromModerationStore` — Flag then `UnflagAsync` (Undo) → edge gone.

Uses a `LocalActorDocumentFetcher` inner class (reads actors from `IPersistenceProvider`
directly) so the server's `HttpSignatureValidator` can resolve the signing key for alice
without a round-trip HTTP fetch (which the TestServer can't serve to itself).

## Design notes

- **Block/Flag are federated** (signed ActivityPub activities delivered to the target's
  inbox); **Mute is local** (Basic-auth POST to the actor's own instance, not federated).
  This mirrors the ActivityPub spec: a block affects all of the blocker's feeds and is
  propagated; a mute is a local content-filtering preference.
- The moderation menu targets the **post author** (the `Create` activity's actor), not the
  post object. Blocking/muting/flagging an actor is the unit of moderation in ActivityPub.
- The menu is hidden for own posts (`AuthorIri == Session.ActorId`) — you can't moderate
  yourself.
- Undo actions (unblock, unmute, unflag) are not exposed in the post-level menu (the user
  would need to find the specific post again). Undo is available from the actor-detail
  moderation tabs (Phase 43.3) and the settings page.
