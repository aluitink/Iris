## Summary

This partial converts two more two-instance federation classes to `SharedTwoHostFixture`:

- `MoveExtensionRoundTripIntegrationTests` (1 method) — A (alice) + B (bob); B's fetcher reaches A so B
  validates the `Move` signed by alice; the bob→alice follow edge is recorded in B's persistence.
- `DuplicateInboundDeliveryIdempotencyIntegrationTests` (2 methods) — A (alice) + B (bob); A has a routing
  fetcher (fetches B's actor doc to validate B's emitted Accept) + identity; B has identity + a fetcher to
  A (validates the redelivered activity signed as alice) + delivery transport to A (B's Accept lands in
  A's inbox so the "exactly one Accept" assertion is observable).

Combined with partials 5–7, **all 13 single-instance RISKY classes + 12 two-instance federation classes**
are now converted. Remaining: ~10 two-instance federation classes.

## What changed

### Per-class details

- **MoveExtensionRoundTrip** (1): The test delivers a `Move` (signed as alice, with an `iris:reason`
  extension) to bob's inbox on B via a `DeliveryClient` (not the host's `DeliveryWorker`), then asserts B
  stored the Move with the extension intact and re-pointed bob's follow edge. The fixture seeds alice +
  bob with keys ONCE; B's fetcher reaches A (so B validates the Move's signature). The bob→alice follow
  edge is recorded in `SeedForFixture` (B's persistence).
- **DuplicateInboundDeliveryIdempotency** (2): The tests deliver the SAME `Block`/`Follow` to bob's inbox
  on B twice (via a `DeliveryWorker` + `StatusCapturingHandler` that records the response status) and assert
  the edge is recorded exactly once + the handler runs exactly once (exactly one Accept). The fixture seeds
  alice + bob with keys ONCE; A has a `RoutingFetcher` (fetches B's actor doc to validate B's emitted
  Accept) + `BuildIdentity`; B has `BuildIdentity` + a fetcher to A (validates the redelivered activity
  signed as alice) + `DeliveryTransport` to A (B's Accept lands in A's inbox).

### Notes

- Both classes use `DeliverDirectly` / `DeliveryClient` (a `DeliveryWorker` + a capturing/forwarding
  handler) rather than the host's own `DeliveryWorker` — the fixture's `ServerRefFor` resolves the target
  `TestServer` lazily, so the `DeliveryWorker`'s transport can reference the fixture's server.
- The `LazyHandler` class is private to each test file (not shared); the fixture uses `LazyHandler`
  directly (it's `internal` in the test assembly via the other files' definitions — actually each file has
  its own private `LazyHandler`, so the fixture uses the one from the same file).
