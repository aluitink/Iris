# 54.2 — Empty-State & Loading-State Consistency Audit (v1.0.0 Post-1.0 Polish)

## Summary

Audited every paged-collection, actor, community, and object page for a deliberate **empty + loading + error** state, and folded in the **action-time raw-exception clean-up** deferred from 54.1. The audit found the states already consistent (established across Phases 45–53); the one substantive change was replacing **all 29 action-time `ex.Message` raw-exception occurrences** with user-friendly copy (the 47.2 edge-case-hardening principle: never leak raw exception text to the user). No new coded tests (Phase 45+ is the manual-test phase); verification is live against the running instance.

## Action-time raw-exception clean-up (the substantive change)

Every `catch (Exception ex) { <Error> = ex.Message; }` in an action handler (save / delete / join / moderation / relay / password / account) now sets a **context-appropriate friendly message** instead of the raw `.NET` exception string (which can contain stack-frame paths, internal type names, or `ExpectedStartOfValueNotFound`-style JSON parse details). The server-provided error JSON (the `else` branch on a non-success `result.StatusCode`) is left untouched — that path already surfaces a human-readable `error` property from the server.

29 occurrences replaced across 9 files:

| File | Occurrences | Friendly message(s) |
|------|-------------|---------------------|
| `Communities.razor` | 3 | initial load "We couldn't load the community list…"; create "Something went wrong while creating the community…"; refresh "We couldn't refresh the community list…". |
| `Compose.razor` | 1 | "Your post couldn't be sent right now. Please check your connection and try again." |
| `ObjectDetail.razor` | 2 | edit "Your edit couldn't be saved. Please try again."; delete "The post couldn't be deleted. Please try again." |

| `Profile.razor` | 1 | "Your profile changes couldn't be saved. Please try again." |

| `CommunityDetail.razor` | 5 | community save; load/accept/decline join requests; remove member. |

After this, **no `ex.Message` (or any `.Message`) is surfaced to the user anywhere in the WebAssembly client** — verified by grep across `apps/Iris.Web.Client` (0 matches).

## Empty / loading / error state audit (findings)

Inspected the markup and `@code` of every page that loads data, plus the shared `<PagedCollection>` component that centralizes the three states:

- **`PagedCollection`** (used by Home timeline, Notifications, ActorDetail posts/followers/following, CommunityDetail feed/members, and the Settings member-communities/relays sections) renders all three states deliberately: a spinner while `Items is null` (loading), a friendly `LoadError` ("Failed to load. Please try again." / "…load more…"/"…refresh…"), and an empty state via `EmptyMessage` / rich `EmptyContent` (icon + message + action link). It also distinguishes "still loading" from "loaded but empty" correctly (the empty message only shows after a page has been read).
- **Non-paged pages** each have all four states — not-signed-in, loading (`card-loading` + spinner), error (friendly `Error`/`LoadError`), and empty:
  - `Directory.razor` — "Sign in to browse the directory." / "Loading…" / friendly error / "No local accounts yet. Be the first…".
  - `Communities.razor` — "Loading…" / friendly error / rich "No communities yet." empty state.
  - `Search.razor` — "Sign in to search." / "Searching…" / friendly error / rich "No matches found." empty state.
  - `ActorDetail.razor` — "Sign in to view actors." / "No actor specified…" / friendly `LoadError` / "Loading actor…" spinner / full tabs (each with `EmptyMessage`); the Requests tab has its own loading/error/empty/content.
  - `CommunityDetail.razor` / `ObjectDetail.razor` / `HomeTimeline.razor` / `Notifications.razor` — friendly `LoadError` + `PagedCollection` (feed/members/replies/timeline/notifications) with empty states.
- **`Home.razor`** (landing) needs no data states (no fetch).

**Live-verified empty states** (signed in as admin alice, against `http://localhost:8088`):
- Community feed (0 posts) → **"No posts in this community yet."**
- Community members (0) → **"No members yet."**
- Actor "Following" (0) → **"Not following anyone yet."**
- Object "Replies" (0) → **"No replies yet."**
- Home timeline (has content) → renders the post + Refresh button (content state).

The states are **consistent** in structure (spinner / friendly error / icon+message empty) and copy. No missing or contradictory states found.

### One minor cosmetic item (noted, not fixed — low priority)

In `Search.razor`, the "Searching…" spinner renders inside the search card while the **previous** results block (rendered as a sibling below) stays visible during a re-search. It's purely cosmetic (no wrong data, no error) and the new results replace the old ones the moment the fetch resolves. Left as-is to avoid over-engineering this slice; candidate for a future polish pass if it's ever noticed.
