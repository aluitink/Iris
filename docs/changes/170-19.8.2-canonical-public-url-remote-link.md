# 170 — Phase 19.8.2: canonical public URL link for remote objects

## Summary

The `ObjectPage` now resolves the **canonical public URL** of a loaded object and shows a **"View on
originating instance"** link when the object is remote (its IRI's host differs from the current
instance's host). The canonical public URL is the object's `url` field (the first URL's Href) when
present, else the object's IRI. This closes the 19.8.2 "canonical public-URL link for remote objects"
sub-item — the last code gate left in 19.8.2 (the like/boost-counts half was closed by 20.4e).

## What changed (code)

- **`samples/SampleBlazorClient/Pages/ObjectPage.razor`**
  - New state property: `CanonicalPublicUrl` (string?) — set on load via `ResolveCanonicalPublicUrl`.
  - New **`public static string? ResolveCanonicalPublicUrl(IObject? doc, Iri? objectIri)`** helper —
    resolves the canonical public URL: the object's `url` field (first URL's Href) when present and
    non-empty, else the object's IRI, else null. Exposed as a static helper so the resolution logic is
    testable in isolation (no full session/client harness needed).
  - New computed property: `IsObjectRemote` — true when the loaded object's IRI host differs from the
    session's dial-base host (the object is on another instance).
  - On load, after the object fetch succeeds: `CanonicalPublicUrl = ResolveCanonicalPublicUrl(ObjectDoc,
    objectIri)`.
  - Markup: when `IsObjectRemote` and `CanonicalPublicUrl` is non-empty, a "This object is from another
    instance. [View on originating instance]" link (rel="noopener" target="_blank") renders under the
    ObjectView.
- **`tests/SampleBlazorClient.Tests/S19ObjectViewQualityTests.cs`**
  - Four new unit tests on `ResolveCanonicalPublicUrl`:
    - `UrlFieldPresent_UsesUrlField` — the `url` field's Href is the canonical public URL.
    - `NoUrlField_FallsBackToIri` — no `url` field → the IRI is the fallback.
    - `UrlFieldEmpty_FallsBackToIri` — `url` field with a null Href → the IRI is the fallback.
    - `NullDocAndIri_ReturnsNull` — null doc + null IRI → null.

## Key types / API

- `ObjectPage.ResolveCanonicalPublicUrl(IObject?, Iri?)` — the canonical public URL resolution (the
  object's `url` field when present, else the IRI). A `public static` helper, tested in isolation.
- `ObjectPage.IsObjectRemote` (computed, private) — drives the link's visibility (host comparison
  against the session's dial base).
- The object's `url` field (`ActivityObject.Url` → first `Link.Href`) — the originating instance's
  public URL for the object.

## Why the `url` field (not just the IRI)

The ActivityStreams `url` field carries the originating instance's **public** URL for the object (e.g.
`https://remote.example/@alice/12345` for a Mastodon-style post), distinct from the ActivityPub IRI
(`https://remote.example/ap/v1/n/1`). When present, the `url` field is the better "view on originating
instance" target (the human-facing public page). The IRI is the fallback (always valid, resolvable).

## Scope / limits

- The link renders only when the object is remote (host mismatch). A local object (host == dial base)
  shows no link (the IRI is already the local deep-link, and the object is on this instance).
- The remote-read/proxying surface (19.1.x) is what makes the remote object *fetchable* in the first
  place (the proxy-fallback handler, S8). This slice adds the canonical-URL *link* on top of that
  (the 19.8.2 deliverable).
- Live/UI verification (a real iris-a → iris-b remote object showing the link in the browser) is a
  19.8.x live item, not a code gate.
