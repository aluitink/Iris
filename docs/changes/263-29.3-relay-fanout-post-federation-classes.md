## Summary

This partial converts two more two-instance federation classes to `SharedTwoHostFixture`:

- `RelayFanOutIntegrationTests` (3 methods) — A (alice) + B (relay); A's `DelegatingFetcher` (relay doc
  from B, self from A) + delivery to B (the relay's inbox); B's fetcher reaches A (validates the fanned-out
  Create); the alice→relay subscription edge is recorded in A's relay store.
- `PostFederationIntegrationTests` (2 methods) — A (alice) + B (erin); A's identity + self-fetcher
  (validates the inbound Create signed by alice) + delivery to B (so the federated Create reaches erin's
  inbox); B's fetcher reaches A (validates the delivered Create); the erin→alice follow edge is recorded in
  A's persistence. Uses `BuildDeliveryWorker` (a `DeliveryWorker` + `DeliveryService` + a minimal host).

Combined with partials 5–8, **all 13 single-instance RISKY classes + 14 two-instance federation classes**
are now converted. Remaining: ~8 two-instance federation classes.

## What changed

### Per-class details

- **RelayFanOut** (3): The tests post a `Create`/`Announce` to alice's inbox on A (via `PostToInboxAsync`,
  a client that signs as alice and routes to A's `TestServer`); A's host `DeliveryWorker` POSTs the activity
  to the relay's inbox on B. The fixture seeds alice + relay with keys ONCE; A's `DelegatingFetcher`
  resolves the relay's actor doc (on B) for delivery-target resolution and every other actor (alice, for
  inbound validation) from A's own actor doc; A's `DeliveryTransport` routes to B; B's fetcher reaches A
  (lazily, via `BuildFetcherForLazy`). The alice→relay subscription edge is recorded in `SeedForFixture`
  (A's relay store).
- **PostFederation** (2): The tests deliver a `Create` to alice's inbox on A (via `BuildDeliveryWorker`,
  a `DeliveryWorker` + `DeliveryService` + a minimal host); A's `CreateActivityHandler` records the post in
  alice's outbox (J-8) and schedules the federated delivery to erin's inbox on B (J-18). The fixture seeds
  alice + erin with keys ONCE; A's identity (for signing outbound deliveries) + self-fetcher (validates the
  inbound Create signed by alice) + `DeliveryTransport` to B; B's fetcher reaches A (lazily, via
  `BuildFetcherForLazy`). The erin→alice follow edge is recorded in `SeedForFixture` (A's persistence).

### Notes

- Both classes use `BuildFetcherForLazy` (a new private helper in each fixture) because the existing
  `BuildFetcherFor` helpers take a `TestServer` directly (which would be created before the server is
  registered in `ServerRegistry`). `BuildFetcherForLazy` takes a `Func<TestServer>` and wraps it in a
  `LazyHandler` so the fetcher's client resolves the target server lazily.
- `PostFederation` uses `BuildDeliveryWorker` (which creates a `DeliveryWorker` + `DeliveryService` + a
  minimal `IHost`) rather than the host's own `DeliveryWorker` — the fixture's `ServerRefFor` resolves the
  target `TestServer` lazily, so the `DeliveryWorker`'s transport can reference the fixture's server.
