# 284 — 32.0: relocate the sample compose stack

> 2026-09-06 · Slice 32.0 · Phase 32 (production social platform app) — step 0 (initial prep)

## What was built

This is Phase 32's **step 0** — initial prep, no new code. The library's sample
federation-test stack (the root `docker-compose.yml`: `iris-a` + `iris-b` + `iris-ui`)
was relocated out of the repo root into `samples/`, freeing the root for the production
app and freeing host port `8088` for `Iris.Web`.

The plan's [production-app-overview.md §6 step 0](../plans/production-app-overview.md)
lists the sub-steps; all were executed in order:

- **(a)** Brought the running sample stack down first
  (`docker compose -f docker-compose.yml down --remove-orphans`) — the file was *not*
  moved out from under running containers (moving it would leave orphaned containers).
- **(b)** `git mv docker-compose.yml samples/docker-compose.yml` (a rename, tracked).
- **(c)** Fixed the three services' `build.context` from `.` to `..` — the file moved one
  directory deeper, but the Dockerfiles still need the repo-root build context
  (the `.dockerignore` lives at the root).
- **(d)** Dropped the `iris-ui` service's now-conflicting `8088:8090` host mapping (kept
  `8090:8090` for local smoke-testing / manual use) and replaced the stale comment that
  explained the 8088 mapping with one explaining *why* it was removed (8088 is now the
  production app's port for `https://iris.luit.ink`).
- **(e)** Updated the command examples that referenced the old path:
  - `scripts/docker-smoke-test.sh` — `COMPOSE_FILE` now points at
    `$REPO_ROOT/samples/docker-compose.yml`.
  - `docs/reference/DEPLOYMENT.md` — the file-table row + the `up` / `down` command
    examples now use `samples/docker-compose.yml`.
  - `samples/SampleServer/README.md` + `samples/SampleBlazorClient/README.md` — their
    quick-start `docker compose` commands now use `samples/docker-compose.yml`.
  - `docs/reference/LIVE_INTEROP_TEST_PLAN.md` — the stack boot command now uses
    `samples/docker-compose.yml`.
- **(f)** Brought the stack back up from its new location and re-ran
  `./scripts/docker-smoke-test.sh` — **passed** (see *Verification* below). The sample UI
  is back on `http://localhost:8090`; `iris-a`/`iris-b` on `8081`/`8082`.
- **(g)** Confirmed the `https://iris.luit.ink` 8088 outage tradeoff explicitly — recorded
  in the [overview's decisions log](../plans/production-app-overview.md#9-decisions-log-fill-in-as-the-agent-resolves-open-questions)
  (accepted: nothing on 8088 until step 5 stands up `iris-web`; no placeholder, because
  there's no real traffic and a placeholder would re-create the squat).

## Verification

- `docker compose -f samples/docker-compose.yml config --quiet` — **OK** (validates from
  the new location).
- `IRIS_COMPOSE_KEEP=1 ./scripts/docker-smoke-test.sh` — **PASSED** end-to-end from the
  new location: all three services healthy; cross-container WebFinger reachability
  (iris-a → iris-b); the UI (index page + `_framework` bootstrap + `icudt .dat`); the
  signed cross-container Follow (a→b, edge recorded on iris-b's followers collection);
  and the proxy fallback (iris-a relays a GET to iris-b). The compose project name
  changed from `workspace` to `samples` (derived from the file's directory), so the
  network/volumes are `samples_iris-net` / `samples_iris-a-data` / `samples_iris-b-data`.
- Post-`up` host-port check: **nothing listens on host `8088`** (the accepted outage);
  `iris-ui` still serves on `8090`; `iris-a`/`iris-b` on `8081`/`8082`.

## Decisions

- **8088 outage accepted, no placeholder.** See the
  [overview decisions log](../plans/production-app-overview.md#9-decisions-log-fill-in-as-the-agent-resolves-open-questions).
  The sample UI remains reachable locally at `http://localhost:8090`; only the public
  `https://iris.luit.ink` (→ host 8088) is down until Phase 32 step 5 (Deployment)
  publishes `iris-web` on 8088.
- **The sample stack was left running** after the smoke test (`IRIS_COMPOSE_KEEP=1`),
  consistent with the repo's convention of keeping the long-lived sample stack up between
  turns; it is now rooted at `samples/docker-compose.yml` (project `samples`).
