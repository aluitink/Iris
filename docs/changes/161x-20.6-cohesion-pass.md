# 161x — Phase 20.6: architecture-cohesion pass

## Summary

Phase 20.6 re-verifies, end to end, that every intended operation holds **after** Phases 20.0–20.5, and that
no layer (client ↔ server ↔ sample UI) contradicts another or hides a "massive overhaul." **Result: the
architecture is coherent.** All nine pillars are confirmed consistent across the three layers. No
contradictions, no stale pre-20.0 client-side id computation, no dead routes, no duplicate
implementations of the same concept. One **documented deferral** (not a contradiction) is recorded as a
known open item.

## Method

A read-only audit of the actual code (not just the docs), pillar by pillar, against the two governing
decisions (055 server-is-object-id-authority, 056 C2S inbox model) and the 20.x change docs. Key claims
were re-verified directly in the source (file:line below). The existing integration suite (1,337 tests,
green) is the executable evidence that each pillar's end-to-end behavior holds.

## Findings / follow-ups

| # | Severity | Pillar | Finding | Fix / disposition |
|---|----------|--------|---------|-------------------|
| 1 | **Low (doc clarity)** | 7 | **Inbound (federated) attachment URL-rewrite is designed (056 (b)) but not implemented** — only the *local authoring* path (upload → post → serve) rewrites to the same origin. A note *received* from a peer with a cross-origin attachment `url` still renders cross-origin (link-out). | **Intentional, documented deferral** — `161v` §"What is deliberately NOT in this slice" scopes it out ("the read path is the *inbound* rewrite; this slice is the local authoring path"). Recorded here as a **known open item** so it is not mistaken for complete. If pursued later: on inbound `Create`/object receipt, download the attachment bytes into `IMediaStore` and rewrite the attachment `url` to `/ap/v1/media/{id}` (the serve path already exists — only the inbound download+rewrite is missing). Self-contained; no layer change. |
| 2 | Info | 2 | "Digest auth" maps to two mechanisms (HTTP-signature `digest` component + Basic auth). | No code change; the ROADMAP phrasing is imprecise, not the code. |
| 3 | Info | 5 | The single authored-content `Id =` (community `Group`) is a documented Decision-055 exception. | No change; already correct. |

**No "massive overhaul" risk.** The layering is clean: the client never mints ids for authored objects,
the server is the sole id authority (055), the C2S inbox is owner-only/no-store with no id rewrite (056),
and media upload/serve is coherent end-to-end. The only open work is the inbound media rewrite (Finding 1),
which is a self-contained, already-scoped follow-up.
