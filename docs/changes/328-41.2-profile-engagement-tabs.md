# 41.2 — Profile engagement tabs (Replies + Likes)

## Summary

The `/profile` page gains a tab bar with three views:

- **Your posts** (default) — the actor's outbox, rendered via `ObjectView` (unchanged behavior).
- **Replies** — inbox `Create` activities whose embedded note has an `InReplyTo` (someone replied to one of your posts).
- **Likes** — inbox `Like` activities (someone liked one of your posts).

## Design decisions

### Inbox-filter (not N+1 per-object collection walks)

The original PLAN description suggested walking the user's outbox notes and fetching each note's `/replies` and `/likes` collections. That's O(n) HTTP calls for n posts — impractical for a profile page with even a modest post count.

Instead, the tabs **filter the user's inbox** client-side. The inbox already contains:
- `Create` activities with `InReplyTo` → replies to your content
- `Like` activities → likes on your content

This is a single paged collection walk (the inbox) with a client-side `Func<IObjectOrLink, bool>` filter — the exact pattern `PagedCollection` already supports via its `ItemFilter` parameter. No new server endpoints, no new client methods, no N+1 problem.

### Reusing `PagedCollection.ItemFilter`

`PagedCollection` already has an `ItemFilter` parameter (added for a prior slice) that excludes non-matching items from the rendered list while still consuming them from the page (so pagination is unaffected). The Profile page passes:
- `IsReply`: `item is Activity { Type: "Create" }` with a non-empty `InReplyTo` on the embedded object.
- `IsLike`: `item is Activity { Type: "Like" }`.

### Rendering

- **Your posts** tab: `ObjectView` (the existing note-renderer).
- **Replies / Likes** tabs: `NotificationRow` (the same "who did what" row the Notifications page uses — verb + actor + target link). This gives the user context (who replied/liked) without requiring a separate fetch of the performer's actor document.

## Tests

5 new integration tests:

1. `ProfilePage_SignedIn_ShowsTabBar` — signed-in `/profile` renders "Your posts", "Replies", "Likes" in the tab bar.
2. `InboxFilter_Reply_DetectsCreateWithInReplyTo` — seeds 4 inbox items (reply, like, follow, plain Create); `IsReply` matches only the reply; `IsLike` matches only the like.
3. `InboxFilter_EmptyInbox_ReturnsEmpty` — empty inbox → no replies, no likes.
4. `InboxFilter_CreateWithoutInReplyTo_IsNotAReply` — a plain `Create` (no `InReplyTo`) is not classified as a reply.
5. `InboxFilter_Like_OnLocalObject_IsDetected` — two `Like` activities → both detected.

Full suite: 0 failures.
