## Recurring patterns

1. **Cookie-auth fallback** (defects 3, 7, 13): the SSR→WASM transition moved the client from
   in-process DI (Basic auth) to cross-request HTTP (cookie auth). Every owner-only endpoint
   needed the same `context.User.FindFirst("actor_iri")` fallback that `ActorDocumentHandler`
   already had. Fixed in: `InboxEndpointHandler`, `LocalMediaUploadHandler`, `LocalMuteHandler`,
   `LocalRelayHandler`.

2. **`PropertyNameCaseInsensitive = true`** (defect 4): the WASM client's `System.Text.Json`
   options did not match the server's camelCase output. Five deserialization sites fixed.

3. **`SameOriginApHandler` ordering** (defect 5): the FQDN→same-origin rewrite must happen
   **before** signing (outermost in the handler chain), or the signature host won't match the
   browser's dial host.

4. **Cache invalidation on writes** (defect 11): collection pages (`following`, `followers`)
   cached with a 60 s TTL were not invalidated after follow/unfollow writes. The outbox publish
   handler and `FollowActivityHandler` now call `InvalidateLocalCollectionPage`.

5. **Docker stale WASM** (defect 14): `wwwroot/_framework/` is build output, not source. It
   must be excluded from the Docker build context (`.dockerignore`) and the WASM project must
   be explicitly restored in the Dockerfile (it is built via a custom MSBuild target, not a
   `ProjectReference`, so the main `dotnet restore` misses it).

## Environment finding (not an app defect)

The nginx reverse proxy caches `/index.html` aggressively (ETag / Last-Modified). During 45.1
verification, a stale cached copy hid the WebCrypto bridge fix until a cache-buster query string
forced a fresh fetch. **Action for deployment runbook:** set `Cache-Control: no-cache` (or a
short TTL) on `/index.html` at the proxy so WASM client updates are not hidden by browser/proxy
caching. This is an environment concern, not an app code issue.
