# 54.20 — AP client proxy fallback for remote object browsing

## Problem

Navigating to a remote actor's page (e.g. `https://mastodon.world/@RayvenMX`) showed no posts,
followers, or following — the collections were empty. Two independent bugs combined to cause this:

### Bug 1: Collection IRIs derived from the URL param instead of the actor doc

`ActorDetail.razor` derived the outbox/followers/following IRIs from the **URL query parameter**
(`?iri=https://mastodon.world/@RayvenMX`) via `OutboxOf()`/`FollowersOf()`/`FollowingOf()`,
producing `https://mastodon.world/@RayvenMX/outbox`. Mastodon does not serve the outbox at the
`@handle` path — it 404s. The canonical path is `https://mastodon.world/users/RayvenMX/outbox`
(the actor doc's `id` is the `/users/` form, and the doc carries explicit `outbox`, `followers`,
and `following` properties).

### Bug 2: Collection items read from `items` but Mastodon uses `orderedItems`

`CollectionPageFactory.FromOrderedCollectionPage` and `ActivityPubClient.ConvertToCollectionPage`
only read the `Items` property (JSON: `items`) from the deserialized collection page. The
ActivityStreams library's `Collection`/`CollectionPage`/`OrderedCollection`/`OrderedCollectionPage`
types expose **both** `Items` (JSON: `items`) and `OrderedItems` (JSON: `orderedItems`). Mastodon
serves its outbox pages with `orderedItems`, not `items` — so `page.Items` was null/empty and the
items were never extracted, even when the page was fetched successfully (200).

## Fix

1. **`ActorDetail.razor`** — Added `ResolveCollectionIri` helper that reads the actor doc's
   `Outbox`/`Followers`/`Following` properties (an `ICollectionOrLink` — a `Link` by its `href`,
   an `Object` by its `id`) when present, falling back to deriving from the doc's canonical `id`.
   The `OutboxIri`/`FollowersIri`/`FollowingIri` properties now use this helper.

2. **`CollectionPageFactory`** — Added `ResolveCollectionItems(Collection)` helper that reads from
   `OrderedItems` first (the ActivityPub canonical form), falling back to `Items`. Updated
   `FromOrderedCollectionPage` to use it.

3. **`ActivityPubClient.ConvertToCollectionPage`** — Updated the `OrderedCollection` and
   `Collection` branches to use `CollectionPageFactory.ResolveCollectionItems` instead of reading
   `collection.Items` directly.

## Verification

- Built Docker image, deployed to `https://iris.luit.ink`.
- Navigated to `https://iris.luit.ink/actor?iri=https://mastodon.world/@RayvenMX`:
  - Outbox fetches from `https://mastodon.world/users/RayvenMX/outbox` (200, not the 404 `@handle` path).
  - **17 posts render** with content, timestamps, and action buttons.
  - Followers/Following tabs fetch from the canonical `/users/` path (200); the list was empty on
    this run due to transient Mastodon 429 rate-limiting on the proxy, not a code bug.
- Local profile page (`/profile`) still renders posts correctly (regression check).
- All tests pass: Core 293/0, Client 154/0, Server 952/0 (17 skips), Web 63/0.
