# 178 — Phase 21.1.3: actor detail — Inbox view (activities delivered to this actor)

## Summary

The actor detail page now shows the **actor's inbox collection** (activities delivered to this actor)
via `GET /ap/v1/u/{handle}/inbox`, paged with `next`-link walking. Each item is an activity (a Follow,
Like, Announce, Create, etc.) that was delivered to this actor, shown with its type and IRI.

This exercises `GetCollectionAsync(inboxIri)` from the detail page.

## What changed (code)

- **`samples/SampleBlazorClient/Pages/ActorDetail.razor`**
  - **Markup:** a new "Inbox" card (between the "Moderation (this actor's collections)" card and the
    "Follow / unfollow" card). It shows the actor's inbox collection (paged, each item showing the
    activity's type and IRI).
  - **State:** `InboxItems`/`InboxHasMore`/`InboxLoadingMore`/`InboxError`/`_inboxResumeFrom`.
  - **`LoadMoreInboxAsync`**: the method that loads the next page of the inbox.
  - **`EnumerateOneInboxPageAsync`**: the method that enumerates one page of the inbox (using
    `actorIri.InboxOf()`).
  - **Initial load:** the first page of the inbox is loaded in `OnParametersSetAsync` (after the target
    moderation collections are loaded), so the card is populated on initial load.

## Key types / API

- `actorIri.InboxOf()` — the IRI extension method that derives the inbox IRI (e.g.
  `https://host/u/alice/inbox`).
- `client.GetCollectionAsync(iri, null, ct)` — the client method that reads a collection (paged).

## Direction note: sample-client UI is manual-tested (not bUnit-tested)

Per the current direction, the sample-client UI is **in flux and subject to a lot of change** once core
stuff is worked out. Rather than invest in bUnit tests for the sample UI (which would need to track every
UI change), the sample UI is **verified manually** (drive the screens through the browser). This change
follows that direction: the Inbox card is wired and builds clean, but has no bUnit test. The underlying
wire (the inbox collection read) is proven by the existing server/client integration tests.

## Scope / limits

- The **live/UI-verification half** of 21.1.3 (drive the inbox view through the browser — log on, view
  an actor's detail, see their inbox, confirm the activities are shown) remains a live-verification
  item. The code (the card + the `LoadMoreInboxAsync` method + the `EnumerateOneInboxPageAsync` method)
  is in and builds clean.
- The inbox items are shown with their **type and IRI** (not a full activity rendering). A future
  enhancement could render the full activity (who did what) with links to the involved actors/objects.
