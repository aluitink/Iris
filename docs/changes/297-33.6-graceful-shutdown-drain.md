# 33.6 — graceful-shutdown verification + explicit timeout

**Phase:** 33 (server production-readiness & hardening), step 6.
**Status:** COMPLETE.

## Problem

The `DeliveryWorker`'s shutdown drain was **unbounded** on a host shutdown. When the host's stopping
token was cancelled (SIGTERM), the `ExecuteAsync` drain loop waited for in-flight deliveries to settle
with no time limit. A hung peer (a network call that ignores cancellation — a blackholed TCP
connection, a peer that accepts the connection but never responds) could block `StopAsync`
indefinitely, exceeding the host's 30 s `HostOptions.ShutdownTimeout` and forcing the OS to kill the
process.

## Change

### Bounded drain in `DeliveryWorker.ExecuteAsync`

The drain loop now **bounds the wait** by a new `Iris:Delivery:ShutdownDrainTimeout` config (env
`IRIS_SHUTDOWN_DRAIN_TIMEOUT`):

- **Host shutdown** (stopping token cancelled): the drain starts with the full budget. A delivery
  that does not finish in time is dropped — it is journaled by the file-backed queue (or
  dead-lettered per the F-22 at-least-once policy) and re-driven on the next run.
- **Normal stop** (queue completed and emptied without any cancellation): the drain is unbounded —
  there is no shutdown in flight to bound it for.
- The **budget timer** uses `CancellationToken.None` (not the stopping token, which is already
  cancelled on a host shutdown) so it actually counts down.

### Config resolution

`DeliveryWorker.ResolveShutdownDrainTimeoutMs(IConfiguration?)` parses the config value:

- A `TimeSpan` format (e.g. `00:00:15` for 15 s, `00:00:00.300` for 300 ms).
- A bare integer (interpreted as **seconds**; e.g. `30` → 30 000 ms).
- Falls back to `DefaultShutdownDrainTimeoutMs` (60 000 ms) on unset, garbage, or negative.

### Constructor + DI wiring

- `DeliveryWorker` gains a new `IConfiguration?` constructor param (the host-driven overload).
  The `IConfiguration` is read once at construction via `ResolveShutdownDrainTimeoutMs`.
- `ActivityPubServerExtensions.AddActivityPubServer` passes
  `sp.GetRequiredService<IConfiguration>()` to the `DeliveryWorker` factory.

### App-level wiring

- `WebAppFactory` adds `ShutdownDrainTimeoutConfigKey` + `DefaultShutdownDrainTimeout` (15 s —
  fits under the 30 s host budget).
- Step 9a sets `HostOptions.ShutdownTimeout` from the same config, so the host's own shutdown
  timeout and the worker's drain budget are aligned.

| Test | Asserts |
|---|---|
| `ResolveShutdownDrainTimeout_BindsFromConfiguration` (theory, 5 cases) | null → default; `00:00:45` → 45 000 ms; `00:00:12` → 12 000 ms; `garbage` → default; `-5` → default |

| 5 more config/edge cases | drain budget edge cases |
