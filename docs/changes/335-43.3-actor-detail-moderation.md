# 43.3 — Moderation on actor detail (Block/Mute/Report + community join-request queue)

**Status:** COMPLETE
**Commit:** `7a16c0c`
**Tests:** 8 new integration tests (full suite: 1249 passing)

## What

This slice completes Phase 43 by putting moderation on the **actor detail page** (`/actor?iri=…`),
where a user views another actor's profile — and adding the community **join-request queue** to the
same page.

### Moderation actions on another actor

Next to the Follow button, a `ModerationActions` control renders for any actor that isn't the
signed-in user. It offers:

- **Block** — `IActivityPubClient.BlockAsync(me, target)`: a signed `Block` delivered to the
  target's inbox; the server records the block edge.
- **Report** — `IActivityPubClient.FlagAsync(me, target)`: a signed `Flag` (a report; does not
  sever the relationship).
- **Mute** — `ILocalModerationClient.MuteAsync(me, target)`: a local Basic-auth request; the server
  records the mute edge (not federated).

On load, the control reads the signed-in actor's **blocks** and **mutes** collections
(`client.GetBlocksAsync(me)` / `client.GetMutesAsync(me)`) and checks whether the target appears.
If already blocked, the button shows **Unblock** (which sends `Undo` of the minted block IRI);
if muted, it shows **Unmute**. Block and Mute are mutually exclusive in the button set (you can't
both block and mute the same actor), and both buttons disable while a request is in flight.

### Community join-request queue

When the viewed actor is a **community** (`Group`) with `manuallyApprovesMembers` enabled, a
**Requests** tab appears in the actor detail tab bar. It lists the pending join requests
(`ILocalModerationClient.GetCommunityJoinRequestsAsync(communityIri)`, a JSON array of actor IRIs)
with **Accept** / **Reject** buttons. Accept adds the actor as a member and removes the request
(`AcceptCommunityJoinRequestAsync`); Reject removes the request without adding membership
(`RejectCommunityJoinRequestAsync`). The same local endpoints the community detail page uses —
re-exposed on the actor detail page so the queue is reachable from the community's public profile.

## Changes

### `apps/Iris.Web/Components/ModerationActions.razor` (new)

- Renders only when a client, a local-moderation client, a signed-in actor, and a non-self target
  are all present.
- Button set: `Block`/`Mute`/`Report` when not blocked and not muted; otherwise `Unblock` (if
  blocked) and/or `Unmute` (if muted).
- `OnParametersSetAsync` reads the blocks/mutes collections once per target (guarded by
  `_lastTargetIri`) to set `IsBlocked`/`IsMuted`.
- `BlockAsync`/`UnblockAsync`/`FlagAsync` via `Client`; `MuteAsync`/`UnmuteAsync` via
  `LocalModeration`. Stores `result.MintedId` for the block/flag so Undo can reference the exact
  activity IRI (Decision 055).
- `ContainsIriAsync` helper normalizes collection items (`IObject.Id` / `Link.Href`) and compares
  case-insensitively to the target IRI.

### `apps/Iris.Web/Components/Pages/ActorDetail.razor`

- Renders `<ModerationActions TargetActor="ActorDoc" />` in the header for non-self actors.
- New **Requests** tab in the tab bar, shown when `ShowJoinRequestsTab` is true.
- `IsCommunity` (`ActorDoc is Actor { Type: "Group" }`), `ApprovesMembers`
  (`ActorDoc.GetManuallyApprovesMembers() == true`), `ShowJoinRequestsTab`
  (`IsCommunity && ApprovesMembers`).
- `SwitchTab("requests")` triggers `LoadJoinRequestsAsync` lazily on first open.
- `LoadJoinRequestsAsync` / `AcceptJoinRequestAsync` / `RejectJoinRequestAsync` mirror the
  community detail page: read the JSON `List<string>` body, accept/reject via the local-moderation
  client, and reload the list on success.

### `apps/Iris.Web/wwwroot/css/app.css`

- `.moderation-actions` (inline-flex, gap, left margin) for the header button row.

### `tests/Iris.Web.Tests/ActorDetailModerationIntegrationTests.cs` (new)

8 integration tests booting the real app in-process via `WebAppFactory` + `TestServer`:

1. `BlockOnActorDetail_RecordsEdge` — `BlockAsync` → `IsBlockedAsync` true.
2. `MuteOnActorDetail_RecordsEdge` — `MuteAsync` → `IsMutedAsync` true.
3. `ReportOnActorDetail_RecordsEdge` — `FlagAsync` → `HasFlaggedAsync` true.
4. `UnblockOnActorDetail_RemovesEdge` — Block then `UnblockAsync(MintedId)` → edge gone.

The constructor seeds a community (`Group`) with a signing key in **both** key stores and registers

itself over a real `HttpClientHandler`).

## Design notes

- **Block/Report federate; Mute is local.** Same split as 43.1: a block/flag is a signed
  ActivityPub activity delivered to the target; a mute is a local preference (Basic-auth POST) that
  never leaves the instance.
- **Undo references the minted IRI, never a recomputed formula** (Decision 055). The block/flag
  `MintedId` is captured on the action and reused by the Undo.
- **State is read from the collections, not the moderation store, client-side.** The control
  enumerates the signed-in actor's public blocks/mutes collections (the same data the UI would show
  in a "blocked/muted" list), keeping the component decoupled from the server's `IModerationStore`.
- The community join-request queue on the actor detail page reuses the **exact same local endpoints**
  as `CommunityDetail` — no new server surface; the page just gives the community's public profile a
  place to review its pending joiners.
