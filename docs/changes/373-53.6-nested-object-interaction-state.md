# 53.6 — isLiked/isShared on Nested Objects + likedCount/sharedCount

## Summary

Two related enhancements to collection-page items:

1. **`likedCount`/`sharedCount` on nested objects**: When serving the outbox or feed, `Create` activities with embedded content objects now carry `iris:likedCount` and `iris:sharedCount` (the number of distinct likers/announcers from the reverse-index stores). These are cacheable, per-object counters — safe to serve from the local collection-page response cache.

2. **`isLiked`/`isShared` on nested objects (feed only)**: When serving the feed (which is not cached), an authenticated requester's net like/boost state on the embedded object is rendered as `iris:isLiked`/`iris:isShared` — the same per-requester extensions already available on the object-document endpoint, now also available on feed items so the timeline can render like/boost state without extra requests.

## Changes

### `Iris.Core`
- `IrisExtensionTerms`: Added `LikedCount` and `SharedCount` constants.

### `Iris.Server`
- `ActivityPubServerExtensions.EnrichCollectionItemsAsync`: New helper that deep-copies collection-page items (activities with embedded objects) and annotates the embedded object with `likedCount`/`sharedCount` (and optionally `isLiked`/`isShared` when a requester IRI is supplied).
- `CollectionEndpointHandler` (outbox): Enriches outbox items with `likedCount`/`sharedCount` before rendering (inside the cache's render callback, so the cached document includes the counts).
- `FollowFeedHandler`: Resolves the authenticated requester via `ISignatureValidator`, enriches feed items with `likedCount`/`sharedCount` + `isLiked`/`isShared`, and passes the enriched items to the document builder.
- `BuildNamespaceDocument`: Declares `likedCount`/`sharedCount` as `integer` terms.

## Design Decisions

- **Outbox gets counts only** (no per-requester state): the outbox is served through the `LocalCollectionPageCache`, so per-requester `isLiked`/`isShared` would be cached and wrong. Counts are cacheable.
- **Feed gets counts + per-requester state**: the feed is not cached (it merges remote outboxes on every request), so per-requester state is safe.
- **Object document endpoint unchanged**: it already has `isLiked`/`isShared` from prior work. `likedCount`/`sharedCount` could be added there too, but that's a follow-up (the object endpoint is cached with a 60s TTL, and counts are cacheable, so it would be safe — deferred to keep this slice focused).
