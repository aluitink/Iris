# 55.2 — Federation Interop Hardening: Live Cross-Instance Verification

## Summary

Stood up a second Iris instance (`iris-dev2.luit.ink`, port 8082) alongside the production
instance (`iris.luit.ink`, port 8088) on the shared Docker network. Verified cross-instance
reachability in both directions. Live-tested remote actor search (carol on iris-dev2 → alice
on iris.luit.ink). **Found and fixed a critical federation defect**: the WASM client's static
`Iris:AdvertiseBase` config (`appsettings.json`) was hardcoded to `https://iris.luit.ink`,
causing the client on iris-dev2 to treat iris.luit.ink as its own instance (same-origin),
bypassing the proxy and fetching local actor docs instead of remote ones.

## Defect: Hardcoded AdvertiseBase Broke Multi-Instance Deployment

**Root cause:** The WASM client's `appsettings.json` had `Iris:AdvertiseBase =
"https://iris.luit.ink"` (hardcoded to the production instance's FQDN). When the same WASM
build was deployed to iris-dev2, the client's `advertiseBase` was still `https://iris.luit.ink`
(instance 1), not `https://iris-dev2.luit.ink` (instance 2). This caused:

1. `DialBaseUri` = `https://iris.luit.ink` → the `ProxyFallbackHandler`'s cross-instance-read
   check (`readUri.Host != dialBase.Host`) saw `iris.luit.ink == iris.luit.ink` and did NOT
   route through the proxy.
2. `SameOriginApHandler` (advertise base = `https://iris.luit.ink`) rewrote
   `https://iris.luit.ink/ap/v1/u/alice` to `https://iris-dev2.luit.ink/ap/v1/u/alice`
   (same-origin), so the browser fetched the **local** instance's actor doc.
3. The local instance served a local actor doc for `alice` with the local IRI — wrong posts,
   wrong follower count, wrong follow target.

**Fix:** In `Program.cs`, when the static `AdvertiseBase` host differs from the browser's
origin host, use the browser's origin as the advertise base. This ensures the session's
ActivityPub clients rewrite the correct host to same-origin and route cross-instance reads
through the correct proxy. The fix is a no-op for single-instance deployments (where the static
AdvertiseBase matches the browser origin).

**Before fix (network trace):**
```
POST /ap/v1/proxy/https%3A%2F%2Firis.luit.ink%2F.well-known%2Fwebfinger...  → 200 (proxy, correct)
POST /ap/v1/proxy/https://iris-dev2.luit.ink/ap/v1/search?q=...             → 200 (proxy, local search)
POST /ap/v1/proxy/https%3A%2F%2Firis.luit.ink%2Fsearch%3Fq%3D...             → 200 (proxy, remote search)
GET  /ap/v1/u/alice                                                        → 200 (DIRECT, local instance — BUG)
```

**After fix:** The remote actor IRI is fetched through the proxy (cross-instance read path
engages correctly). The search result links to `/actor?iri=https://iris.luit.ink/ap/v1/u/alice`
(correct remote IRI). The actor profile shows alice's real posts (4), followers (1), following
(1), and a working Follow button. 0 console errors.
