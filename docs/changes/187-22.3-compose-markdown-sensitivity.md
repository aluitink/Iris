# 187 — Phase 22.3: compose — Markdown content + content-sensitivity (US-11)

## Summary

Closes **US-11** (compose a note "with media, markdown, sensitivity") and with it **Phase 22.3
(authoring surfaces)**. The Compose page already had media (image `InputFile` upload, attached as an
`Image` attachment with a same-origin `Url`) and audience/reply (`as:Public` / actor IRIs, `ParentIri`
+ `@mention` tags). This adds the two missing authoring capabilities:

- **Markdown content.** A "Markdown" toggle. When enabled, the typed content is rendered to safe HTML
  by the dependency-free `Markdown.ToHtml` renderer (Phase 20.4c — the same renderer `ObjectView`
  uses to display content) before it is posted, so the stored `content` is HTML and the note displays
  formatted (headings, bold, italic, links, lists, code). When off, the content is posted exactly as
  typed (no change to the existing plain/HTML path).
- **Content sensitivity.** A "Mark as sensitive" toggle + a "Sensitivity summary" input (enabled only
  when sensitive). When set, the note carries the ActivityStreams `sensitive` flag (in `ExtensionData`
  — the representation `IriExtensions.IsSensitive` reads) and, when a summary is entered, the AS
  `summary` term (the preview a client shows in place of a sensitive note's content until revealed).

A **rendering fix** was required for the Markdown half to display correctly: `ObjectView` previously
ran *all* content through `Markdown.ToHtml`, which HTML-escapes its input — so content that was
already pre-rendered HTML (a Markdown-rendering client's output) would be escaped and shown as literal
text. `ObjectView` now emits pre-rendered HTML verbatim and only runs the Markdown transform on
content that is not already HTML (a new pure, unit-tested detector
`IriExtensions.IsPreRenderedHtmlContent`).

## What changed (code)

- **`src/Iris.Core/Compose/ComposeNote.cs`** (new) — `ComposeNote.Build(...)`: builds an authored
  `Note` from raw inputs (actor, content, optional pre-rendered Markdown HTML, sensitivity flag +
  summary, audience). A small, dependency-free, unit-testable composition helper for the note's wire
  shape (content / `attributedTo` / `sensitive` / `summary` / `to`). The Compose page inlines the same
  shape (it must additionally attach the uploaded `Image`); the helper is the canonical, tested
  expression of the US-11 composition.
- **`src/Iris.Core/Identity/IriExtensions.cs`** — new `IsPreRenderedHtmlContent(IObject?)`: a heuristic
  detector (content starting with a block-level HTML tag → pre-rendered HTML; else Markdown/plain).
  Drives `ObjectView`'s render choice.
- **`samples/SampleBlazorClient/Pages/Compose.razor`** — new "Markdown" checkbox + "Mark as sensitive"
  checkbox + "Sensitivity summary" input (disabled unless sensitive); state `IsMarkdown`,
  `IsSensitive`, `Summary`; `RenderedContent()` (Markdown → `Markdown.ToHtml`, else verbatim) applied
  in both the attachment and plain note branches; `ApplySensitivity(note)` (sets `sensitive` in
  `ExtensionData` + `summary` when set). The `disabled` attribute uses the codebase's boolean idiom
  (`disabled="@(!IsSensitive)"`) — a string-ternary (`@(x ? "" : "disabled")`) does not clear the
  attribute on re-render.
- **`samples/SampleBlazorClient/Components/ObjectView.razor`** — `RenderedContent` now emits the
  content verbatim when `IsPreRenderedHtmlContent` is true, else runs it through `Markdown.ToHtml`
  (preserving the existing safe-HTML-from-Markdown behavior for Markdown/plain content).

## Key types / API

- **`Iris.Core.Compose.ComposeNote.Build(Iri actorId, string content, string? markdownHtml = null,
  bool sensitive = false, string? summary = null, IEnumerable<Iri>? to = null)`** → `Note`. Pure
  composition; no I/O. `sensitive` is written to `ExtensionData["sensitive"]` (initialized first —
  `Note.ExtensionData` is null on a fresh note) as `SerializeToElement(true)`; `summary` to the AS
  `Summary` property (only when sensitive + non-blank).
- **`IriExtensions.IsPreRenderedHtmlContent(IObject?)`** → `bool`. Inspects the first non-empty
  content value; true when it begins (after leading whitespace) with a block tag (`<p`, `<h1`–`<h6`,
  `<ul`, `<ol`, `<pre`, `<blockquote`, `<table`, `<div`), case-insensitive.
- No `Iris.Client` API change: `PostNoteAsync(Iri, Note, ct)` is the pre-existing delivery seam
  (wraps the `Note` in a `Create`, delivers to the actor's outbox, signed).

## Decisions

- **Markdown is rendered client-side, before posting; the stored `content` is HTML.** The dependency-free
  `Markdown.ToHtml` (already the renderer `ObjectView` uses) is reused on the compose side. Posting
  HTML (rather than Markdown source + a client-side render flag) keeps the wire AP-native and lets any
  reader (including `ObjectView`) display the content without re-deriving it. `Markdown.ToHtml`
  HTML-escapes its input and sanitizes link schemes (`http`/`https`/`mailto` only), so the output is
  safe to store and emit.
- **Pre-rendered HTML is emitted verbatim by `ObjectView`; Markdown source is rendered.** Because a
  Markdown-rendering client posts HTML, `ObjectView` must not run that HTML through the Markdown
  renderer again (it would be escaped and shown as literal text). `IsPreRenderedHtmlContent`
  distinguishes the two by a leading block tag (Markdown source never begins with one), so content
  authored as Markdown renders, content authored as pre-rendered HTML passes through, and
  Markdown/plain content from other clients is unaffected.
- **`sensitive` lives in `ExtensionData`; `summary` is a typed AS property.** `sensitive` is not modeled
  as a property by the ActivityStreams library, so it is carried in `ExtensionData` (the same
  representation the seeded fixtures, `MastodonExtensionPassthroughIntegrationTests`, and
  `IriExtensions.IsSensitive` already use). `summary` is a real AS property (`IEnumerable<string>`)
  and is set directly. Both round-trip through `ActivityJson`.
- **`ComposeNote.Build` is a tested helper even though the page inlines the shape.** The page must
  attach the uploaded `Image`, so it cannot simply call `Build` and be done; but the US-11 composition
  (content / attribution / sensitivity / summary / audience) is worth a small, dependency-free,
  unit-testable unit in `Iris.Core` so the wire shape is verified in `Iris.Core.Tests` rather than only
  by a manual browser run.

## Scope / limits

- This closes **US-11** (compose with media, markdown, sensitivity) and **Phase 22.3** (authoring
  surfaces; the reply form / US-12 was already done under 22.2, change 186).
- Markdown rendering is the dependency-free `Markdown.ToHtml` subset (headings, inline/fenced code,
  links, lists, paragraphs) — not a full CommonMark engine. Raw HTML in the compose input is escaped
  (rendered as text), never injected — consistent with the object view's security posture.
- The sensitivity `summary` is shown only when "Mark as sensitive" is checked (the input is disabled
  otherwise); a sensitive note with no summary shows the default "This content may be sensitive."
  notice with no preview text.
- **22.3 is now complete.** Remaining Phase 22 work: 22.4 (cross-server polish — US-8, US-2, US-24),
  22.5 (broad story review), 22.6 (implementation sweep + manual test pass).
