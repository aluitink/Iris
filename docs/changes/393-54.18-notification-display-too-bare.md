# 54.18 — Notification display is too bare

Phase 54 slice. The notification list rendered each inbox activity as a minimal text row: a small
SVG icon, a verb ("liked your post"), the actor's **handle** (not display name), and a relative
timestamp — with no actor **avatar** and no actor **display name**. The slice asked for a richer
notification item: actor avatar, actor display name, a snippet/preview of the referenced post, a
relative timestamp, and a link to the post.

## Root cause

`NotificationRow.razor` read the activity's `actor` property as an IRI link and rendered only
`HandleOf(performer)` (the last path segment, e.g. "andrew") — it never fetched the actor's document,
so it had no access to the actor's `name` (display name) or `icon` (avatar). The row's layout was a
flat flex row (icon + verb + handle + time) with no room for an avatar.

## Change

1. **Fetch the actor's document and render avatar + display name**
   ([NotificationRow.razor](../../apps/Iris.Web.Client/Components/NotificationRow.razor)):
   - Injected `UiContext` (the per-circuit actor-document cache, 5-minute TTL) and added
     `OnInitializedAsync` to fetch the activity's actor document via `Ui.GetActorAsync(iri)`. The
     `UiContext` already caches actor documents per-circuit, so repeated rows for the same actor do
     not re-fetch — the N+1 is bounded by the number of distinct actors in the visible page.
   - Added a `Dictionary<string, IObject?> _actorDocs` to hold the fetched document (keyed by actor
     IRI value) so the render block can read it.
   - **Display name:** the row now renders `displayName` (the actor doc's `Name?.FirstOrDefault()`)
     in a `.notification-name` link, falling back to `HandleOf(performer)` when the actor doc has no
     name or hasn't loaded yet.
   - **Avatar:** added a `.notification-avatar` element (1.75rem circular) that renders an `<img>`
     when the actor doc has an `icon` (first icon's IRI, rewritten same-origin via
     `RewriteMediaToSameOrigin` — the same helper `ObjectView` uses), or an initial-letter fallback
     (`.notification-avatar-fallback`) when there is no icon. The `AvatarInitial` helper picks the
     first alphanumeric character of the display name or handle.
   - Added `ActorIconIri` (reads the first icon's IRI from the actor doc, mirroring
     `Profile.razor`'s `GetIconIri`) and `RewriteMediaToSameOrigin` (absolute https → same-origin
     path, mirroring `ObjectView.RewriteMediaToSameOrigin`).

2. **Re-layout the row** (NotificationRow.razor): the row's inner content is now a
   `.notification-body` flex container with the avatar on the left and a `.notification-content`
   (flex: 1, min-width: 0) on the right holding the existing `.notification-head` (name + icon + verb
   + time) and `.notification-target` (preview link) unchanged. The name link is now the first
   element in the head (before the SVG icon), so the visual order is: **name · icon · verb · time**.

3. **CSS** ([app.css](../../apps/Iris.Web.Client/wwwroot/css/app.css)): added
   `.notification-body` (flex, gap 0.6rem), `.notification-avatar` (1.75rem circular, border,
   overflow hidden), `.notification-avatar img` (1.75rem, object-fit cover), `.notification-avatar-
   fallback` (0.8rem bold accent), `.notification-content` (flex: 1, min-width: 0), and
   `.notification-name` (bold, accent on hover).

    stale-blob issue).

## Design decision

The actor document is fetched **client-side** per-row via `UiContext.GetActorAsync` (the per-circuit
cache), rather than adding a server-side enrichment step to the inbox endpoint. This avoids a new
server code path and reuses the existing cache infrastructure. The N+1 is bounded by the number of
distinct actors in the visible page (10 rows), and the 5-minute TTL means a full page re-render
after the first fetch is cache-only. A server-side enrichment (stamping `iris:actorName`/
`iris:actorIcon` onto inbox activities, like the 54.8 `iris:likedCount` stamping) would be more
efficient for large inboxes but is out of scope for this slice; it can be a follow-up if inbox
performance becomes an issue.
