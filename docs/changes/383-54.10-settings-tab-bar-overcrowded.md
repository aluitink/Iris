# 54.10 — Settings tab bar overcrowded

Phase 54 slice. The Settings tab bar (Account / Password / Notifications /
Communities / Relays / Moderation / Danger — 7 tabs) was becoming squished as
tabs accumulated. The slice called for folding the Password tab's
change-password form into the Account tab to drop a tab and free up space.

## Change

[Settings.razor](apps/Iris.Web.Client/Components/Pages/Settings.razor):

- **Dropped the `Password` tab** from the tab bar (7 tabs → 6: Account,
  Notifications, Communities, Relays, Moderation, Danger).
- **Moved the change-password form into the Account tab** as a native
  `<details class="settings-subsection">` collapsible, placed below the
  `ActorProfile` + "Edit your profile" link inside the same card. The
  `<summary>` reads "Change password"; expanding it reveals the existing
  three-field form (current / new / confirm) + the "Change password" button.
- **Removed the `ActiveTab == "password"` render branch** (the form markup now
  lives in the Account branch). All password state fields
  (`CurrentPassword` / `NewPassword` / `ConfirmPassword` / `PasswordBusy` /
  `PasswordError` / `PasswordSuccess`) and `ChangePasswordAsync` are unchanged —
  they're still referenced, just rendered in the Account tab now.
- The `SwitchTab` method needed no change (it had no `password` case — the
  password form carried no lazy-load, only the other tabs do).

[app.css](apps/Iris.Web.Client/wwwroot/css/app.css) (mirrored to
[apps/Iris.Web/wwwroot/css/app.css](apps/Iris.Web/wwwroot/css/app.css)):

- Added `.settings-subsection` (top border + top padding, `margin-top`),
  `.settings-subsection-summary` (cursor pointer, bold, hidden default
  marker), a `::before` chevron (`▸`) that rotates 90° when the `<details>`
  is `[open]`, and `.settings-subsection-body` (top margin). Native
  `<details>`/`<summary>` — no JS, keyboard-accessible, matches the app's
  existing card/panel visual language (`var(--panel)`, `var(--border)`,
  `var(--muted)`).

## Why a native `<details>`

A `<details>`/`<summary>` gives the collapsible behavior with zero JavaScript
and full keyboard/AT support for free (it's a real disclosure widget in the
accessibility tree). It fits the app's otherwise-JS-light, CSS-class-driven
visual language and avoids adding a dependency or a state field to track
open/closed. The chevron is a CSS `::before` so the summary text stays plain.
