# 163 — Phase 19.8.3: actor detail completeness (followers/following + raw inspector)

## Summary

The `ActorDetail` page now renders the actor's **followers** and **following** collections (paged with
`next`-link walking, each item a clickable link to the follower/followed actor's detail) and a **raw
inspector** (the actor document as formatted JSON — the explicit escape hatch for inspecting the raw
ActivityStreams/ActivityPub representation). This closes the 19.8.3 gaps: "every collection (with
correct counts matching the wire)" and "the raw inspector as an explicit escape hatch (not the default
view)."

## What changed (code)

- **`samples/SampleBlazorClient/Pages/ActorDetail.razor`** — three new UI sections added between the
  outbox and the moderation cards:
  - **Followers** card: paged list of the actor's `followers` collection items (each an `ILink` bare
    actor IRI, per the server's `ActorIrisToLinks` serialization). Each item renders as a link to
    `/actor?iri={href}` (the follower's actor detail). "Load more" walks `next` links (mirrors the
    outbox paged idiom, 20.3).
  - **Following** card: identical structure for the actor's `following` collection.
  - **Raw inspector** card: a "Show raw JSON" / "Hide raw JSON" toggle that renders the actor document
    (`ActorDoc`) as indented JSON (`System.Text.Json.JsonSerializer.Serialize` with
    `WriteIndented = true` + `JavaScriptEncoder.UnsafeRelaxedJsonEscaping`). The raw JSON is generated
    once at load time (not per-render) and stored in `RawJson`.
  - New `@code` state: `FollowersItems`/`FollowersHasMore`/`FollowersLoadingMore`/`FollowersError`/
    `_followersResumeFrom`, `FollowingItems`/`FollowingHasMore`/`FollowingLoadingMore`/`FollowingError`/
    `_followingResumeFrom`, `ShowRaw`/`RawJson`.
  - New methods: `LoadInitialFollowersAsync`, `LoadMoreFollowersAsync`, `EnumerateOneFollowersPageAsync`,
    `LoadInitialFollowingAsync`, `LoadMoreFollowingAsync`, `EnumerateOneFollowingPageAsync` (all mirror
    the outbox paged idiom: `GetCollectionAsync` against `actorIri.FollowersOf()` /
    `actorIri.FollowingOf()`, breaking after the first yielded page per "Load more" click).
  - New `HandleOf(string iri)` overload: extracts the path's last segment (the username) from an actor
    IRI string for display (the followers/following items are `ILink` bare IRIs, not full actor objects,
    so the existing `HandleOf(IObject)` doesn't apply).
  - The item rendering handles both `ILink { Href: ... }` (the actual server shape) and `IObject { Id:
    ... }` (defensive, for a future server change that serves full actor objects).

## Key types / API

- `IriExtensions.FollowersOf(this Iri)` / `IriExtensions.FollowingOf(this Iri)` — the collection IRI
  derivations (pre-existing; now used by the UI).
- `IActivityPubClient.GetCollectionAsync(Iri, CollectionQuery?, CancellationToken)` — the paged
  collection read (pre-existing; now used for followers/following in the UI).
- Server-side: `ActorIrisToLinks` (in `ActivityPubServerExtensions`) serializes followers/following
  items as `Link { Href = new Uri(iri) }` — `ILink` objects, not full actor documents.

## New tests (4, all passing)

- **`tests/SampleBlazorClient.Tests/S19ActorDetailCompletenessTests.cs`** (new):
  - `ActorDetail_FollowersCollection_ContainsFollowers` — after bob follows alice,
    `GetCollectionAsync(alice.FollowersOf())` returns bob as an `ILink` item.
  - `ActorDetail_FollowingCollection_ContainsFollowed` — after alice follows bob,
    `GetCollectionAsync(alice.FollowingOf())` returns bob as an `ILink` item.
  - `ActorDetail_RawJson_SerializesActorDocument` — the actor document serializes to valid, parseable
    JSON carrying the actor's `id` and `preferredUsername` (the raw inspector's input).
  - `ActorDetail_FollowersFollowing_EmptyByDefault` — both collections are empty before any follows are
    made (the page renders "No followers recorded." / "Not following anyone.").
