# 58.3 — Rich attachment rendering (F-11)

## Summary

Replaced the Image-only media attachment rendering in `ObjectView` with a rich attachment renderer
that handles all AS2.0 attachment types: `Image`, `Document`, `Audio`, `Video`, and plain `Link`.

- **Image** attachments render as a plain `<img>` (same as before).
- **Document** / **Audio** / **Video** / **Link** attachments render as a card with:
  - A type-appropriate icon (📄 / 🎵 / 🎬 / 📎).
  - A preview image thumbnail when the attachment carries a `preview` property.
  - The attachment name (or URL) as a clickable link (opens in a new tab).
  - The attachment type label (uppercase, muted).

This is the **inbound read path** for rich attachments. Outbound posts do not emit non-Image
attachments (Iris has no document/audio/video upload feature yet); this slice is purely the
inbound rendering of attachments that arrive via federation or direct API insertion.

## Changes

### `RichAttachment` record + `GetRichAttachments()` (Core)

- `RichAttachment(string? Type, string? Name, Iri Url, Iri? Preview)` — namespace-level record in
  `Iris.Core.Identity`.
- `IriExtensions.GetRichAttachments(IObject?)` — reads every `attachment` entry (not just `Image`),
  returning its type (most-specific AS2.0 type name, skipping the base `"Object"`), name (first
  `Name` entry), media URL (from `id`, `url`, or `href`), and optional preview URL (from the
  `preview` property — a `Link`/`Image` with `href`/`id`, or a bare-string `url`).
- `ResolveAttachmentUrlIri(IObject)` — private helper that resolves the `url` property of a
  non-Image attachment (Document/Audio/Video): reads the first `url` entry's `href` via the
  typed `ActivityObject.Url` property, falling back to a bare-string or array `url` in
  `ExtensionData`.
- `ResolvePreviewIri(JsonElement)` — private helper that resolves a `preview` value from
  `ExtensionData` (string, or object with `href`/`url`).

### `ObjectView` (Web Client)

- `ObjectView.razor.cs`: added `RichAttachments` / `ActivityRichAttachments` properties (backed by
  `GetRichAttachments()`), plus four helper methods: `RichAttachmentUrl()`,
  `RichAttachmentPreviewUrl()`, `RichAttachmentIcon()`, `IsPlainImage()`.
- `ObjectView.razor`: replaced the three `@foreach (var media in …MediaAttachments)` loops with
  rich-attachment loops. Each iteration checks `IsPlainImage(att)`:
  - **Plain image** → `<div class="object-media"><img …/></div>` (same as before).
  - **Rich attachment** → `<div class="object-attachment">` card with icon, optional preview
    thumbnail, name link, and type label.

### CSS

- `.object-attachment` — flex row card with border, radius, and surface background.
- `.object-attachment-icon` — large emoji icon, fixed size.
- `.object-attachment-preview` — 3rem × 3rem thumbnail, cover-fit, rounded.
- `.object-attachment-info` — flex column for name + type label.
- `.object-attachment-link` — accent-colored link, truncated with ellipsis.
- `.object-attachment-type` — small uppercase muted type label.

## Tests

8 new unit tests in `IriExtensionsTests` (`GetRichAttachments_*`):

| Test | Covers |
|---|---|
| `FromImage_ReturnsImageType` | `Image` attachment with `Id` + `Name` → type "Image", name, URL |
| `FromDocument_ReturnsDocumentType` | JSON-deserialized `Document` with `name` + `url` → type "Document", name, URL |
| `FromAudioWithPreview_ReturnsPreview` | JSON-deserialized `Audio` with `preview` (object with `url`) → preview IRI resolved |
| `FromVideo_ReturnsVideoType` | JSON-deserialized `Video` with bare-string `preview` → type "Video", preview resolved |
| `FromLink_ReturnsNullType` | Plain `Link` attachment → type null, URL from `href` |
| `MultipleMixedTypes_ReturnsAll` | Image + Document + Audio in one attachment array → 3 entries, correct types |
| `NoAttachments_ReturnsEmpty` | Note with no `attachment` → empty list |
| `Null_ReturnsEmpty` | `null` object → empty list |

## Scope notes

- `Article`-specific fields (`publishedTime`, `duration`, `inLanguage`) are **not** surfaced in
  this slice — they are a separate concern (long-form article rendering) and are tracked under the
  same F-11 feature but are a larger UI effort.
- Outbound attachment creation (uploading documents/audio/video and embedding them in a post) is
  out of scope; this slice is purely the inbound read + render path.
