## The key-preservation fix

The critical insight from the first attempt (partial 3, where `BlocksCollection` was attempted and
reverted): `TestSeeder.SeedPersonWithKey` calls `KeyPairGenerator.GenerateRsa(keyId)` — it generates
a **new** key every call. On reseed after `Reset()`, the key *value* changes (though the keyId stays
deterministic as `{actorIri}#key-1`). For classes that **sign** requests and rely on a self-fetcher
holding a copy of the initial key, reseeding via `SeedPersonWithKey` causes a signature mismatch (401).

The fix: the **key store is preserved** across `Reset()` (it's a separate store not cleared by
`InMemoryPersistenceProvider.Reset()`). So the actors/communities can be re-seeded with the *same*
key instance the self-fetcher already holds:

- `TestSeeder.SeedPersonWithExistingKey(persistence, host, handle, keyId)` — looks up the existing
  key in the key store, seeds the `Person` + its `publicKey` extension, no new key generated.
- `TestSeeder.SeedCommunityWithExistingKey(persistence, host, name, keyId)` — same for `Group`.

## What changed

### `TestSeeder.SeedCommunityWithExistingKey` (new)

Mirrors `SeedPersonWithExistingKey` for communities: looks up the existing key by `keyId`, builds a
`Group` with the `publicKey` extension populated from the existing key's public PEM, and puts it in
the community store. Throws if the key is not present in the key store.

### Conversion pattern (all four classes)

1. The **fixture** (`*SharedHost : SharedHostFixture`) builds the host once with the initial seed's
   keys (generated by `SeedPersonWithKey` / `SeedCommunityWithKey`), wires the self-fetcher via
   `SharedHostFixture.ServerRefFor(persistence)`, and registers the server in the static registry.
2. The **test class** takes the fixture, creates an `HttpClient`, and sets key fields to `null!`.
3. `InitializeAsync` calls `_fixture.Reset()` + `SeedForFixture(_persistence)` (which uses
   `SeedPersonWithExistingKey` / `SeedCommunityWithExistingKey`), then re-fetches the key objects
   from the key store (they're the same instances the self-fetcher holds).
4. Test methods that build signed clients use `_fixture.Server.CreateHandler()` (not a `_server`
   field).
5. `BuildSelfFetcher` is made `internal static` (called from the fixture's static `BuildOptions`).

### Per-class details

- **BlocksCollection** (8): bob + carol (extra local actor). Fixture seeds both with keys; test
  re-seeds with `SeedPersonWithExistingKey`. Delivery client uses bob's key.
- **FlagsCollection** (7): identical topology to Blocks (bob flagger, carol flagged). Same pattern.
- **Reply** (7): single actor alice. Fixture seeds alice + objects + reply edges; test re-seeds with
  `SeedPersonWithExistingKey` + object/edge re-seed. `CreateClient` uses `_fixture.Server`.
- **CommunityJoinRequest** (10): alice + bob (with keys) + two communities (iris gated, open).
  Fixture seeds all four with keys; test re-seeds with `SeedPersonWithExistingKey` (×2) +
  `SeedCommunityWithExistingKey` (×2) + `SetManuallyApprovesMembers`. `BuildSelfFetcher` now takes
  `(Iri aliceIri, Func<TestServer> serverRef)` (was an instance method using `_server`).
