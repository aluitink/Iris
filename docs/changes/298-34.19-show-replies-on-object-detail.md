# 34.19 — Show replies on object detail

**Phase 34 — UI polish & engagement.**

## What was built

The object detail page (`/object?iri=…`) now shows the replies to a content object under the note itself. Previously the page rendered the object + a "Reply" button but nothing else — a user reading a note had no way to see its replies without navigating elsewhere.

## How it works

After `OnParametersSetAsync` loads the object document, a new `LoadRepliesAsync` method:

1. Fetches the replies collection via `IActivityPubClient.GetRepliesAsync(iri, new CollectionQuery { Limit = 20 })` — the server's `GET {object}/replies` endpoint (F-12), which returns a paged `OrderedCollection` of reply IRIs as `Link` objects.
2. Resolves each `Link` to a full object via `IActivityPubClient.GetObjectAsync` (the replies collection carries IRIs, not embedded objects).
3. Collects the resolved objects into a `List<IObject?>` and re-renders.

The replies render in a dedicated "Replies" card below the note, each using the shared `ObjectView` component for consistent rendering (author handle, timestamp, content, "in reply to" link).

**Actor objects** skip the replies section entirely (an actor has no meaningful replies collection).

**Unresolvable replies** (404, network error, malformed IRI) are silently skipped — the object still renders; replies simply won't show for those items.

**Replies loading failure** is non-fatal: the object renders regardless; the replies section shows "No replies yet."

## Key types

- `ObjectDetail.razor` — the page component. New state: `RepliesLoading` (bool), `Replies` (`List<IObject?>`). New method: `LoadRepliesAsync`. New property: `ShowRepliesSection`.
- `app.css` — new `.replies-section` styles (heading, list, item cards with subtle background + border).

## Verification

Verified live via MCP Playwright against the Docker stack (`iris.luit.ink:8088`):

1. Logged in as `alice`.
2. Navigated to `/profile` → clicked the first post ("Hi alice! Great to see you here.") → object detail showed the note + "Replies" section with "No replies yet." (this note is itself a reply; it has no replies to it).
3. Clicked the "in reply to" link to navigate to the parent note ("Hello from alice!") → object detail showed the note + "Replies" section with the reply "Hi alice! Great to see you here." rendered via `ObjectView` (author handle, content, "in reply to" link).

## Decision

The replies section fetches up to 20 replies (a reasonable default for a social platform; the server's replies collection is paged, so a "Load more" button could be added later if needed). Each reply IRI is resolved to a full object via a separate `GetObjectAsync` call — this is the same pattern the `PagedCollection` component uses for feeds (the server's replies endpoint returns IRIs, not embedded objects, so resolution is required for `ObjectView` to render author + content + timestamp). The resolution is sequential (not parallel) to avoid hammering the server with concurrent requests; for the typical reply count (0–20) this is imperceptible.
