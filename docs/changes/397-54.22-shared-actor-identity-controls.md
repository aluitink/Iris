# 54.22 — Shared Actor Identity Controls (ActorBar / ActorCard / ActorAvatar)

## Problem

Timeline note cards (`ObjectView`) rendered an actor's initial-letter avatar even when the actor
had a real icon set, because `ObjectView` only had the actor IRI (from the activity's `actor`
field) and did not fetch the actor document to resolve the icon. The icon-resolution logic was
copy-pasted in four places (`ActorProfile`, `DirectoryCard`, `NotificationRow`, and `Profile`'s
`GetIconIri`), and the same-origin media rewrite logic was duplicated in three.

## Solution

Created three shared components and one helper class:

### `ActorIdentityHelper.cs` (new)

Static helper class consolidating the duplicated logic:

- `IconIri(IObject?)` — resolves the actor's first `icon` IRI (an `IObject` icon by its `id`,
  an `ILink` icon by its `href`), or null.
- `RewriteMediaToSameOrigin(string)` — rewrites an absolute HTTPS media URL to a same-origin
  path (so the browser's cookie auth applies).
- `AvatarInitial(string?, string?)` — a short display initial for the avatar fallback.
- `HandleOf(Iri)` — derives a short handle from an actor IRI (last path segment).
- `ActorHref(Iri)` — the actor detail page URL.
- `NameIsRedundant(string?, string?)` — whether `name` duplicates `preferredUsername`.

### `ActorAvatar.razor` (new)

Self-fetching avatar component. Takes an `ActorIri` and fetches the actor document via
`UiContext.GetActorAsync` (per-circuit cache, 5-minute TTL) to resolve the icon IRI. Accepts
optional `DisplayName` and `IconIriOverride` parameters to skip the fetch when the caller
already has the data. Renders an `<img>` when an icon is available, otherwise a fallback initial.

### `ActorBar.razor` (new)

Compact identity for inline/list contexts (note headers, notification rows). Renders an
`ActorAvatar` + a handle link. Accepts `ActorIri`, optional `DisplayName`, and optional
`IconIriOverride`.

### `ActorCard.razor` (new)

Full identity for directory/profile-preview contexts. Takes an actor document (`IObject?`) and
renders `ActorAvatar` + handle + name (omitted when redundant) + bio + optional `ChildContent`
(e.g. a follow button). Accepts `Actor` and `ActorId` parameters.

### Migrations

| Component | Before | After |
|---|---|---|
| `ObjectView.razor` | Static fallback-only avatar + handle (3 call sites) | `<ActorBar ActorIri="..."/>` (3 call sites) — **fixes the icon bug** |
| `NotificationRow.razor` | Inline avatar + icon resolution + same-origin rewrite | `<ActorAvatar ActorIri="..." DisplayName="..." IconIriOverride="..."/>` |
| `DirectoryCard.razor` | Inline avatar + icon resolution + same-origin rewrite + handle | `<ActorCard Actor="..." ActorId="...">` with `ChildContent` for expand/follow |
| `ActorProfile.razor` | Inline avatar + icon resolution + same-origin rewrite | `<ActorAvatar ... CssClass="actor-profile-avatar"/>` + shared helper methods |

### CSS

Added `.actor-avatar`, `.actor-avatar-fallback`, `.actor-bar`, `.actor-bar-handle`, `.actor-card`,
`.actor-card-avatar`, `.actor-card-avatar-fallback`, `.actor-card-body`, `.actor-card-handle`,
`.actor-card-name`, `.actor-card-summary` classes. Existing `.actor-profile-*` classes retained
for `ActorProfile`'s panel styling.

  - **Directory**: `ActorCard` renders avatar + name + handle + follow button. No console errors.

## Design decisions

- **`ActorAvatar` self-fetches** (via `UiContext`) rather than requiring the caller to pass the
  actor document. This lets `ObjectView` (which only has an IRI, not a document) render a real
  avatar. The `UiContext` per-circuit cache (5-min TTL) prevents repeated fetches for the same
  actor. Optional `DisplayName`/`IconIriOverride` parameters allow callers that already have the
  data to skip the fetch.
- **`ActorBar` uses `ActorAvatar`** internally, so the avatar fetching is centralized.
- **`ActorCard` takes the actor document directly** (it's used in contexts where the document is
  already loaded — directory listing, profile header) and passes the icon IRI as an override to
  `ActorAvatar` (no re-fetch needed).
- **`ActorProfile` kept as a wrapper** around `ActorCard`'s styling (`.actor-profile-*` CSS
  classes) but now uses `ActorAvatar` + shared helpers internally. This preserves the existing
  panel/border/padding look while eliminating the duplicated icon-resolution code.
