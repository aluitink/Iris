# 48.1 — Nginx reverse proxy configuration

## Summary

Created production reverse-proxy configuration files for Iris.Web deployment behind TLS:

- `apps/Iris.Web/deploy/nginx.conf` — full nginx server block: TLS termination (HTTP→HTTPS redirect,
  Let's Encrypt certs), WebSocket upgrade for the Blazor SignalR circuit, security headers (HSTS, CSP,
  X-Frame-Options, etc.), gzip compression, rate limiting (10 r/s per IP, burst 20), health check
  endpoint exemption, 1h proxy read timeout for long-lived WebSocket connections.
- `apps/Iris.Web/deploy/nginx-ratelimit.conf` — `limit_req_zone` directive for the http{} block.
- `apps/Iris.Web/deploy/Caddyfile` — equivalent Caddy config (simpler; Caddy handles TLS + WebSocket
  automatically). Includes security headers, rate limiting, gzip, body size cap.
- `apps/Iris.Web/deploy/README.md` — deployment instructions for both nginx and Caddy, verification
  steps (WebSocket 101 check, health check), security headers table, rate-limit tuning notes.

## Design decisions

- **Two proxy options** (nginx + Caddy): the deployment doc recommended Caddy (simpler, automatic
  TLS + WebSocket), but nginx is the more common choice in production. Providing both lets operators
  pick based on their infrastructure.
- **CSP uses `unsafe-inline` for scripts**: the Blazor .NET runtime bootstraps via inline `<script>`
  blocks in the prerendered HTML. Removing `unsafe-inline` would require a nonce-based approach
  (generate a random nonce per page render, inject into both the CSP header and the script tags) —
  deferred to a future slice if CSP hardening becomes a priority.
- **`X-Frame-Options: DENY`**: the app is never embedded in an iframe; DENY is stricter than SAMEORIGIN.
- **Rate limiting exempts `/ap/v1/health`**: monitoring/uptime checks should not be throttled.
- **`client_max_body_size 10m`**: the app's federation body cap is 1 MiB, but media uploads (images
  via the compose form) can be larger. 10 MiB is a safe upper bound.
- **No static file offloading in nginx** (commented out): the app's own `UseStaticFiles` with
  Cache-Control headers (added in 47.4) is sufficient for the current scale. Uncommenting the
  nginx static blocks would require mounting wwwroot into the nginx container and is an optimization
  for high-traffic deployments.
