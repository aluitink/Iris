# 218 — 19.5.1 Community creation discovery: WebFinger + capabilities

> 2026-09-03 · Slice 19.5.1 (community-creation discovery) · Phase 19.5 (community creation & management)

## Summary

The WebFinger handler now resolves **community** handles (not just actor handles), and the created
community document advertises its `iris:capabilities` extension. Two new integration tests pin the
discovery behavior:

1. **`CreateCommunityAsync_ThenWebFinger_ResolvesCommunityHandle`** — creates a community via
   `CreateCommunityAsync`, then issues a WebFinger query for `@devs@host`. The response must contain
   a `self` link whose `href` is the community IRI (`{base}/ap/v1/c/devs`).

2. **`CreateCommunityAsync_ThenDocument_AdvertisesCapabilities`** — creates a community, fetches the
   community document by IRI, and asserts the `iris:capabilities` extension is present (the
   capability set that tells a remote client which community features are supported).

## Changes

### Server — `ActivityPubServerExtensions.cs`

- **WebFingerHandler** (`WebFingerHandler` lambda, ~line 3644): after the actor-store lookup fails,
  the handler now falls back to the **community store**. It builds a community IRI via
  `BuildCommunityIri(baseUrl, handle)` and calls
  `persistence.Communities.TryGetCommunityAsync(communityIri, …)`. When found, the community IRI is
  used as the resolved IRI in the WebFinger response.

- **Iri serialization fix**: the `href` field in the WebFinger response is now explicitly converted
  to a `string` via `resolvedIri.ToString()` before being placed in the anonymous object. Without
  this, `System.Text.Json` serializes the `Iri` readonly record struct as a JSON **object**
  (`{"Uri":…,"Value":…,"IsAbsolute":…,"IsPublic":…}`) instead of a plain string, which violates
  RFC 8615 (JRD) and breaks any consumer expecting a string `href`.

### Tests — `CommunityCreationIntegrationTests.cs`

- **`CreateCommunityAsync_ThenWebFinger_ResolvesCommunityHandle`**:
  - Creates a community with handle `devs` via `CreateCommunityAsync`.
  - Issues `GET /.well-known/webfinger?resource=acct:devs@{host}`.
  - Asserts HTTP 200.
  - Parses the JRD document, finds the `rel == "self"` link, and asserts its `href` equals the
    community IRI.

- **`CreateCommunityAsync_ThenDocument_AdvertisesCapabilities`**:
  - Creates a community with handle `devs` via `CreateCommunityAsync`.
  - Fetches the community document at `{base}/ap/v1/c/devs`.
  - Asserts HTTP 200.
  - Asserts the `iris:capabilities` extension is present in the document's `ExtensionData`.

## What this closes

- **19.5.1 WebFinger discovery**: a remote client can now discover a community by handle via
  WebFinger, the same way it discovers an actor.
- **19.5.1 capabilities advertisement**: the created community document carries the
  `iris:capabilities` extension so remote clients know which community features are available.
