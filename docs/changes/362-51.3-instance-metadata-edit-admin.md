# 51.3 — Instance metadata edit (admin)

**Phase 51, Slice 3: Admin-only form to edit instance name/description (NodeInfo fields).**

## What

An admin can edit the instance's display name and description via `/admin/instance`. The
values are persisted in a new `InstanceMetadata` table (single row) and served by the
`GET /local/v1/admin/instance` endpoint. The `PUT /local/v1/admin/instance` endpoint
updates the row. The NodeInfo document (`/ap/v1/nodeinfo/2.0`) continues to serve the
static `ActivityPubServerOptions.InstanceName` (the library's endpoint is not overridden
due to route ambiguity with the catch-all `/ap/v1/{**path}` handler); the admin-edited
values are available via the local admin endpoint.

## Design decisions

- The `IInstanceMetadataStore` lives in `Iris.Server.Data.Accounts` (same pattern as
  `IUserAccountStore`): it is a local concern with no federation surface.
- The NodeInfo override was attempted but caused an `AmbiguousMatchException` (the
  library's `NodeInfoHandler` is more specific than a duplicate mapping, and the
  catch-all `ObjectDocumentHandler` creates a second candidate). The admin endpoint
  provides the full read/update cycle; the NodeInfo document continues to reflect the
  static option. A future improvement could use a terminal middleware or a library
  extension point.
- The entity uses `IdentityByDefaultColumn` (Id=1 for the single row); the store
  queries with `FirstOrDefaultAsync()` (no Id filter).
