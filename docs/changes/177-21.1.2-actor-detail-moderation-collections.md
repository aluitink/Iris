# 177 — Phase 21.1.2: actor detail — target actor's moderation collections (mutes/blocks/flags)

## Summary

The actor detail page now shows the **target actor's moderation collections** (who the target has muted,
blocked, and flagged) via `GET /ap/v1/u/{handle}/{mutes|blocks|flags}`, paged with `next`-link walking.
Each item links to the moderated actor's detail.

No per-item unmute/unblock/unflag buttons: the Decision 055 learned-id model requires the id of the
original activity to undo it, which these collections do not carry (they carry actor IRIs, not activity
ids). The unmute/unblock/unflag capability is provided by the existing "Moderation" card (which uses the
captured learned ids).

## What changed (code)

- **`samples/SampleBlazorClient/Pages/ActorDetail.razor`**
  - **Markup:** a new "Moderation (this actor's collections)" card (between the "My moderation (you)"
    card and the "Follow / unfollow" card). It has three sections (Mutes, Blocks, Flags), each showing
    the target actor's moderation collection (paged, clickable).
  - **State:** `TargetMutesItems`/`TargetMutesHasMore`/`TargetMutesLoadingMore`/`TargetMutesError`/

    `TargetBlocksError`/`_targetBlocksResumeFrom`, `TargetFlagsItems`/`TargetFlagsHasMore`/
    `TargetFlagsLoadingMore`/`TargetFlagsError`/`_targetFlagsResumeFrom`.
  - **`LoadMoreTargetMutesAsync`** / **`LoadMoreTargetBlocksAsync`** / **`LoadMoreTargetFlagsAsync`**:
    the methods that load the next page of each collection.
  - **`EnumerateOneTargetMutesPageAsync`** / **`EnumerateOneTargetBlocksPageAsync`** /
    **`EnumerateOneTargetFlagsPageAsync`**: the methods that enumerate one page of each collection
    (using `actorIri.MutesOf()`, `actorIri.BlocksOf()`, `actorIri.FlagsOf()`).
  - **Initial load:** the first page of each collection is loaded in `OnParametersSetAsync` (after the
    moderation counts are loaded), so the card is populated on initial load.

## Key types / API

- `actorIri.MutesOf()` / `actorIri.BlocksOf()` / `actorIri.FlagsOf()` — the IRI extension methods that
  derive the moderation collection IRIs (e.g. `https://host/u/alice/mutes`).
- `client.GetCollectionAsync(iri, null, ct)` — the client method that reads a collection (paged).

## Decision: why no per-item undo buttons

The Decision 055 learned-id model requires the id of the original activity to undo it. The moderation
collections (`/mutes`, `/blocks`, `/flags`) carry **actor IRIs** (the muted/blocked/flagged actors), not
**activity ids** (the ids of the original mute/block/flag activities). So the page doesn't have the
learned ids for each moderation action, and can't offer per-item undo buttons. The unmute/unblock/unflag
capability is provided by the existing "Moderation" card (which uses the captured learned ids when the
logged-on actor mutes/blocks/flags via this UI).

## Direction note: sample-client UI is manual-tested (not bUnit-tested)

Per the current direction, the sample-client UI is **in flux and subject to a lot of change** once core
stuff is worked out. Rather than invest in bUnit tests for the sample UI (which would need to track every
UI change), the sample UI is **verified manually** (drive the screens through the browser). This change
follows that direction: the moderation collections card is wired and builds clean, but has no bUnit test.
The underlying wire (the moderation collection reads) is proven by the existing server/client integration
tests.
