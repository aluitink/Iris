# 181 — Phase 22.1: identity bar (US-3) + back links (US-22)

## Summary

Closes the two cross-cutting "make the tool work" stories that live in the app shell rather than a
single page:

- **US-3 — always-visible identity bar.** The `MainLayout` header now shows, while logged on, the
  active actor IRI (the WebFinger-resolved advertised IRI when available, else the direct IRI) **and**
  a `Dialing {dial base}` line — so the "who am I" and "which server a read/write hits" are visible on
  every screen, not just Home. The dial base (a host-published port for a local instance) is distinct
  from the advertised IRI host, so both are shown. Logged out, it keeps the single "not logged on"
  line.
- **US-22 — consistent back links.** A new shared `BackLink` component renders one link at the top of
  a detail page: `← Back to object` (the last-viewed object), else `← Back to actor` (the
  last-viewed actor), else `← Home`. Wired onto `ObjectPage`, `ActorDetail`, and `Community` — the
  pages a user deep-links *into*.

The key enabler is that `ExplorerSession` now raises a **refresh signal** (an
`INotifyPropertyChanged` event with a null property name) on every identity change — logon, OAuth2
logon, instance switch, logout, and navigable-state change. `MainLayout` and `BackLink` subscribe, so
the header and back links re-render **without a full page navigation** (previously the header only
updated on a hard reload, because the session was a plain singleton the layout never re-read).

This is the 22.1 "shared components first" working order, following the `PagedCollection` +
`RawInspector` sub-slice (change 180). Deep-dive:
[plans/22-3-identity-bar-and-back-links.md](../plans/22-3-identity-bar-and-back-links.md).

## What changed (code)

- **`samples/SampleBlazorClient/Explorer/ExplorerSession.cs`**
  - Implements `INotifyPropertyChanged`. A `PropertyChanged` event is raised (via a private
    `NotifyIdentityChanged()` helper, a null property name — a "refresh" signal, not a per-property
    change) from: the success path of `LogOnAsync`, the success path of `LogOnWithOAuth2Async`,
    `LogOut()`, `SetNavigableObjectIri`, `SetNavigableActorIri`, and `ClearNavigableState`.
  - Subscribers re-read the public identity properties (`IsLoggedIn`, `ResolvedActorIri`,
    `ActorIri`, `DialBaseUri`, the navigable IRIs) rather than keying off a specific property.

- **`samples/SampleBlazorClient/Layouts/MainLayout.razor`**
  - The single `.instance` span is replaced by a `.identity` block (two lines: the `IdentityIri`
    span, and the `Dialing <code>` line). `IdentityIri` is a computed property
    (`Session.ResolvedActorIri ?? Session.ActorIri`).
  - Implements `IDisposable`; `OnInitialized` subscribes and `Dispose` unsubscribes the session's
    `PropertyChanged`, calling `StateHasChanged()` on each signal.

- **`samples/SampleBlazorClient/Components/BackLink.razor`** (new)
  - Injects `ExplorerSession`. Renders, when logged in: `← Back to object` → `/object?iri={escaped}`
    if `NavigableObjectIri` is set; else `← Back to actor` → `/actor?iri={escaped}` if
    `NavigableActorIri` is set; else `← Home` → `/`. No render when logged out. The deep-link targets
    mirror the exact patterns `Home`'s "Continue where you left off" card already uses.
  - Implements `IDisposable` + subscribes/unsubscribes to the session's `PropertyChanged` so the
    target updates when the user views a new item or logs out.

- **`samples/SampleBlazorClient/Pages/{ObjectPage,ActorDetail,Community}.razor`**
  - `<BackLink />` placed immediately under the page `<h2>` (above the load card).

- **`samples/SampleBlazorClient/_Imports.razor`**
  - Adds `@using System.ComponentModel` (for `PropertyChangedEventArgs` in the `.razor` code blocks).

- **`samples/SampleBlazorClient/wwwroot/css/app.css`**
  - `.identity` / `.identity-actor` / `.identity-dial` (the two-line header identity block) and
    `.back-link` (+ `:hover`) (the muted, underlined-on-hover sub-heading link).

## Key types / API

- `ExplorerSession : INotifyPropertyChanged` — the new refresh contract. `PropertyChanged` is a
  "the logged-on identity / navigable state may have changed" signal (null property name); the
  subscriber re-reads the public identity properties. Raised on logon / OAuth2 logon / switch /
  logout / navigable-state change.
- `ExplorerSession.IdentityIri` is **not** a session property — it is a computed property on
  `MainLayout` (`ResolvedActorIri ?? ActorIri`), keeping the "authoritative advertised IRI" decision
  at the rendering edge. The session already exposes `ResolvedActorIri` and `ActorIri` separately.
- `ExplorerSession.NavigableObjectIri` / `NavigableActorIri` (19.8.5 "last-viewed item" state) — the
  back-link target, set by `ObjectPage` / `ActorDetail` on load and preserved across instance
  switching.
- Blazor note: in this WASM target `ComponentBase` implements neither `IDisposable` nor a virtual
  `Dispose`, so the shell components opt in with `@implements IDisposable` + a public `Dispose()`.

## Scope / limits

- The back link is wired onto the three **detail** pages a user deep-links into
  (`ObjectPage`, `ActorDetail`, `Community`). List/search/authoring pages (`Actors`, `Feed`,
  `Compose`, `Deliver`, `Instance`) don't need one — they are top-level entry points reached from the
  nav row.
- The session refresh is a **null-property-name signal**, not per-property change tracking; subscribers
  re-read the relevant public properties. This keeps the session's public surface unchanged (no new
  identity properties were added — `ResolvedActorIri`, `DialBaseUri`, and the navigable IRIs already
  existed).
- The 22.1 item remains open: the `ObjectView` deep-dive (US-19) and the card
  loading/empty/error pattern (US-23) are the remaining 22.1 sub-slices.
