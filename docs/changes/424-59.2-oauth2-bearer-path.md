# 59.2 — OAuth2 Bearer path for inbox + endpoints on actor doc (F-20)

## Summary

Completes F-20 (OAuth2 Bearer authentication for the inbox). Two gaps were closed:

1. **Actor document endpoints**: the `endpoints` object on every local actor document now advertises
   `oauthAuthorizationEndpoint` and `oauthTokenEndpoint`, so a real client (Mastodon, Pleroma, a
   third-party app) can discover the OAuth2 flow's endpoints from the actor document alone — no
   hard-coded paths.

2. **Bearer fallback in the inbox handler**: when an inbound inbox POST carries no valid HTTP
   signature (unsigned, or the signature failed), the handler now checks for an
   `Authorization: Bearer <token>` header. If the token resolves to an actor IRI via the
   `IOAuthTokenStore`, the request is treated as authenticated and processed normally. If the token
   is unknown or revoked (or there is no Bearer header), the request is rejected with 401 — the same
   outcome as an invalid signature.

A third fix was required for the Bearer path to work: the inbox handler's body-reading code assumed
the request body had already been buffered by the signature middleware (which only buffers when a
`Signature` header is present). For an unsigned Bearer request the body was never buffered, so
`Position = 0` threw. The handler now calls `EnableBuffering()` unconditionally and reads through the
safe `ReadAsBufferedStringAsync` helper (handles both seekable and non-seekable streams).

## Changes

### Actor document endpoints (`BuildActorDocument` in `ActivityPubServerExtensions`)

When building the public actor document, the `endpoints` object now always includes:

- `oauthAuthorizationEndpoint`: `{base}/ap/v1/oauth2/authorize`
- `oauthTokenEndpoint`: `{base}/ap/v1/oauth2/token`

The base URI is derived from `ActivityPubServerOptions.BaseUri` (when set) or the actor IRI's host
(fallback: the actor IRI up to the route prefix). These are written with `??=` so a host that
explicitly pre-populated the endpoints (e.g. a custom token endpoint on a different path) is not
overwritten.

### Bearer fallback (`HandleInboxPostAsync` in `ActivityPubServerExtensions`)

The shared inbox POST core now accepts an optional `IOAuthTokenStore?` parameter. When the
signature-validation outcome is not valid (unsigned request, or invalid signature), the handler calls
the new `TryResolveBearerActorAsync` helper, which:

1. Reads the `Authorization` header.
2. Checks for the `Bearer ` scheme prefix.
3. Extracts the token string.
4. Resolves it via `tokenStore.ResolveTokenAsync(token, ct)`.

If the token resolves to an actor IRI, the outcome is replaced with
`new SignatureValidationResult(IsValid: true, KeyId: bearerActorIri, ActorIri: bearerActorIri)` and
processing continues (the Bearer actor IRI stands in for the signature's keyId — used for the
per-peer rate-limit key and logging). If the token is unknown/revoked or there is no Bearer header,
the request is rejected with 401.

### `TryResolveBearerActorAsync` (new private helper)

Extracts the Bearer token from the `Authorization` header and resolves it via the
`IOAuthTokenStore`. Returns `null` when: no token store is configured, no `Authorization` header,
non-Bearer scheme, empty token, or the token is unknown/revoked.

### Body-reading fix (`HandleInboxPostAsync`)

The body is now read via `context.Request.EnableBuffering()` + `ReadAsBufferedStringAsync(...)`
instead of a direct `context.Request.Body.Position = 0` + `StreamReader`. This is correct for both
the signed path (body already buffered by `HttpSignatureValidator`) and the Bearer path (body not yet
buffered). `EnableBuffering` is idempotent on an already-buffered stream.

### Call-site updates

- `InboxHandler` (actor inbox): injects `IOAuthTokenStore` and passes it to `HandleInboxPostAsync`.
- `CommunityInboxHandler` (community inbox): injects `IOAuthTokenStore` and passes it to
  `HandleInboxPostAsync`.
