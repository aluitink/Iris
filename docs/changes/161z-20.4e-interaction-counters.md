# 161z — 20.4(e): per-object interaction counters (like / boost counts)

> 2026-09-02 · Slice 161z · Phase 20.4 (e) · Decision 056 (d)

## What was built

A content object's per-object **like** and **boost** counters — deferred from Decision 056 §d (the
`likedBy`/`announcedBy` object-side collections). The **source of truth is the reverse indexes** (object →
set of actor IRIs), **not a wire rewrite**: the object document itself stays verbatim (Decision 055 + 056 (c)
unchanged), and the count is **derived from the reverse index at read time**.

The wire exposes the counts as **extension collections under the bare, non-namespaced terms the ActivityPub
ecosystem uses** for object-side interaction collections (Mastodon/Pleroma/Misskey all use bare `likes` /
`shares`, never namespaced):

- `GET {object-iri}/likes` — the likers, as a **full, non-paged `OrderedCollection`** of actor `Link`s,
  `totalItems` = the like count.
- `GET {object-iri}/shares` — the announcers (boosters), same shape, `totalItems` = the boost count.

These are **extension collections, not core ActivityStreams `Object` properties** — the only core object
collection is `replies`; likes/shares exist only as `Like`/`Announce` activities. Per the ActivityStreams
extensibility rule a strict consumer that does not know the term **MUST ignore it** (not error), so the bare
terms are safe to expose. A like/boost set is small and bounded (unlike an outbox), so the whole set is
served at once — no paging, and a client reads the exact count off `totalItems`. An object this instance does
not store 404s (mirroring the object document). Discoverability is via the `iris:capabilities` extension
(`CapabilityLikes` / `CapabilityShares`). No new NuGet.

## Key types & files

**New (server):**
- `src/Iris.Server/Stores/IAnnounceStore.cs` — the announce (boost) store: `RecordAnnounceAsync` /
  `RemoveAnnounceAsync` / `GetAnnouncedAsync` / `HasAnnouncedAsync` / `GetAnnouncersAsync` (the reverse
  index backs the object's `shares` collection).
- `src/Iris.Server.InMemory/Stores/InMemoryAnnounceStore.cs` — in-memory (two concurrent dictionaries:
  `announcer → [announced]` + `announced → [announcers]`; both directions maintained on record/remove).
- `src/Iris.Server/Persistance/Stores/FileBackedAnnounceStore.cs` — file-backed (`announces.json`,
  `{"edges":[...],"announcedBy":[...]}`; the reverse-index section is an internal storage key, not the wire
  term).

**Changed (server):**
- `src/Iris.Server/Stores/ILikeStore.cs` — `GetLikersAsync` (the object's `likes` reverse index).
- `src/Iris.Server/Stores/IPersistenceProvider.cs` — `IAnnounceStore Announces { get; }`.
- `src/Iris.Server.InMemory/Stores/InMemoryLikeStore.cs` — dual dictionaries (`_liked` + `_likedBy`); both
  directions maintained on record/remove (the remove removes from **both** — a short-circuit `||` would leave
  a stale liker in the reverse index).
- `src/Iris.Server/Persistance/Stores/FileBackedLikeStore.cs` — dual indexes persisted in
  `{"edges","likedBy"}`; **backward-compatible** with the earlier bare-array (liker-direction-only) file — a
  bare array is read as `edges` and the reverse index is rebuilt by reversing those edges.
- `src/Iris.Server.InMemory/InMemoryPersistenceProvider.cs` / `InMemoryPersistenceExtensions.cs` — the
  announce store wired in + DI (`TryAddSingleton<InMemoryAnnounceStore>()`).
- `src/Iris.Server/Persistance/FileBackedPersistenceProvider.cs` — `Announces` (`announces.json`).
- `src/Iris.Server/Inbox/AnnounceActivityHandler.cs` — records the announce edge after the outbox entry.
- `src/Iris.Server/Inbox/UndoActivityHandler.cs` — the previously-missing `Undo(Announce)` branch (an
  un-boost removes the announce edge **and** the boost's outbox entry).
- `src/Iris.Server/ActivityPubServerExtensions.cs` — the `ObjectDocumentHandler` dispatches the `/likes` +
  `/shares` segments to `ObjectLikesAsync`/`ObjectSharesAsync` → `BuildInteractionCollection` (a full,
  non-paged `OrderedCollection`; 404 when the object is not stored).
- `src/Iris.Server/ActivityPubServerConstants.cs` — `CapabilityLikes` / `CapabilityShares` (the
  `iris:capabilities` extension values).

**New / changed (client):**
- `src/Iris.Core/Identity/IriExtensions.cs` — `LikesOf()` / `SharesOf()` (the object's `likes` / `shares`
  collection IRIs).
- `src/Iris.Client/IActivityPubClient.cs` / `ActivityPubClient.cs` — `GetLikesAsync(Iri objectIri, …)` /
  `GetSharesAsync(Iri objectIri, …)`: enumerate the full collection (the count of yielded items is the
  count).
- `samples/SampleBlazorClient/Pages/ObjectPage.razor` — the like / boost counts render next to the Like /
  Boost buttons; `null` for external objects (no count shown, not 0).

## Decisions

- **Decision 056 (d)** — the object-side `likes` / `shares` interaction collections (the per-object like /
  boost counters): the deferral is [docs/decisions/056-c2s-inbox-model.md](../decisions/056-c2s-inbox-model.md)
  §d; this slice implements it as bare-term extension collections over the reverse indexes (wire verbatim,
  count derived at read time).
