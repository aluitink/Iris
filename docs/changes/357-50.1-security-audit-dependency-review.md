# 50.1 — Security audit & dependency review

## Summary

Full security audit of the Iris.Web production app. All NuGet dependencies checked for
known vulnerabilities (none found). Auth/session, CSRF, CORS, Dockerfile, docker-compose,
appsettings, and in-code secrets reviewed. Four issues found and fixed.

## Dependency vulnerability check

`dotnet list package --vulnerable` run on all 7 projects (5 src + 2 test + 1 app):
**0 vulnerable packages** across the entire solution.

## Changes made

### 1. Cookie security flags (WebAppFactory.cs:216-228)

```csharp
options.Cookie.HttpOnly = true;
options.Cookie.SameSite = SameSiteMode.Lax;
options.Cookie.SecurePolicy = CookieSecurePolicy.SameAsRequest;
```

- `HttpOnly=true`: prevents JS access to the auth cookie (XSS defense).
- `SameSite=Lax`: allows top-level navigation from other sites (login redirects) while
  blocking cross-site POST (CSRF defense). `Strict` would break the login redirect flow.
- `SecurePolicy=SameAsRequest`: sets `Secure` only when the request is HTTPS. Behind
  nginx (production) the forwarded-headers middleware makes the app see HTTPS → `Secure`
  is set. Over plain HTTP (local dev / Docker) the cookie is still usable.

### 2. Non-root Docker user (Dockerfile)

- Created `iris` user (uid 1001, gid 1001) in the runtime stage.
- `chown -R iris:iris /app` for the published app files.
- Entrypoint script (`/entrypoint.sh`) runs as root briefly to `chown` the DP keys volume
  (Docker named volumes are created root-owned), then drops to `iris` via `setpriv`.
- DP keys path changed from `/root/.aspnet/DataProtection-Keys` to
  `/home/iris/.aspnet/DataProtection-Keys` (Dockerfile + docker-compose.yml).

Verified: `docker exec irisweb-iris-web-1 ps aux` shows `iris 1 ... dotnet Iris.Web.dll`.
Login + session work (DP keys read/write succeed as `iris`).

### 3. DesignTimeDbContextFactory (src/Iris.Server.Data/DesignTimeDbContextFactory.cs)

```csharp
var conn = Environment.GetEnvironmentVariable("IRIS_DB_CONNECTION")
    ?? "Host=localhost;Database=iris;Username=iris;Password=iris";
```

The literal `Password=iris` is now only a fallback for CI/dev (where `IRIS_DB_CONNECTION`
is unset). Production never uses this factory (it's design-time only for `dotnet ef`).

### 4. docker-compose.yml

- DP keys volume path updated to `/home/iris/.aspnet/DataProtection-Keys`.

## Remaining notes (not fixed this slice)

- **Security headers only at nginx**: all headers (HSTS, CSP, X-Frame-Options, etc.) are
  set in `deploy/nginx.conf`, not in the app. If the app is ever accessed directly
  (bypassing nginx), these headers are absent. Acceptable for the current deployment
  model (nginx is always in front); would be defense-in-depth to also set them in-app.
- **CSP `'unsafe-inline'`**: required for Blazor WASM bootstrap. The `script-src` also
  includes `https://*.blazor.boot.dev` (a dev-only origin) which should be removed from
  the production nginx.conf.
- **No resource limits** in docker-compose.yml: a runaway process is unbounded. Add
  `mem_limit`/`cpus`/`pids_limit` for production hardening.
