# 53.7 — repliedCount on Nested Objects

## Summary

Added `iris:repliedCount` to nested objects in collection-page items (outbox and feed), computed from the `IReplyStore.GetRepliesAsync` reverse-index count. This is a cacheable, per-object interaction counter (like `likedCount`/`sharedCount`) that lets the client render a "N replies" indicator without an extra request to the `/replies` endpoint.

## Design Decision

**`isReplied` skipped**: Unlike likes/boosts (toggleable state), replies are content — a user can have multiple replies to the same object, and there's no clean "I have replied" boolean. The `IReplyStore` tracks `parent → [children]` edges, but "does actor X have any reply to object Y" would require scanning the requester's outbox. This is ambiguous and low-value compared to the count, so `isReplied` is not implemented.

**Reply expansion**: The existing `GET {object}/replies` endpoint already supports thread expansion (the client fetches the replies collection when the user clicks "N replies"). No new endpoint is needed.

## Changes

### `Iris.Core`
- `IrisExtensionTerms`: Added `RepliedCount` constant.

### `Iris.Server`
- `ActivityPubServerExtensions.EnrichCollectionItemsAsync`: Now also computes `repliedCount` from `IReplyStore.GetRepliesAsync` and adds it to the embedded object's extensions.
- `BuildNamespaceDocument`: Declares `repliedCount` as `integer`.
