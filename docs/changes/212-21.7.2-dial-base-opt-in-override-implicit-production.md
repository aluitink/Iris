# Change 212 — 21.7.2 Dial-base / base-URL story: implicit production, explicit opt-in override

## Summary

The log-on flow's dial-base resolution was reworked so the UI **implicitly assumes it is talking to a
real production server** (the IRI host is browser-reachable). The `InstanceBaseUrls` map no longer
silently redirects a FQDN log-on to a localhost port; the dial base is now an **opt-in override** in a
collapsed "Advanced" section, empty by default.

## What changed

### `Home.razor`

- `BaseUrl` default changed from `"https://iris.luit.ink"` to `""` (empty).
- The base URL input is now inside a `<details>` element labelled
  "Advanced: talk to a different endpoint" (collapsed by default).
- `ResolveDialBase` no longer consults `Session.BaseUrls` (the `InstanceBaseUrls` map). The logic is:
  explicit override → used as-is; empty → `https://{host}` (the IRI host, production assumption).
- The "Dialing …" line is removed from the logged-on card.
- The top-of-page description updated to "The explorer dials the actor's home server by default; use
  the advanced section below only if the instance is reachable at a different endpoint."

### `MainLayout.razor`

- The "Dialing `<code>`" span removed from the identity bar (internal detail, not user-facing).

### `Program.cs`

- The `InstanceBaseUrls` seeding (iris.luit.ink, localhost, iris-dev1.luit.ink, iris-dev2.luit.ink →
  localhost ports) is removed. `AddIrisExplorer()` is called with no arguments (empty map).

### `README.md`

- "Logon & the base-URL / IRI-host rule" section rewritten: two fields + optional override; the
  production assumption is the default; the map-based auto-resolution is gone.
- "The external-instance mechanism" section simplified: address + password is all that's needed for a
  production instance; the override is for non-standard deployments.
- Quick-start table updated to show the override values for the local compose stack.

## What did NOT change

- `InstanceBaseUrls` class itself (still part of `ExplorerSession`'s public API; the map is simply
  empty by default).
- `ExplorerSession.LogOnAsync` / `LogOnWithOAuth2Async` (they still take an explicit `dialBaseUri`
  parameter — the resolution happens in the UI layer).
- The server's `Iris:AdvertiseHost` / `Iris:HostName` split (unchanged; the client-side resolution
  simply no longer has a secret map).
- The `RecentInstance` record (still stores the `DialBaseUri` actually used at log-on time for
  one-click switching).

## Design decision

**The `InstanceBaseUrls` map is no longer consulted in the default (empty override) path.**

Previously, `ResolveDialBase` would look up the address's host in the map and, if found, use the
mapped value (e.g. `iris-dev1.luit.ink` → `http://localhost:8081`). This meant a user logging in with
`alice@iris-dev2.luit.ink` (intending to reach the real FQDN) would be **silently redirected** to
`http://localhost:8082` — a "secret" localhost connection that contradicted the production assumption.

The new behavior is: empty override → always `https://{host}`. If the FQDN is not resolvable from the
browser, the log-on fails with a clear error (the user then expands the Advanced section and enters the
correct endpoint). No hidden map lookup.

The `InstanceBaseUrls` class is retained (not deleted) because it is part of the `ExplorerSession`
public constructor surface and could be useful for future explicit opt-in features (e.g. a
"known instances" picker that *offers* the override values, rather than silently applying them).

## Manual verification (Playwright MCP)

| Scenario | Address | Override | Expected | Result |
|---|---|---|---|---|
| Production assumption (FQDN resolvable) | `alice@iris-dev2.luit.ink` | empty | Dials `https://iris-dev2.luit.ink` | **PASS** — actor IRI `https://iris-dev2.luit.ink/ap/v1/u/alice` |
| Compose dev env via override | `alice@iris-dev1.luit.ink` | `http://localhost:8081` | Dials `http://localhost:8081` | **PASS** — actor IRI `https://iris-dev1.luit.ink/ap/v1/u/alice` |
| "Dialing" line removed | — | — | No "Dialing …" in header or Home card | **PASS** |
| Advanced section collapsed by default | — | — | Not visible until expanded | **PASS** |

Note: in this environment the compose FQDNs (`iris-dev1/dev2.luit.ink`) **are** resolvable from the
browser (the Playwright browser runs on the host, not in the container), so the production-assumption
path works end-to-end. The "graceful error on non-resolvable host" case is not testable here but is
the natural fallback (the `HttpRequestException` in `LogOnAsync` → `LoginAsync` returns false →
"Login failed" error message).
