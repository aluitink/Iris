      - **33.4 — inbound request-body size cap (Phase 33 step 4):** the production app set **no** inbound request-body limit (Kestrel's default is unbounded), so an unauthenticated inbound `POST /ap/v1/u/{handle}/inbox` (reachable by any fediverse peer) could stream an arbitrarily large body into the app's memory — a **denial-of-service vector for a public instance**. `WebAppFactory.ConfigureServices` now caps Kestrel's `Limits.MaxRequestBodySize` at **1 MiB** by default (new `WebAppFactory.DefaultMaxRequestBodySize`), overridable via `Iris:MaxRequestBodySize` (new `MaxRequestBodySizeConfigKey`; env `IRIS_MAX_REQUEST_BODY_SIZE` in `docker-compose.yml` + `.env.example`, in bytes); a non-numeric/non-positive value falls back to the default.
