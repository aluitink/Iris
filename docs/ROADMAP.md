- **Phase 136.18 — Privacy and visibility policy alignment (COMPLETE):** four cross-instance integration tests (`CrossInstanceVisibilityIntegrationTests`, two-instance `TestServer` fixture: A `vis-a.domain.local` alice, B `vis-b.domain.local` bob, alice follows bob) verify the current visibility behavior and pin two significant gaps. Key findings: (1) Iris uses pure AS2 `to`/`cc` addressing — no first-class visibility field, no enum, no `iris:`-namespaced term; visibility is derived from audience (`as:Public` in `to`/`cc` = public; `followers` in `cc` = followers-only; actor in `to` only = direct/DM). (2) **Read path gap:** the public feed, follow feed, community feed, outbox GET, and both search implementations do NOT filter by visibility — a DM post is visible in the public timeline, every follower's feed, and search. (3) **Federation gap:** `RewriteOutboundAudienceAsync` appends all followers to `cc` for every `Create`, clobbering the original direct visibility; the receiving `CreateActivityHandler` stores the object unconditionally. (4) AS2 has no "unlisted" term — Iris cannot represent Mastodon-style unlisted. No production source change (test-only slice — pins gaps for future visibility-filtering work). Iris.Server.Tests 1199 passed (+4), 16 skipped, 0 failed. 136.19 is now the top of Up Next. [changes/13618](changes/13618-phase136-privacy-visibility-policy.md).
